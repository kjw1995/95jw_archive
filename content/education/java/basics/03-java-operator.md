연산자 장은 보통 표를 외우는 장으로 기억된다. 우선순위 14단계, 결합 방향, 형변환 규칙. 그런데 이 표들은 대부분 두 가지 원리에서 따라 나온 결과다. 첫째, **연산자는 언제나 값을 돌려준다.** 둘째, [Chapter 02](../02-java-variable)에서 잠깐 본 것처럼 **JVM은 `int`, `long`, `float`, `double` 네 가지 타입으로만 계산한다.** 첫 번째 원리에서 식의 중첩과 대입의 결합 방향이 나오고, 두 번째 원리에서 산술 변환과 `byte b = b + 1`이 안 되는 이유가 나온다. 이 장은 표를 먼저 보여 주되, 각 표가 왜 그렇게 생겼는지를 함께 본다.

---

## 1. 연산자는 값을 돌려준다

| 용어 | 뜻 | 예 |
|:-----|:---|:---|
| 연산자 | 연산을 수행하는 기호 | `+`, `-`, `*`, `/`, `%` |
| 피연산자 | 연산의 대상 | 변수, 상수, 리터럴, 다른 식 |
| 식 | 연산자와 피연산자의 조합 | `x + y * 2` |
| 평가 | 식을 계산해 값 하나를 얻는 과정 | `10 + 20 * 2` → `50` |

```java
int result = x + y * 2;   // x + y * 2 라는 식을 평가한 값을 result에 넣는다
```

연산자는 피연산자를 가지고 연산한 뒤 **반드시 결과값을 내놓는다.** 당연해 보이는 이 성질이 이 장의 절반을 설명한다. 결과가 값이므로 그 값을 다시 다른 연산자의 피연산자로 쓸 수 있다. `x + y * 2`에서 `y * 2`의 결과가 `+`의 피연산자가 되는 것이 그렇다. 대입 `=`도 연산자라서 값을 돌려주며, 그래서 `a = b = c = 100`처럼 이어 쓸 수 있다. 조건 연산자 `? :`가 `if`문과 다른 점도 값을 돌려준다는 것이다.

| 분류 | 피연산자 수 | 예 |
|:-----|:------------|:---|
| 단항 | 1 | `-x`, `++i`, `!flag`, `(int) d` |
| 이항 | 2 | `a + b`, `x > y`, `a && b` |
| 삼항 | 3 | `조건 ? 값1 : 값2` |

| 종류 | 연산자 | 결과 타입 |
|:-----|:-------|:----------|
| 산술 | `+` `-` `*` `/` `%` | 숫자 |
| 비교 | `<` `>` `<=` `>=` `==` `!=` | `boolean` |
| 논리 | `&&` `\|\|` `!` | `boolean` |
| 비트 | `&` `\|` `^` `~` `<<` `>>` `>>>` | 정수 |
| 대입 | `=` `+=` `-=` `*=` `/=` 등 | 대입된 값 |
| 증감 | `++` `--` | 숫자 |
| 조건 | `? :` | 두 값 중 하나 |
| 기타 | `(type)`, `instanceof` | 변환된 값, `boolean` |

## 2. 우선순위와 결합 방향

| 순위 | 연산자 | 결합 방향 |
|:----:|:-------|:---------:|
| 1 | `()` `[]` `.` | → |
| 2 | `++` `--` `+` `-` `~` `!` `(type)` (단항) | ← |
| 3 | `*` `/` `%` | → |
| 4 | `+` `-` | → |
| 5 | `<<` `>>` `>>>` | → |
| 6 | `<` `>` `<=` `>=` `instanceof` | → |
| 7 | `==` `!=` | → |
| 8 | `&` | → |
| 9 | `^` | → |
| 10 | `\|` | → |
| 11 | `&&` | → |
| 12 | `\|\|` | → |
| 13 | `? :` | ← |
| 14 | `=` `+=` `-=` 등 | ← |

### 2.1 왜 이 순서인가

표를 통째로 외울 필요는 없다. 큰 흐름이 **산술 → 비교 → 논리 → 대입**이고, 이 순서는 사람이 식을 읽는 순서와 같다. `result = a + b > c && d`를 읽을 때 우리는 먼저 `a + b`를 계산하고, 그것을 `c`와 비교하고, 그 결과를 `d`와 묶고, 마지막에 저장한다고 이해한다. 우선순위는 그 자연스러운 읽기를 문법으로 옮긴 것이다. 수학의 곱셈이 덧셈보다 먼저인 것도 그대로 가져왔다.

결합 방향은 같은 순위의 연산자가 이어질 때 어느 쪽부터 묶느냐다. 대부분 왼쪽부터다. `10 - 5 - 2`는 `(10 - 5) - 2`이지 `10 - (5 - 2)`가 아니다. 예외가 단항 연산자와 대입이다. 단항 연산자는 자기 오른쪽에 있는 것에 붙으니 오른쪽부터 묶어야 `-(-x)` 같은 식이 성립하고, 대입은 오른쪽 값이 먼저 있어야 왼쪽에 넣을 수 있으니 `a = (b = (c = 100))` 순서가 된다.

### 2.2 우선순위가 만드는 함정

```java
if (x & 1 == 0)        // 컴파일 오류. 1 == 0 이 먼저 계산되어 x & false
if ((x & 1) == 0)      // 의도한 식
```

비트 연산자 `&`가 비교 연산자 `==`보다 순위가 낮다는 사실은 C에서 물려받은 것으로, 직관과 어긋나는 대표적인 자리다. 비트 연산이 섞이면 괄호를 쓰는 것이 규칙이다. 괄호는 우선순위를 바꾸는 수단이기 전에 읽는 사람에게 의도를 알리는 수단이다.

{{< callout type="warning" >}}
`++i + i++ + ++i`처럼 한 식 안에서 같은 변수를 여러 번 증감하지 않는다. 자바는 C와 달리 피연산자를 **왼쪽부터 순서대로** 평가하도록 정해져 있어 결과 자체는 정해져 있지만, 그 결과를 알려면 읽는 사람이 머릿속에서 실행해 봐야 한다. 우선순위는 "무엇을 먼저 묶는가"이고 평가 순서는 "무엇을 먼저 계산하는가"라서 서로 다른 규칙이라는 점도 알아 둘 만하다.
{{< /callout >}}

## 3. 산술 변환: JVM은 네 가지 타입으로만 계산한다

### 3.1 규칙

```java
byte a = 10;
byte b = 20;
byte c = a + b;     // 컴파일 오류. a + b 는 int
int c = a + b;      // 된다

char ch = 'A';
int n = ch + 1;                // 66
char next = (char) (ch + 1);   // 'B'. int를 char로 되돌려야 한다
```

이항 연산자는 두 피연산자의 타입이 같아야 계산할 수 있다. 다르면 컴파일러가 둘을 같은 타입으로 맞추는데, 그 규칙이 **산술 변환**이다.

```
규칙 1: 더 큰 타입으로 맞춘다
   int + long     → long
   long + float   → float
   float + double → double

규칙 2: int보다 작으면 int로 올린다
   byte + short   → int
   char + byte    → int
```

### 3.2 왜 int보다 작으면 int가 되는가

규칙 1은 값이 잘리지 않게 하려는 것이니 자연스럽다. 이상한 것은 규칙 2다. `byte`끼리 더했는데 왜 `byte`가 아니라 `int`인가. 이유는 JVM의 명령어에 있다. JVM에는 `int`를 더하는 `iadd`, `long`을 더하는 `ladd`, `float`와 `double`을 더하는 `fadd`, `dadd`가 있을 뿐, `byte`나 `short`를 더하는 명령이 없다. 작은 정수는 계산 직전에 `int`로 올려서 `iadd`로 더한다. JVM의 피연산자 스택이 32비트 칸으로 되어 있어 `byte` 하나도 어차피 칸 하나를 차지하니, 작은 타입 전용 명령을 두어도 얻는 것이 없다.

그래서 `a + b`의 결과는 `int`이고, 그것을 `byte` 변수에 넣으려면 4바이트를 1바이트로 줄이는 명시적 변환이 필요하다. 2장에서 "정수는 기본적으로 `int`를 쓴다"고 한 이유가 이것이다. `byte`로 선언해 봐야 계산할 때마다 `int`가 됐다가 돌아온다.

### 3.3 승격이 다르게 적용되는 곳

| 경우 | 동작 | 이유 |
|:-----|:-----|:-----|
| 단항 `-b` (`b`는 `byte`) | 결과는 `int` | 단항 연산자도 피연산자를 `int`로 올린다 |
| 시프트 `b << 1` | 왼쪽 피연산자만 승격. 결과는 왼쪽의 타입 | 오른쪽은 "몇 칸"이라는 횟수일 뿐이라 결과 타입과 무관하다 |
| 증감 `b++` | 결과가 다시 `byte` | 원래 변수에 되돌려 넣는 것이 목적이라 변환이 포함되어 있다 |
| 복합 대입 `b += 1` | 결과가 다시 `byte` | `b = (byte)(b + 1)`로 정의되어 있다 (10절) |

## 4. 증감 연산자

```
j = ++i;        j = i++;
┌──────────┐    ┌──────────┐
│ i = i+1  │    │ j = i    │
│ j = i    │    │ i = i+1  │
└──────────┘    └──────────┘
i=6, j=6        i=6, j=5
```

```java
int i = 5;
int j = ++i;   // i를 먼저 6으로 만들고 그 값을 준다. i=6, j=6

i = 5;
int k = i++;   // 5를 준 뒤에 i를 6으로 만든다. i=6, k=5
```

`i++`도 값을 돌려준다는 1절의 원리를 적용하면 전위와 후위의 차이가 정리된다. 둘 다 `i`를 1 늘리는 것은 같고, **돌려주는 값**만 다르다. 전위형은 늘린 뒤의 값을, 후위형은 늘리기 전의 값을 돌려준다. 후위형은 옛 값을 복사해 두었다가 돌려주는 셈이라, 문장 하나로 `i++`만 쓸 때는 어느 쪽이든 결과가 같다.

```java
int i = 5;
i = i++;       // i는 여전히 5
```

이 유명한 함정도 같은 원리로 풀린다. `i++`는 옛 값 5를 돌려주고 `i`를 6으로 만든다. 그다음 대입이 그 5를 `i`에 넣는다. 증가는 일어났지만 대입이 덮어썼다.

## 5. 산술 연산자

### 5.1 나눗셈과 나머지

```java
int a = 10, b = 3;
a / b;                 // 3. 정수끼리 나누면 소수점 아래를 버린다
a % b;                 // 1. 10 = 3 × 3 + 1
(double) a / b;        // 3.333…  하나를 실수로 바꾸면 실수 나눗셈이 된다
-7 / 2;                // -3. 0 쪽으로 버린다. -4가 아니다
-7 % 3;                // -1. 부호는 왼쪽 피연산자를 따른다
```

정수 나눗셈이 소수점 아래를 버리는 이유는 결과 타입이 `int`이기 때문이다. 3절의 규칙대로 `int / int`는 `int`이고, 3.33을 `int`에 담을 방법이 없다. 버리는 방향이 "0 쪽"이라는 점은 알아 둘 만하다. `-7 / 2`는 -3.5에서 0 쪽으로 가 -3이다.

`%`의 부호가 왼쪽 피연산자를 따르는 것은 `a == (a / b) * b + a % b`가 항상 성립하도록 정의했기 때문이다. `-7 / 3`이 -2이므로 나머지는 `-7 - (-2 × 3) = -1`이다. 수학의 나머지(항상 0 이상)를 원한다면 `Math.floorMod(-7, 3)`을 쓴다. 결과는 2다.

### 5.2 0으로 나누기

```java
10 / 0;        // ArithmeticException
10.0 / 0.0;    // Infinity
0.0 / 0.0;     // NaN
```

정수는 예외를 던지고 실수는 값을 돌려준다. 이 차이는 2장의 저장 방식에서 온다. IEEE 754 실수에는 무한대와 "숫자 아님"을 위한 비트 패턴이 예약되어 있어 0으로 나눈 결과를 표현할 수 있다. 정수에는 그런 값이 없다. 32비트 전부가 숫자이므로 표현할 수 없는 결과에는 예외를 던지는 수밖에 없다.

| x | y | `x / y` | `x % y` |
|:--|:--|:--------|:--------|
| 유한수 | ±0.0 | ±Infinity | NaN |
| 유한수 | ±Infinity | ±0.0 | x |
| ±0.0 | ±0.0 | NaN | NaN |
| ±Infinity | ±Infinity | NaN | NaN |

### 5.3 문자와 문자열의 덧셈

```java
'a' - 'A';               // 32. 문자는 유니코드 번호라 계산된다
(char) ('A' + 32);       // 'a'
'7' - '0';               // 7. 숫자 문자를 정수로

"" + 1 + 2;              // "12"
1 + 2 + "";              // "3"
```

문자 연산은 2장에서 본 대로 `char`가 숫자이기 때문에 가능하다. `+`는 피연산자 중 하나라도 문자열이면 **문자열 연결**로 동작하는데, 이때 2절의 결합 방향이 결과를 가른다. `"" + 1 + 2`는 왼쪽부터 `("" + 1) + 2`이므로 처음부터 문자열 연결이고, `1 + 2 + ""`는 `(1 + 2) + ""`라서 덧셈이 먼저다.

## 6. 비교 연산자

### 6.1 값을 비교하는가, 주소를 비교하는가

```java
int a = 10, b = 10;
a == b;                        // true. 기본형은 값을 비교한다

String s1 = "hello";
String s2 = "hello";
String s3 = new String("hello");
s1 == s2;                      // true
s1 == s3;                      // false
s1.equals(s3);                 // true
```

`==`는 변수 칸에 들어 있는 것을 비교한다. 2장에서 기본형 변수에는 값이, 참조형 변수에는 주소가 들어 있다고 했다. 그래서 참조형에 `==`를 쓰면 "같은 객체인가"를 묻는 것이지 "내용이 같은가"를 묻는 것이 아니다. 내용 비교는 `equals()`의 몫이다.

`s1 == s2`가 `true`인 것은 그래서 오히려 특이한 경우다. 컴파일러는 소스에 적힌 문자열 리터럴을 한 곳(문자열 풀)에 모아 두고 같은 내용이면 같은 객체를 쓰게 한다. `new String("hello")`는 그 풀을 우회해 새 객체를 만든다. 이 최적화 때문에 `==`가 우연히 맞는 경우가 있어 버그가 늦게 드러난다. 문자열의 내부 구조는 [Chapter 09](../09-java-lang-package)에서 다룬다.

{{< callout type="warning" >}}
**문자열은 언제나 `equals()`로 비교한다.** `s1`이 `null`일 수 있다면 `s1.equals(s2)` 대신 `Objects.equals(s1, s2)`나 `"hello".equals(s1)`을 쓴다. 같은 함정이 `Integer` 같은 래퍼 클래스에도 있다. `Integer a = 127, b = 127`은 `==`가 `true`지만 `128`이면 `false`다. 작은 값만 캐시에서 같은 객체를 돌려주기 때문인데, 이 역시 9장에서 본다.
{{< /callout >}}

### 6.2 실수의 비교

```java
double d1 = 0.1 + 0.2;
d1 == 0.3;                        // false
Math.abs(d1 - 0.3) < 1e-9;        // true
```

2장에서 본 대로 0.1과 0.2는 이미 정확한 값이 아니다. 실수는 "같은가"가 아니라 "차이가 허용 오차보다 작은가"로 비교한다.

## 7. 논리 연산자

| 연산자 | 뜻 | `true`가 되는 조건 |
|:-------|:---|:-------------------|
| `&&` | AND | 둘 다 `true` |
| `\|\|` | OR | 하나라도 `true` |
| `!` | NOT | 피연산자가 `false` |

| x | y | `x && y` | `x \|\| y` | `!x` |
|:--|:--|:---------|:-----------|:-----|
| T | T | T | T | F |
| T | F | F | T | F |
| F | T | F | T | T |
| F | F | F | F | T |

### 7.1 단락 평가: 결과가 정해지면 멈춘다

```
a && b:  a가 false ─▶ b는 보지 않는다
a || b:  a가 true  ─▶ b는 보지 않는다
```

```java
String str = null;
if (str != null && str.length() > 0) {   // str이 null이면 length()는 실행되지 않는다
    ...
}

int x = 10;
if (true || ++x > 10) { }
x;                                        // 10. ++x는 실행되지 않았다
```

`&&`는 왼쪽이 `false`면 오른쪽이 무엇이든 `false`다. 볼 필요가 없는 것을 보지 않는 것이 **단락 평가**다. 성능도 이유지만 더 큰 쓸모는 위 첫 번째 예다. 오른쪽을 실행하면 안 되는 상황을 왼쪽 조건으로 막을 수 있다. `null` 검사와 사용을 한 식에 쓰는 관용구가 이 성질 위에 서 있다.

같은 AND인데 `&`와 `&&`가 따로 있는 이유가 여기서 나온다. `&`는 `boolean`에 쓰면 논리 AND로 동작하되 **양쪽을 항상 평가**한다. 오른쪽에 반드시 실행돼야 하는 부작용이 있을 때 쓰는데, 그런 코드는 읽기 어려우니 실무에서는 거의 언제나 `&&`다.

## 8. 비트 연산자

### 8.1 비트 논리 연산

| 연산자 | 뜻 | 1이 되는 조건 |
|:-------|:---|:--------------|
| `&` | AND | 둘 다 1 |
| `\|` | OR | 하나라도 1 |
| `^` | XOR | 서로 다름 |
| `~` | NOT | 각 비트를 뒤집는다 |

```java
int a = 0b1010;   // 10
int b = 0b1100;   // 12
a & b;            // 0b1000 = 8
a | b;            // 0b1110 = 14
a ^ b;            // 0b0110 = 6
~a;               // -11
```

`~10`이 `-11`인 것은 2장의 2의 보수 때문이다. 모든 비트를 뒤집는 것은 1의 보수이고, 2의 보수는 거기에 1을 더한 것이므로 `~x`는 언제나 `-(x + 1)`이다.

```java
int flags = 0;
flags |= 0b0100;                   // 특정 비트 켜기
boolean on = (flags & 0b0100) != 0;   // 특정 비트 확인
flags ^= 0b0100;                   // 특정 비트 뒤집기
(n & 1) == 0;                      // 짝수 판별. 마지막 비트가 0이면 짝수
```

비트 연산이 실무에서 쓰이는 자리는 이런 **플래그** 처리다. `int` 하나에 켜고 끌 수 있는 스위치 32개를 담고, 켜기·확인·끄기를 연산 한 번으로 한다. 2.2절에서 본 대로 비교 연산자와 섞을 때는 괄호가 필수다.

### 8.2 시프트 연산

```
 8       = 0000 1000
 8 << 1  = 0001 0000 = 16   (× 2)
 8 >> 1  = 0000 0100 =  4   (÷ 2)

-8       = 1111 1000
-8 >> 1  = 1111 1100 = -4   (부호 유지)
-8 >>> 1 = 0111…1100        (0으로 채움)
```

| 연산자 | 뜻 | 빈자리 |
|:-------|:---|:-------|
| `<<` | 왼쪽으로 n칸. 2^n 곱하기 | 0 |
| `>>` | 오른쪽으로 n칸. 2^n 나누기 | 부호 비트와 같은 값 |
| `>>>` | 오른쪽으로 n칸 | 0 |

2진수에서 한 칸 왼쪽으로 옮기면 값이 두 배가 되는 것은 10진수에서 0을 하나 붙이면 열 배가 되는 것과 같다. `>>`가 빈자리를 부호 비트로 채우는 이유는 음수를 오른쪽으로 옮겨도 음수로 남아야 "나누기"의 뜻이 유지되기 때문이다. `>>>`는 부호를 무시하고 0으로 채우므로 음수에 쓰면 아주 큰 양수가 된다. `-1 >>> 1`은 `2147483647`이다. 비트를 숫자가 아니라 비트열로 다룰 때, 예를 들어 해시 값을 섞을 때 쓴다.

{{< callout type="info" >}}
시프트 횟수는 왼쪽 피연산자의 비트 수 안에서만 의미가 있다. `int`는 하위 5비트만 써서 `1 << 32`는 `1 << 0`, 즉 1이다. 32칸을 옮겼으니 0이 될 것 같지만 그렇지 않다. `long`은 하위 6비트를 쓴다.
{{< /callout >}}

## 9. 조건 연산자

```java
int max = (a > b) ? a : b;
int abs = (n >= 0) ? n : -n;

String sign = (x > 0) ? "양수"
            : (x < 0) ? "음수"
            : "영";
```

`조건 ? 값1 : 값2`는 `if`문을 줄여 쓴 것이 아니라 **값을 돌려주는 식**이다. `if`문은 문장이라 대입의 오른쪽에 올 수 없지만 조건 연산자는 올 수 있다. 자바에서 유일하게 피연산자가 셋인 연산자라 삼항 연산자라고도 부른다. 중첩하면 위처럼 줄을 나눠 정렬해야 읽을 수 있고, 두 단계를 넘으면 `if`나 `switch`가 낫다.

```java
double d = true ? 1 : 2.0;   // 1.0
```

두 값의 타입이 다르면 3절의 산술 변환이 적용되어 결과 타입이 정해진다. 조건이 `true`라 `1`이 골라졌는데도 `double`인 이유는, 식의 타입이 실행 전에 하나로 정해져야 하기 때문이다. 어느 쪽이 골라질지는 실행해 봐야 알지만 타입은 컴파일 때 알아야 한다.

## 10. 대입 연산자

```java
int a, b, c;
a = b = c = 100;   // c = 100 → b = 100 → a = 100

3 = x;             // 컴파일 오류. 왼쪽에는 값을 담을 수 있는 것이 와야 한다
```

대입의 왼쪽에는 변수처럼 **값을 담을 수 있는 자리**만 올 수 있다. 리터럴이나 식의 결과는 자리가 아니라 값이라 왼쪽에 올 수 없다. 오른쪽은 값이면 무엇이든 된다.

### 10.1 복합 대입에는 형변환이 숨어 있다

| 복합 대입 | 뜻 |
|:----------|:---|
| `i += 3` | `i = i + 3` |
| `i -= 3` | `i = i - 3` |
| `i *= 3` | `i = i * 3` |
| `i /= 3` | `i = i / 3` |
| `i %= 3` | `i = i % 3` |
| `i <<= 2`, `i >>= 2` | `i = i << 2`, `i = i >> 2` |
| `i &= 3`, `i \|= 3`, `i ^= 3` | `i = i & 3`, `i = i \| 3`, `i = i ^ 3` |

```java
byte b = 10;
b = b + 5;     // 컴파일 오류. b + 5 는 int
b += 5;        // 된다. b = (byte)(b + 5) 와 같다
```

`b += 5`가 되는 이유는 복합 대입이 `b = (byte)(b + 5)`로 **정의되어 있기** 때문이다. 오른쪽을 계산한 뒤 왼쪽 변수의 타입으로 되돌리는 변환이 문법에 포함되어 있다. 편의를 위한 설계이지만, 3절의 규칙이 사라진 것은 아니다. `b + 5`는 여전히 `int`로 계산되고, 그 결과가 `byte`로 잘려 들어간다. `b`가 125라면 `b += 5`는 오류 없이 -126이 된다.

## 11. 형변환

```
byte→short→int→long→float→double
      char ↗
```

```java
int i = 100;
long l = i;            // 자동. 작은 타입에서 큰 타입으로
double d = l;          // 자동

double x = 3.14;
int n = (int) x;       // 3. 명시적. 소수점 아래를 버린다
int big = 300;
byte b = (byte) big;   // 44. 넘치는 비트를 버린다
```

큰 타입으로 가는 변환은 컴파일러가 알아서 한다. 값이 잘릴 위험이 없다고 보기 때문이다. 작은 타입으로 가는 변환은 반드시 `(type)`으로 명시해야 한다. 값이 잘릴 수 있으니 "알고 있다"는 표시를 요구하는 것이다. `(int) 3.14`는 소수점 아래를 버리고, `(byte) 300`은 300의 비트 중 하위 8비트만 남겨 44가 된다.

{{< callout type="info" >}}
"큰 타입으로 가면 안전하다"에는 예외가 하나 있다. `int`에서 `float`로, `long`에서 `double`로 가는 변환은 자동이지만 정밀도를 잃을 수 있다. `float f = 16777217;`은 `16777216`이 된다. `float`의 가수는 24비트라 2^24를 넘는 정수를 전부 표현하지 못하기 때문이다. 크기로는 4바이트에서 4바이트지만, 2장에서 본 대로 실수는 크기가 아니라 유효 숫자로 정밀도를 말한다.
{{< /callout >}}

## 12. instanceof

```java
Object obj = "Hello";
obj instanceof String;         // true
obj instanceof Object;         // true
null instanceof String;        // false. null은 어떤 타입의 인스턴스도 아니다

if (obj instanceof String) {   // 형변환 전에 확인한다
    String s = (String) obj;
    s.length();
}

if (obj instanceof String s) { // Java 16. 확인과 변환을 한 번에
    s.length();
}
```

`instanceof`는 참조 변수가 가리키는 객체가 어떤 타입인지 묻는다. 필요한 이유는 [Chapter 07](../07-oop-advanced)에서 볼 다형성 때문이다. `Object` 타입 변수에는 무엇이든 들어갈 수 있으므로, 실제로 무엇이 들어 있는지 확인하지 않고 `(String)`으로 바꾸면 실행 중에 `ClassCastException`이 난다. Java 16의 패턴 매칭은 "확인했으면 그 타입의 변수로 바로 쓰게 해 달라"는 오랜 요구에 대한 답이다. 같은 값을 두 번 쓰는 캐스트 문장이 사라진다.

## 13. 요약

| 항목 | 핵심 | 왜 |
|:-----|:-----|:---|
| 연산자 | 언제나 값을 돌려준다 | 그래서 식을 중첩하고 대입을 이어 쓸 수 있다 |
| 우선순위 | 산술 → 비교 → 논리 → 대입 | 사람이 식을 읽는 순서다 |
| 결합 방향 | 대부분 왼쪽부터. 단항과 대입은 오른쪽부터 | 단항은 오른쪽에 붙고 대입은 오른쪽 값이 먼저 필요하다 |
| 산술 변환 | 큰 타입으로 맞추고, `int`보다 작으면 `int` | JVM에 작은 정수용 산술 명령이 없다 |
| 증감 | 전위는 늘린 값, 후위는 옛 값을 돌려준다 | 값을 돌려준다는 원리의 적용 |
| 정수 나눗셈 | 0 쪽으로 버림. `%`의 부호는 왼쪽을 따른다 | 결과가 `int`이고 `a == (a/b)*b + a%b`가 성립해야 한다 |
| 0으로 나누기 | 정수는 예외, 실수는 `Infinity` | 실수에만 무한대 비트 패턴이 있다 |
| `==` | 기본형은 값, 참조형은 주소 | 변수 칸에 들어 있는 것을 비교한다 |
| 단락 평가 | `&&`, `\|\|`는 결과가 정해지면 멈춘다 | `null` 검사와 사용을 한 식에 쓸 수 있다 |
| 시프트 | `<<`는 곱하기, `>>`는 부호 유지 나누기, `>>>`는 0 채움 | 2진수의 자리 이동 |
| 복합 대입 | `b += 1`은 `b = (byte)(b + 1)` | 형변환이 정의에 포함되어 있다 |
| 형변환 | 큰 타입은 자동, 작은 타입은 명시 | 값이 잘릴 수 있으면 표시를 요구한다 |
| `instanceof` | 형변환 전에 타입 확인. 16부터 패턴 매칭 | 다형성 때문에 실제 타입을 모를 수 있다 |
