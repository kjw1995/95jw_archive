[04. 가정에서의 LAN 구성](../04-home-lan-configuration)의 집은 안과 밖, 두 영역뿐이었다. 회사는 다르다. 밖에 보여 줘야 하는 서버가 있고, 기기가 수백 대이며, 망이 멈추면 돈이 나간다. 이 장의 원리는 셋이다. 첫째, **회사 망의 설계는 "누가 어디에 닿을 수 있는가"를 정하는 일이다.** DMZ와 방화벽 정책이 그 답이고, 공개 서버는 뚫릴 수 있다는 전제에서 출발한다. 둘째, **하나로 되던 것을 나누고, 하나였던 것을 둘로 만든다.** 공유기 한 상자에 들어 있던 기능을 전용 장비로 쪼개고, 스위치 하나를 VLAN으로 나누고, 장비를 두 대씩 두는 이유가 전부 규모에서 나온다. 셋째, **서버를 어디에 둘지는 통제와 비용의 교환이다.** 온프레미스와 클라우드는 "어디까지 남에게 맡기는가"의 눈금이다.

## 1. 가정과 무엇이 다른가

| 구분 | 가정 | 회사 | 차이가 생기는 이유 |
|:-----|:-----|:-----|:------------------|
| 규모 | 10대 안팎 | 수십에서 수천 대 | 기기가 많으면 한 망에 다 넣을 수 없다 |
| 서버 | 없다 | 웹, 메일, DNS, 파일, DB | 밖에 보여 줄 것과 안에서만 쓸 것이 섞여 있다 |
| 영역 | 안과 밖 | 인터넷, DMZ, 서버팜, 내부망 | 뚫려도 피해를 한 영역에 가둔다 |
| 장비 | 공유기 한 대 | 라우터, 스위치, 방화벽, 무선 컨트롤러 | 성능과 관리, 장애 격리 |
| 장애 | 불편 | 손실 | 그래서 두 대씩 둔다 |
| 관리 | 본인 | 전담 인력과 정책 | 규칙이 사람보다 오래 간다 |

```text
        인터넷
          │
     ┌────┴────┐
     │  방화벽 │
     └────┬────┘
   ┌──────┼──────┐
   ▼      ▼      ▼
┌──────┬──────┬──────┐
│ DMZ  │ 서버 │ 내부 │
│      │  팜  │  망  │
└──────┴──────┴──────┘
```

집에서는 공유기의 NAT가 "밖에서 안으로 못 들어온다"를 공짜로 주었다. 회사는 그 문을 일부러 열어야 한다. 웹 사이트와 메일은 밖에서 들어와야 하기 때문이다. 문을 여는 순간 "어디까지 들어오게 할 것인가"가 설계의 중심이 되고, 그 답이 영역을 나누고 영역 사이에 방화벽을 두는 구조다.

## 2. DMZ: 뚫릴 것을 전제한 설계

```text
   인터넷
     │
┌────┴────┐
│ 외부 FW │  1차. 지정 포트만 통과
└────┬────┘
     │
   ┌─┴─┐
   │DMZ│  공개 서버
   └─┬─┘
┌────┴────┐
│ 내부 FW │  2차. DMZ에서 오는 것은 거부
└────┬────┘
     │
   ┌─┴─┐
   │LAN│
   └───┘
```

인터넷에 열린 서버는 언젠가 공격받는다. 이것을 막을 수 있다고 믿는 대신, **뚫려도 거기서 끝나게** 만드는 것이 DMZ다. 휴전선의 비무장 지대에서 이름을 따 왔다. 외부와 내부 사이에 완충 영역을 두고 공개 서버를 거기 놓으면, 서버가 장악되어도 공격자는 내부망 앞의 두 번째 벽을 다시 넘어야 한다. 방화벽을 둘 두는 이중 구성이 교과서적인 형태이고, 방화벽 하나에 인터페이스를 셋 달아(외부, DMZ, 내부) 같은 정책을 구현하는 것이 비용을 아낀 형태다.

| 방향 | 정책 | 왜 |
|:-----|:-----|:---|
| 인터넷 → DMZ | 지정 포트만 허용 (80, 443, 25 등) | 공개할 서비스의 포트만 연다. 나머지는 공격면이다 |
| DMZ → 내부망 | 기본 거부 | DMZ 서버가 장악되어도 내부로 못 오게 |
| 내부망 → DMZ | 관리 목적의 포트만 허용 | 관리자가 서버를 손봐야 한다 |
| 내부망 → 인터넷 | 업무에 필요한 것만 허용 | 밖으로 새는 것도 막는다. 악성 코드의 통신 차단 |

정책의 뿌리는 하나다. **기본은 거부, 필요한 것만 허용.** 집의 공유기가 NAT의 부산물로 하던 것을 회사는 명시적인 규칙으로 적는다. 규칙은 "출발지, 목적지, 포트"의 조합이고, 포트가 무엇인지는 [26. 포트 번호의 구조](../26-port-number-structure)에 있다.

{{< callout type="warning" >}}
가장 자주 깨지는 원칙이 **DMZ → 내부망 기본 차단**이다. 웹 서버가 내부의 DB를 읽어야 한다는 이유로 이 방향을 넓게 열면 DMZ의 의미가 사라진다. 여는 경우에도 DB 서버 한 대의 포트 하나로 한정하고, 가능하면 DB를 DMZ가 아닌 서버팜에 두고 그 한 줄만 허용한다.
{{< /callout >}}

요즘은 여기에 한 층이 더 붙는다. 공개 서버 앞에 역방향 프록시나 CDN, 웹 방화벽(WAF)을 두어 서버가 인터넷에 직접 닿지 않게 하고, 내부망도 믿지 않고 접속마다 확인하는 제로 트러스트가 방화벽 위에 얹힌다. 구조는 바뀌어도 "뚫릴 것을 전제한다"는 원리는 같다.

## 3. DMZ에 두는 서버

| 서버 | 역할 | 포트 | 왜 밖에 열어야 하나 |
|:-----|:-----|:-----|:-------------------|
| 웹 | HTTP, HTTPS | 80, 443 | 고객이 브라우저로 들어온다 |
| 메일 | SMTP, POP3, IMAP | 25, 587, 110, 143 | 다른 회사의 메일 서버가 우리 서버에 배달한다 |
| DNS | 우리 도메인의 이름 풀이 | 53 | 세상이 우리 서버의 주소를 물어본다 |
| FTP, SFTP | 파일 전송 | 20, 21, 22 | 외부와 파일을 주고받는다 |
| VPN | 원격 접속의 입구 | 443, 1194, 500 | 재택근무자가 내부로 들어오는 유일한 문 |

DMZ에 두는 기준은 단순하다. **밖에서 먼저 연결을 걸어오는 서버**만 둔다. DB 서버와 파일 서버는 안의 서버들이 찾아가는 것이지 밖에서 걸어오는 것이 아니므로 서버팜에 두고, DMZ의 웹 서버가 필요한 데이터만 방화벽의 한 줄을 통해 가져간다.

```
발신자 ─SMTP▶ 서버 A ─SMTP▶ 서버 B
                              │
                    POP3/IMAP │
                              ▼
                            수신자
```

메일이 좋은 예다. 우리 회사로 오는 메일은 상대 회사의 서버가 우리 메일 서버의 25번 포트로 직접 배달하므로 그 서버는 밖에 열려 있어야 하고, 직원이 메일을 읽는 POP3와 IMAP은 안에서 서버로 가는 방향이라 내부에서만 열어도 된다. 웹 서버가 요청을 받는 구조는 [29. 웹 서버의 구조](../29-web-server-structure)에서, 메일의 두 프로토콜은 [31. 메일 서버의 구조](../31-mail-server-structure)에서, 우리 도메인의 주소를 세상에 알리는 DNS는 [30. DNS 서버의 구조](../30-dns-server-structure)에서 본다.

## 4. 서버를 어디에 둘 것인가

| 방식 | 무엇인가 | 얻는 것 | 잃는 것 |
|:-----|:---------|:--------|:--------|
| 온프레미스 | 자체 시설에 서버를 두고 직접 운영 | 데이터와 설정을 완전히 통제. 내부망과의 지연이 없다 | 초기 비용, 운영 인력, 확장과 재해 복구가 어렵다 |
| 클라우드 | 사업자의 데이터센터를 인터넷으로 빌린다 | 초기 비용이 없고 필요한 만큼 늘리고 줄인다. 전 세계 배포 | 인터넷에 의존하고, 오래 쓰면 비싸질 수 있으며, 사업자에 묶인다 |
| 하이브리드 | 둘을 VPN으로 잇는다 | 통제가 필요한 것은 안에, 늘었다 줄었다 하는 것은 밖에 | 두 세계를 다 관리해야 한다 |

| 모델 | 남이 관리하는 것 | 내가 관리하는 것 | 예 |
|:-----|:-----------------|:-----------------|:---|
| IaaS | 건물, 전기, 하드웨어, 가상화 | OS부터 애플리케이션까지 | AWS EC2, Azure VM |
| PaaS | 여기에 OS와 실행 환경까지 | 코드와 데이터 | Elastic Beanstalk, Heroku |
| SaaS | 전부 | 사용과 설정 | Microsoft 365, Salesforce |

```text
┌──────────┐       ┌──────────┐
│온프레미스│◀─VPN─▶│ 클라우드 │
│          │       │          │
│핵심 DB   │       │웹서버    │
│레거시    │       │백업      │
└──────────┘       └──────────┘
```

세 모델의 차이는 기능이 아니라 **어디까지 남에게 맡기는가**의 눈금이다. 아래로 갈수록 내가 할 일이 줄고 마음대로 할 수 있는 것도 준다. 2절의 DMZ는 클라우드에서도 사라지지 않는다. 이름이 보안 그룹과 서브넷으로 바뀔 뿐, 공개 서버와 내부 서버를 다른 구역에 두고 그 사이의 규칙을 적는 일은 같다. 온프레미스와 클라우드를 잇는 VPN이 [03. LAN과 WAN](../03-lan-and-wan)에서 본 인터넷 VPN이고, 그 터널의 안쪽은 [08. 캡슐화와 역캡슐화](../08-encapsulation-decapsulation)에 있다.

## 5. 장비: 공유기를 쪼개면

| 기능 | 가정용 | 엔터프라이즈 | 왜 따로 두나 |
|:-----|:-------|:-------------|:------------|
| 라우터 | 공유기 안 | 전용 라우터 | WAN 회선이 여럿이고 라우팅 프로토콜을 돌린다 |
| 스위치 | 4포트 | 24, 48포트를 층마다 | 기기 수백 대. 포트와 처리량 |
| 방화벽 | NAT의 부산물 | UTM, NGFW | 규칙 수천 개, 침입 탐지, 애플리케이션 식별 |
| 무선 | 공유기의 AP | 컨트롤러 + AP 수십 대 | 건물 전체를 덮고 이동 중에도 끊기지 않게 |
| 관리 | 웹 화면 | CLI와 중앙 관리 | 장비 수십 대를 한 번에 설정하고 감시한다 |

4장의 공유기는 여섯 가지 일을 한 상자에서 했다. 회사에서 그것을 쪼개는 이유는 셋이다. **성능**은 기기 수백 대의 트래픽을 한 상자가 감당하지 못하고, **관리**는 기능마다 담당과 정책이 다르며, **장애 격리**는 무선 장비가 죽어도 유선은 살아 있어야 하기 때문이다. UTM은 방화벽에 바이러스 검사, 침입 탐지, 웹 필터를 합친 장비이고, NGFW는 포트 번호가 아니라 "어떤 애플리케이션인가"까지 식별해 규칙을 거는 방화벽이다. 시스코, 주니퍼(라우터와 스위치), 포티넷과 팔로알토(방화벽), 아루바(무선)가 대표 제조사다.

## 6. 사내 망 설계: 나누고 겹치기

### VLAN: 스위치 하나를 여럿으로

```text
┌────────────────────────┐
│       L2 스위치        │
│ ┌────┐  ┌────┐  ┌────┐ │
│ │VLAN│  │VLAN│  │VLAN│ │
│ │ 10 │  │ 20 │  │ 30 │ │
│ │영업│  │개발│  │인사│ │
│ └────┘  └────┘  └────┘ │
└────────────────────────┘
```

스위치는 프레임을 목적지 포트로만 보내지만 **브로드캐스트**는 모든 포트로 내보낸다. 4장의 DHCP Discover와 뒤에서 볼 ARP가 브로드캐스트다. 기기가 수백 대면 이 브로드캐스트만으로 망이 시끄러워지고, 한 기기의 고장이 폭풍이 되어 전체를 멈출 수 있다. 그리고 인사팀의 PC와 개발 서버가 같은 망에 있으면 서로 아무 제한 없이 닿는다. VLAN은 스위치 하나를 논리적으로 여러 스위치로 나눠 브로드캐스트의 범위와 보안 경계를 동시에 긋는다. 케이블을 다시 깔지 않고 설정만으로 나누므로 자리를 옮겨도 포트 설정만 바꾸면 된다. VLAN 사이는 다른 네트워크이므로 오가려면 라우터(또는 라우팅이 되는 L3 스위치)를 거쳐야 하고, 거기에 방화벽 규칙을 걸 수 있다. 스위치가 브로드캐스트를 막지 못하는 이유는 [14. 스위치의 구조](../14-switch-structure)에서, 브로드캐스트 도메인은 [20. 네트워크 주소와 브로드캐스트 주소의 구조](../20-network-broadcast-address)에서 본다.

### IP 체계: 나눈 망에 이름 붙이기

```
10.0.0.0/8
├─ 10.10.0.0/16  본사
│  ├─ 10.10.1.0/24  1층 (VLAN 10)
│  ├─ 10.10.2.0/24  2층 (VLAN 20)
│  ├─ 10.10.100.0/24  서버팜
│  └─ 10.10.200.0/24  DMZ
├─ 10.20.0.0/16  지사 A
└─ 10.30.0.0/16  지사 B
```

VLAN마다 서브넷 하나를 준다. 4장의 사설 대역 중 가장 큰 10.0.0.0/8을 잡고, 둘째 옥텟으로 지점을, 셋째 옥텟으로 층과 용도를 나누면 주소만 보고 어디의 무엇인지 읽힌다. 규칙 있는 체계는 방화벽 규칙을 짧게 만든다. "10.10.200.0/24에서 10.10.100.0/24로는 거부"처럼 대역 단위로 적을 수 있기 때문이다. 나누는 계산은 [21. 서브넷의 구조와 서브넷팅](../21-subnet-structure)에 있다.

### 이중화: 하나였던 것을 둘로

| 대상 | 방법 | 왜 |
|:-----|:-----|:---|
| 라우터, 방화벽 | HSRP, VRRP로 두 대가 게이트웨이 주소 하나를 나눠 갖는다 | 한 대가 죽으면 다른 대가 같은 주소로 이어받는다 |
| 스위치 사이 | 링크 집합(LACP)으로 케이블 여러 가닥을 하나처럼 | 한 가닥이 끊겨도 대역폭만 줄고 연결은 산다 |
| 서버 | NIC 둘을 다른 스위치에 | 스위치 한 대가 죽어도 서버는 살아 있다 |
| 회선 | ISP 둘 | 통신사 하나의 장애가 회사 전체의 장애가 되지 않게 |

집에서는 공유기가 죽으면 다시 켜면 된다. 회사에서는 그 사이 주문이 끊기고 공장이 선다. 그래서 **하나뿐인 것**을 찾아 둘로 만드는 것이 이중화이고, 하나뿐이라 죽으면 전체가 죽는 지점을 단일 장애점이라 부른다. 두 대가 게이트웨이 주소 하나를 나눠 갖는 방법은 [22. 라우터의 구조와 라우팅](../22-router-structure)의 기본 게이트웨이 절과 이어진다.

---

## 7. 실제 구성 예시

```
인터넷─[FW/RT]─[스위치]─┬─ PC 5대
                      ├─ 프린터
                      └─ Wi-Fi AP
```

소규모 사무실(SOHO)은 집과 거의 같다. 방화벽 겸 라우터 한 대와 스위치 한 대이고 DMZ가 없다. 공개할 서버가 없거나 있어도 클라우드에 두기 때문이다.

```
인터넷
  │
[방화벽]
  ├─[DMZ]─ 웹·메일 서버
  └─[코어 스위치]
     ├─ 서버팜 (DB·파일)
     ├─ 층별 L2 스위치
     └─ 무선 컨트롤러·AP
```

50명에서 100명 규모부터 이 장의 구조가 그대로 나타난다. 방화벽이 영역을 가르고, 코어 스위치가 층별 스위치와 서버팜을 모으며, 층별 스위치마다 VLAN을 나누고, 방화벽과 코어 스위치는 두 대씩이다.

## 핵심 정리

| 구성 요소 | 역할 | 왜 |
|:----------|:-----|:---|
| 영역 분리 | 인터넷, DMZ, 서버팜, 내부망 | 뚫려도 피해를 한 영역에 가둔다 |
| DMZ | 밖에서 먼저 연결해 오는 서버의 자리 | 공개 서버는 언젠가 뚫린다는 전제 |
| 방화벽 정책 | 기본 거부, 필요한 것만 허용 | 집에서 NAT가 공짜로 주던 것을 규칙으로 적는다 |
| DMZ → 내부망 차단 | 가장 자주 깨지는 원칙 | 여는 순간 DMZ의 뜻이 사라진다 |
| 온프레미스와 클라우드 | 통제와 비용의 교환 | IaaS, PaaS, SaaS는 남에게 맡기는 정도의 눈금 |
| 전용 장비 | 공유기의 기능을 쪼갠 것 | 성능, 관리, 장애 격리 |
| VLAN | 스위치 하나를 논리적으로 여럿으로 | 브로드캐스트 범위와 보안 경계를 배선 없이 긋는다 |
| IP 체계 | 대역으로 지점과 용도를 읽게 | 방화벽 규칙이 대역 단위로 짧아진다 |
| 이중화 | 하나뿐인 것을 둘로 | 단일 장애점은 회사에서 손실이다 |

{{< callout type="info" >}}
**용어 정리**
- **SOHO**: Small Office/Home Office. 집과 비슷한 구조의 소규모 사업장 망
- **DMZ**: Demilitarized Zone. 인터넷과 내부망 사이에 둔 완충 영역. 공개 서버를 놓는다
- **UTM / NGFW**: 방화벽에 검사 기능을 합친 장비 / 애플리케이션까지 식별하는 차세대 방화벽
- **온프레미스**: 자체 시설에 직접 구축해 운영하는 방식
- **클라우드 / IaaS, PaaS, SaaS**: 인터넷으로 빌려 쓰는 컴퓨팅 / 인프라, 플랫폼, 완성 앱 단위로 빌리는 모델
- **VLAN**: Virtual LAN. 스위치 하나를 논리적으로 나눈 네트워크
- **이중화 / 단일 장애점**: 하나뿐인 장비나 회선을 둘로 두는 것 / 하나가 죽으면 전체가 죽는 지점
- **HSRP / VRRP**: 라우터 두 대가 게이트웨이 주소 하나를 나눠 갖는 프로토콜(시스코 전용 / 표준)
{{< /callout >}}
