[06. 네트워크의 규칙 - 프로토콜](../06-network-protocol)에서 규칙이 한 줄이 아니라 다섯 줄인 이유를 "문제가 다르면 규칙도 다르다"로 설명했다. 이 장은 그 층을 정식으로 세운 두 모델을 본다. 원리는 셋이다. 첫째, **계층은 문제를 나누기 위한 것이고, 각 층은 아래 층을 믿는다.** 층마다 답하는 질문이 하나씩이고, 그래서 한 층을 갈아 끼워도 나머지는 모른다. 둘째, **OSI는 설계도이고 TCP/IP는 지어진 집이다.** 위원회가 그린 7층 도면보다 먼저 돌아가던 4층짜리 집이 표준이 됐지만, 도면의 용어는 살아남아 지금도 "L2 스위치", "L7 방화벽"으로 쓰인다. 셋째, **같은 데이터가 층마다 다른 이름으로 불린다.** 세그먼트, 패킷, 프레임은 다른 물건이 아니라 같은 데이터에 봉투가 몇 겹 붙었는지의 차이다.

## 1. 왜 계층으로 나누는가

```
7 응용     무엇을 주고받나
4 전송     어느 프로그램에게, 신뢰는?
3 네트워크 어느 망의 어느 기계에게
2 링크     바로 옆 기계에게 어떻게
1 물리     비트를 어떤 신호로
```

1980년대 초까지 제조사마다 자기 규격을 썼고, 규격 하나가 신호부터 화면 표시까지 전부를 정했다. 그래서 다른 제조사의 장비와는 통신이 안 됐고, 한 부분을 바꾸려면 전부를 다시 만들어야 했다. 계층 모델은 통신을 **서로 다른 질문 몇 개**로 쪼갠 것이다. 위의 다섯 질문은 서로 독립적이다. "무엇을 주고받나"(HTTP)는 "비트를 어떤 신호로"(케이블인지 전파인지)와 아무 상관이 없다. 그래서 층마다 규칙을 따로 두고, 각 층은 바로 아래 층이 자기 일을 해 준다고 믿기만 하면 된다.

| 얻는 것 | 뜻 | 예 |
|:--------|:---|:---|
| 독립성 | 한 층을 바꿔도 다른 층은 모른다 | Wi-Fi로 바꿔도 브라우저는 그대로다 |
| 표준화 | 층마다 규칙을 따로 정하고 따로 발전시킨다 | 이더넷은 10Mbps에서 400Gbps가 됐지만 IP는 그대로다 |
| 교체 가능 | 같은 층의 규칙끼리는 갈아 끼울 수 있다 | IPv4를 IPv6로, TCP를 UDP로 |
| 진단 | 문제를 층 단위로 좁힌다 | 6절 |

독립성은 실제로 이렇게 보인다. 필자의 PC에서 `curl -v http://example.com`을 실행하면 "IPv6: (none)"이라 찍히고 IPv4로 연결된다. `example.com`은 IPv6 주소도 갖고 있지만 이 PC의 회선에 IPv6가 없어서 그렇다. 그런데 HTTP 요청과 응답은 [06](../06-network-protocol)장에서 본 것과 한 글자도 다르지 않다. 네트워크 층이 어느 규칙을 쓰는지를 응용 층은 모르고, 알 필요도 없다.

## 2. OSI 7계층: 설계도

```text
┌──────────────────────────┐
│ 7 응용 (Application)     │
├──────────────────────────┤
│ 6 표현 (Presentation)    │
├──────────────────────────┤
│ 5 세션 (Session)         │
├──────────────────────────┤
│ 4 전송 (Transport)       │
├──────────────────────────┤
│ 3 네트워크 (Network)     │
├──────────────────────────┤
│ 2 데이터링크 (Data Link) │
├──────────────────────────┤
│ 1 물리 (Physical)        │
└──────────────────────────┘
```

ISO가 1984년에 확정한 OSI(Open Systems Interconnection) 참조 모델은 통신을 일곱 층으로 나눈다. 외울 때는 "응표세전네데물"이다. 위에서부터 사람에 가깝고 아래로 갈수록 전선에 가깝다.

| 층 | 답하는 질문 | 대표 규칙과 기술 | 장비 |
|:---|:-----------|:-----------------|:-----|
| 7 응용 | 프로그램이 무엇을 주고받나 | HTTP, DNS, SMTP, FTP, SSH | |
| 6 표현 | 어떤 형식으로 적고, 압축하고, 암호화하나 | TLS, JPEG, UTF-8, gzip | |
| 5 세션 | 대화를 언제 시작하고 끝내나 | 세션 관리, RPC | |
| 4 전송 | 어느 프로그램에게, 믿을 수 있게 | TCP, UDP, 포트 번호 | |
| 3 네트워크 | 어느 망의 어느 기계에게 | IP, ICMP, 라우팅 | 라우터 |
| 2 데이터 링크 | 같은 망 안의 옆 기계에게 어떻게 | 이더넷, Wi-Fi, MAC 주소 | 스위치 |
| 1 물리 | 비트를 어떤 신호로 | 케이블, 커넥터, 전압, 전파 | 허브, 리피터 |

### 위의 세 층: 응용, 표현, 세션

응용 층은 사용자의 프로그램이 네트워크를 만나는 창구다. 브라우저의 HTTP, 메일의 SMTP, 이름 풀이의 DNS가 여기 있고, 이 시리즈의 마지막 아홉 장이 이 층이다. 표현 층은 "같은 데이터를 어떻게 적을 것인가"다. [02. 비트와 바이트](../02-bit-and-byte)의 인코딩, 압축, 암호화가 여기 속하고, HTTPS의 TLS를 이 층에 두는 것이 교과서의 배치다. 세션 층은 대화의 시작과 끝, 순서를 관리한다. OSI가 세션 층의 일로 든 것이 대화의 방향인데, 실제로는 매체의 성질이라 [15. 데이터가 케이블에서 충돌하지 않는 구조](../15-collision-free-structure)에서 전이중을 다시 만난다.

| 방식 | 뜻 | 예 |
|:-----|:---|:---|
| 단방향 (simplex) | 한쪽만 보낸다 | 라디오, TV |
| 반이중 (half-duplex) | 양쪽이 번갈아 | 무전기, 허브 시절의 이더넷, Wi-Fi |
| 전이중 (full-duplex) | 양쪽이 동시에 | 전화, 스위치의 이더넷 |

이 세 층은 3절에서 하나로 합쳐진다. 그 이유를 미리 말하면, 표현과 세션의 일은 별도의 프로토콜이 아니라 **응용 프로그램 안에서** 처리되기 때문이다.

### 아래의 네 층: 전송, 네트워크, 데이터 링크, 물리

전송 층은 "이 기계의 어느 프로그램에게"를 포트 번호로 가리키고, TCP라면 순서와 재전송으로 신뢰까지 준다([23](../23-transport-layer-role), [24](../24-tcp-structure)장). 네트워크 층은 세계 공통의 주소(IP)로 다른 망의 기계를 가리키고 거기까지의 길을 고른다([17](../17-network-layer-role), [22](../22-router-structure)장). 데이터 링크 층은 같은 망 안에서 바로 옆 기계에게 프레임을 건네고 깨졌는지 확인한다([12](../12-datalink-layer-ethernet)장).

```text
프레임 구조
┌──────┬──────┬────┬──────┬────┐
│목적지│출발지│타입│데이터│FCS │
│ MAC  │ MAC  │    │      │    │
│  6B  │  6B  │ 2B │ 가변 │ 4B │
└──────┴──────┴────┴──────┴────┘
```

데이터 링크 층은 둘로 더 나뉜다. 위쪽 LLC는 어느 상위 규칙에게 줄지와 흐름 제어를, 아래쪽 MAC은 주소와 "누가 언제 보낼 수 있나"(매체 접근 제어)를 맡는다. 이더넷과 Wi-Fi가 다른 것은 MAC 쪽이고, 그 위는 같다. 물리 층은 [02](../02-bit-and-byte)장에서 본 대로 비트를 전압, 빛, 전파로 바꾸며, 케이블의 종류와 커넥터 모양까지 여기서 정한다([09](../09-physical-layer-nic), [10](../10-cable-types-structure)장).

## 3. TCP/IP 4계층: 지어진 집

| OSI 7계층 | TCP/IP 4계층 | 대표 규칙 |
|:----------|:-------------|:----------|
| 7 응용 | 4 응용 | HTTP, DNS, SMTP, FTP, SSH |
| 6 표현 | 4 응용 | TLS, 인코딩 |
| 5 세션 | 4 응용 | 프로그램 안의 세션 관리 |
| 4 전송 | 3 전송 | TCP, UDP |
| 3 네트워크 | 2 인터넷 | IP, ICMP, ARP |
| 2 데이터 링크 | 1 네트워크 접속 | 이더넷, Wi-Fi |
| 1 물리 | 1 네트워크 접속 | 신호와 매체 규격 |

```
┌──────────────────────────┐
│ 응용   HTTP DNS FTP SMTP │
│ 전송   TCP  UDP          │
│ 인터넷 IP  ICMP  ARP     │
│ 접속   이더넷  Wi-Fi     │
└──────────────────────────┘
```

실제 인터넷이 쓰는 모델은 네 층이다. 1970년대에 ARPANET을 만들면서 먼저 코드로 구현되고 1989년의 RFC 1122가 그 네 층을 문서로 정리했다. OSI의 일곱 층이 넷으로 줄어든 자리는 정확히 두 곳이다. 위의 세 층이 응용 하나로, 아래의 두 층이 네트워크 접속 하나로 합쳐졌다.

위의 세 층이 합쳐진 이유는 2절에서 말한 대로 표현과 세션에 **독립된 프로토콜이 거의 없기** 때문이다. 인코딩과 압축은 HTTP 헤더 한 줄(`Content-Type`, `Content-Encoding`)로 응용 프로토콜 안에서 처리되고, 세션은 프로그램이 알아서 관리한다. TLS가 몇 층이냐를 두고 지금도 답이 갈리는 것이 그 증거다. 전송 층 위에 얹혀 응용에게 안전한 통로를 주는 TLS는 OSI의 어느 칸에도 딱 맞지 않는다. 아래의 두 층이 합쳐진 이유는 반대다. 물리와 데이터 링크는 이더넷이나 Wi-Fi 같은 **하나의 기술이 둘을 함께** 정하기 때문이다. IEEE 802.3이 케이블의 전압과 프레임의 형식을 한 문서에 담는다. 그래서 교과서에 따라서는 물리를 떼어 다섯 층으로 그리기도 한다.

## 4. OSI와 TCP/IP: 설계도와 집

| 항목 | OSI | TCP/IP |
|:-----|:----|:-------|
| 층 수 | 7 | 4 |
| 만든 곳 | ISO. 국제 표준 위원회 | DARPA와 ARPANET을 만든 연구자들 |
| 시기 | 1977년 시작, 1984년 확정 | 1974년 논문, 1983년 ARPANET 전환 |
| 성격 | 먼저 그린 설계도 | 먼저 돌아간 코드 |
| 지금 | 교육과 설계의 공통 언어 | 인터넷 그 자체 |

OSI가 진 이유는 [06](../06-network-protocol)장의 RFC 문화와 같은 이야기다. OSI는 위원회가 7년에 걸쳐 완벽을 기해 그린 설계도였고, 그 설계도대로 지은 집(OSI 프로토콜 묶음)이 나왔을 때 TCP/IP는 이미 대학과 연구소의 망에서 몇 해째 돌아가고 있었다. 층이 넷이라 구현이 쉬웠고, 특정 하드웨어나 운영체제에 매이지 않았으며, 규칙이 공개되어 누구나 구현할 수 있었다. 인터넷이 자라면서 사실상의 표준이 됐다.

그런데 설계도의 용어는 살아남았다. 스위치를 L2 장비, 라우터를 L3 장비, 애플리케이션까지 보는 방화벽을 L7 방화벽이라 부르고, 장애를 "3계층 문제"라고 말한다. TCP/IP의 네 층은 이름이 뭉뚱그려져 있어서 "네트워크 접속 층 문제"로는 케이블인지 스위치 설정인지 구별이 안 된다. OSI의 일곱 층은 실제 프로토콜 묶음으로는 졌지만, **통신을 이야기하는 공통의 언어**로는 이겼다. 이 시리즈가 OSI의 층 이름을 따라 장을 나눈 것도 그래서다.

## 5. PDU: 층마다 다른 이름

| 층 | PDU | 무엇이 붙었나 |
|:---|:----|:-------------|
| 응용 | 데이터 | 프로그램이 만든 내용 |
| 전송 | 세그먼트(TCP), 데이터그램(UDP) | TCP 또는 UDP 헤더 |
| 네트워크 | 패킷 | IP 헤더 |
| 데이터 링크 | 프레임 | 이더넷 헤더와 뒤의 FCS |
| 물리 | 비트 | 신호 |

```
응용     [        데이터        ]
전송     [TCP][     데이터      ]
네트워크 [IP][TCP][   데이터    ]
링크  [ETH][IP][TCP][데이터][FCS]
물리  0101 1101 ... (신호)
```

세그먼트, 패킷, 프레임은 서로 다른 물건이 아니다. 같은 데이터에 봉투가 한 겹씩 더 붙은 상태를 각 층이 **자기 이름으로** 부를 뿐이다. 전송 층은 자기 헤더가 붙은 단위를 세그먼트라 하고, 네트워크 층은 거기에 IP 헤더를 붙인 것을 패킷이라 하며, 데이터 링크 층은 그 앞뒤에 이더넷 헤더와 FCS를 붙인 것을 프레임이라 한다. 이름이 층마다 있는 이유는 각 층이 자기 봉투만 보기 때문이다. 라우터는 프레임을 뜯어 패킷만 보고, 스위치는 프레임의 헤더까지만 본다. 봉투를 붙이고 뜯는 과정과 각 헤더의 필드는 [08. 캡슐화와 역캡슐화](../08-encapsulation-decapsulation)에서 본다.

## 6. 층으로 문제를 찾는다

| 증상 | 의심할 층 | 확인 |
|:-----|:----------|:-----|
| 링크 LED가 꺼져 있다 | L1 | 케이블과 포트를 바꿔 본다 |
| 같은 망의 옆 PC도 안 보인다 | L2 | 스위치 포트, VLAN, `arp -a` |
| 게이트웨이에 `ping`이 안 간다 | L3 | `ipconfig`로 주소, 마스크, 게이트웨이 확인 |
| `ping`은 되는데 접속이 안 된다 | L4 | 방화벽의 포트 차단. `netstat`, `Test-NetConnection` |
| 접속은 되는데 응답이 이상하다 | L7 | 서버 로그, 브라우저 개발자 도구 |

계층 모델의 가장 실용적인 쓸모가 이것이다. "인터넷이 안 된다"는 증상 하나를 층 단위로 쪼개면 아래에서 위로 하나씩 지워 갈 수 있다. 케이블이 꽂혀 있는가, 옆 기계가 보이는가, 게이트웨이가 답하는가, 상대의 포트가 열려 있는가, 응답의 내용이 맞는가. 아래 층이 안 되면 위 층은 볼 필요도 없다. 각 층은 아래 층을 믿는다는 첫째 원리가 진단 순서를 정해 준다. [06](../06-network-protocol)장의 도구들이 이 표의 확인 열이다.

## 7. 계층별 장비

| 층 | 장비 | 무엇을 읽나 |
|:---|:-----|:-----------|
| L1 | 허브, 리피터, 케이블 | 신호만. 읽지 않고 되쏜다 |
| L2 | 스위치, 브리지 | 프레임의 MAC 주소 |
| L3 | 라우터, L3 스위치 | 패킷의 IP 주소 |
| L4 ~ L7 | 방화벽, 로드 밸런서, WAF | 포트 번호, 그리고 데이터의 내용까지 |

[01](../01-network-basics)장에서 장비의 층은 "패킷의 어디까지 읽는가"라고 했다. 5절의 봉투 그림과 겹쳐 보면 그대로다. 허브는 봉투를 열지 않고, 스위치는 겉봉투(프레임)의 주소만 읽고, 라우터는 한 겹 안의 주소(IP)를 읽는다. 방화벽과 로드 밸런서는 그보다 안쪽, 포트 번호와 데이터의 내용까지 읽는다. 깊이 읽을수록 똑똑해지고 느려진다. 스위치가 라우터보다 빠르고 방화벽이 병목이 되는 이유가 읽는 깊이의 차이다.

| 개념 | 핵심 | 왜 |
|:-----|:-----|:---|
| 계층 | 통신을 독립된 질문들로 나눈다 | 한 층을 바꿔도 나머지가 모른다 |
| 아래 층을 믿는다 | 각 층은 자기 문제만 푼다 | HTTP는 IPv4인지 IPv6인지 모른다 |
| OSI 7계층 | ISO의 설계도, 1984년 | 제조사마다 다르던 규격을 하나의 언어로 |
| 응표세전네데물 | 응용, 표현, 세션, 전송, 네트워크, 데이터 링크, 물리 | 위가 사람, 아래가 전선 |
| TCP/IP 4계층 | 먼저 돌아간 집 | 위의 셋은 응용 안에서, 아래의 둘은 한 기술이 |
| 표현·세션의 흡수 | 독립된 프로토콜이 없다 | 인코딩과 세션은 프로그램 안의 일. TLS의 층 논쟁 |
| OSI가 남은 곳 | L2, L3, L7이라는 말 | 통신을 이야기하는 공통 언어로 이겼다 |
| PDU | 세그먼트, 패킷, 프레임, 비트 | 같은 데이터에 봉투가 몇 겹인가 |
| 진단 | 아래 층부터 위로 | 아래가 안 되면 위는 볼 필요가 없다 |
| 장비의 층 | 어디까지 읽는가 | 깊이 읽을수록 똑똑하고 느리다 |

**용어 정리**
- **OSI (Open Systems Interconnection)**: ISO가 1984년에 확정한 7계층 참조 모델. 실제 프로토콜보다 공통 용어로 살아남았다
- **TCP/IP 모델**: 인터넷이 실제로 쓰는 4계층 모델. 응용, 전송, 인터넷, 네트워크 접속
- **PDU (Protocol Data Unit)**: 각 층이 다루는 데이터 단위. 세그먼트, 패킷, 프레임, 비트
- **캡슐화 / 역캡슐화**: 층마다 헤더를 덧붙이는 것 / 받는 쪽이 한 겹씩 뜯는 것 ([08](../08-encapsulation-decapsulation))
- **LLC / MAC**: 데이터 링크 층의 위아래 절반. 상위 규칙 연결과 흐름 제어 / 주소와 매체 접근 제어
- **단방향 / 반이중 / 전이중**: 한쪽만 / 번갈아 / 동시에 보내는 통신 방식
