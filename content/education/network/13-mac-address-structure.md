[09. 물리 계층의 역할과 랜 카드의 구조](../09-physical-layer-nic)에서 MAC 주소는 카드에 새겨지고 앞 절반은 제조사의 것이라고 했고, [12. 데이터 링크 계층의 역할과 이더넷](../12-datalink-layer-ethernet)에서는 그 주소가 프레임의 맨 앞에 놓인다고 했다. 이 장은 그 48비트를 비트 단위로 들여다본다. 원리는 셋이다. 첫째, **MAC 주소는 카드의 이름이고 IP 주소는 위치다.** 이름은 어디로 가져가도 같고 위치는 옮기면 바뀐다. 네트워크에 주소가 두 종류나 있는 이유이자, 둘을 잇는 ARP가 필요한 이유다. 둘째, **48비트 안에 세 가지 정보가 들어 있다.** 누가 만들었는지, 한 대에게 보내는지 여럿에게 보내는지, 공장이 새긴 것인지 소프트웨어가 정한 것인지가 정해진 비트에 적혀 있고, 그 비트가 첫 바이트의 끝자리인 데는 이유가 있다. 셋째, **주소는 새겨지지만 믿을 수는 없다.** 스마트폰은 일부러 주소를 바꾸고, 누구나 명령 한 줄로 바꿀 수 있으므로 MAC 주소는 식별이지 인증이 아니다. 이 장의 실측은 필자 PC의 어댑터와 ARP 캐시에서 읽은 것이다.

## 1. MAC 주소: 카드의 이름

| 항목 | 값 | 왜 |
|:-----|:---|:---|
| 길이 | 48비트, 6바이트 | 약 281조 개. 세상의 모든 카드에 다른 번호를 주고도 남는다 |
| 표기 | 16진수 12자리 | [02](../02-bit-and-byte)장에서 본 대로 바이트 하나가 두 자리다 |
| 유일성 | 전 세계 | 2절의 배분 방식이 보장한다 |
| 누가 정하나 | 제조사가 만들 때 새긴다 | 그래서 어디로 가져가도 같다 |
| 쓰는 층 | 2층 | 같은 링크 안의 옆 기계를 가리킨다 |

주소가 두 종류나 있는 이유부터 짚어야 한다. IP 주소는 **위치**다. 노트북을 회사에서 집으로 가져가면 IP 주소가 바뀌고, [04](../04-home-lan-configuration)장의 DHCP가 그 자리에 맞는 주소를 새로 준다. MAC 주소는 **이름**이다. 카드에 새겨져 어디로 가져가도 같다. 2층은 한 링크 안에서만 배달하므로 위치가 필요 없고 이름으로 충분하며, 3층은 세계 어디로든 보내야 하므로 어느 망의 어느 자리인지를 말하는 위치가 필요하다. 이름만으로 세계를 찾을 수 없는 것은 전화번호부에 이름만 적혀 있는 것과 같다. 두 층이 서로 다른 주소를 쓰는 것이 아니라, **서로 다른 질문에 답하는 주소**를 쓰는 것이다.

## 2. 48비트의 구조

```
 00:23:AE  :  D9:7A:9A
 └─OUI──┘   └─NIC──┘
  24bit       24bit
 제조사ID    일련번호
```

| 부분 | 비트 | 누가 정하나 | 경우의 수 |
|:-----|:-----|:-----------|:----------|
| OUI | 24 | IEEE가 제조사에게 판다 | 약 1,677만 제조사 |
| 일련번호 | 24 | 제조사가 카드마다 다르게 | OUI 하나에 약 1,677만 대 |

유일성을 보장하는 방법은 중앙에서 전부 나눠 주는 것이 아니라 **두 단계로 위임**하는 것이다. IEEE는 제조사에게 앞 24비트 하나를 팔고 뒤는 제조사에게 맡긴다. 제조사끼리는 앞이 다르니 겹칠 수 없고, 한 제조사 안에서는 자기가 관리하니 겹치지 않는다. 한 OUI로 1,677만 대를 만들면 다음 OUI를 산다. 큰 제조사는 수십 개를 갖고 있다.

| OUI | 누구 |
|:----|:-----|
| 00:00:0C | Cisco |
| 00:50:56 | VMware 가상 카드 |
| 08:00:27 | VirtualBox 가상 카드 |
| 00:15:5D | Microsoft. Hyper-V 가상 카드 |
| B8:27:EB | Raspberry Pi |
| 3C:5A:B4 | Google |

이 PC의 어댑터 목록이 표의 예다. 유선 카드는 9장에서 본 대로 `B4-2E-99`로 시작해 메인보드 제조사의 것이고, Hyper-V가 만든 가상 어댑터 둘은 `00-15-5D`로 시작해 Microsoft의 OUI를 달고 있다. 가상 카드에도 진짜 제조사처럼 OUI가 있는 것은, 같은 링크에 실제 카드와 가상 카드가 섞여 있어도 이름이 겹치면 안 되기 때문이다. ARP 캐시에 남은 같은 망의 이웃들도 앞 세 바이트만 보면 어느 회사의 장비인지 대략 안다. 이 PC와 같은 `B4-2E-99`로 시작하는 이웃이 하나 있어 같은 회사의 메인보드라는 것까지 짐작된다. 반대로 OpenVPN이 만든 TAP 가상 어댑터는 `00-FF`로 시작하는데, 이 번호는 IEEE 표에 없다. 배분 규칙은 제조사가 지키는 약속이지 강제할 방법은 없다는 뜻이고, 5절의 이야기는 여기서 출발한다.

## 3. 표기 방식

| 스타일 | 예 | 어디서 |
|:-------|:---|:-------|
| 콜론 | 00:23:AE:D9:7A:9A | 리눅스, macOS, 대부분의 문서 |
| 하이픈 | 00-23-AE-D9-7A-9A | Windows의 `ipconfig`, `getmac` |
| 점 | 0023.AED9.7A9A | Cisco 장비 |
| 구분자 없음 | 0023AED97A9A | 데이터베이스, 설정 파일 |

같은 주소를 운영체제와 장비마다 다르게 적는다. 값은 같고 구분자만 다르며 대소문자도 가리지 않으므로, 도구 사이에 주소를 옮길 때는 구분자를 바꿔 주면 된다. 표기가 통일되지 않은 것은 표준이 주소의 비트만 정했지 사람이 읽는 형식은 정하지 않았기 때문이다.

## 4. 유니캐스트, 멀티캐스트, 브로드캐스트

| 첫 바이트의 비트 | 0이면 | 1이면 |
|:-----------------|:------|:------|
| 가장 낮은 비트 (I/G) | 한 대에게 (유니캐스트) | 여럿에게 (그룹) |
| 둘째로 낮은 비트 (U/L) | 제조사가 새긴 전역 주소 | 소프트웨어가 정한 로컬 주소 |

| 첫 바이트 | 2진 | I/G | U/L | 뜻 |
|:----------|:----|:----|:----|:---|
| B4 | 1011010**0** | 0 | 0 | 이 PC의 유선 카드. 한 대, 공장이 새김 |
| 01 | 0000000**1** | 1 | 0 | IPv4 멀티캐스트 |
| 33 | 0011001**1** | 1 | 1 | IPv6 멀티캐스트 |
| 02 | 000000**1**0 | 0 | 1 | 소프트웨어가 정한 유니캐스트. 랜덤 MAC의 전형 |
| FF | 11111111 | 1 | 1 | 브로드캐스트 |

주소의 종류는 첫 바이트의 가장 낮은 두 비트에 적혀 있다. 왜 하필 **첫 바이트의 끝자리**인가. 이더넷은 바이트를 보낼 때 낮은 비트부터 내보낸다. 그러니 첫 바이트의 가장 낮은 비트가 프레임에서 주소의 **첫 번째 비트**이고, 카드는 그 한 비트만 받고도 "여럿에게 가는 것인가"를 안다. 12장에서 목적지 주소를 맨 앞에 둔 이유와 같은 발상이다. 가장 빨리 판단할 것을 가장 앞에 둔다.

```
유니캐스트      [A] ──→ [B]

멀티캐스트      [A] ─┬→ [G1]
                    └→ [G2]

브로드캐스트    [A] ─┬→ [B]
                    ├→ [C]
                    └→ [D]
```

| 유형 | 주소 | 받는 쪽 | 왜 있나 |
|:-----|:-----|:--------|:--------|
| 유니캐스트 | 카드에 새겨진 주소 | 그 카드 하나 | 보통의 통신 |
| 멀티캐스트 | 01:00:5E:xx:xx:xx (IPv4), 33:33:xx:xx:xx:xx (IPv6) | 그 그룹에 가입한 카드들 | 영상 중계처럼 여럿에게 같은 것을, 모두는 아니게 |
| 브로드캐스트 | FF:FF:FF:FF:FF:FF | 이 링크의 모두 | 상대의 이름을 모를 때 |

이 PC의 ARP 캐시를 열어 보면 `224.0.0.251`은 `01-00-5E-00-00-FB`에, `239.255.255.250`은 `01-00-5E-7F-FF-FA`에 대응되어 있다. IPv4 멀티캐스트 주소의 아래 23비트를 `01:00:5E` 뒤에 그대로 붙이는 규칙이다. IP 주소의 그룹 번호가 28비트인데 MAC에는 23비트만 들어가므로 IP 그룹 32개가 MAC 주소 하나를 나눠 쓰고, 카드가 걸러 내지 못한 나머지는 IP 층이 다시 거른다. 브로드캐스트 `FF:FF:FF:FF:FF:FF`는 [09](../09-physical-layer-nic)장에서 본 대로 모든 카드가 받아들이는 주소이고, 8절의 ARP와 [04](../04-home-lan-configuration)장의 DHCP Discover가 이것을 쓴다.

{{< callout type="info" >}}
브로드캐스트 프레임은 같은 브로드캐스트 도메인의 모든 카드가 받아 운영체제까지 올린다. 이 PC의 유선 카드가 지금까지 받은 프레임 95만 개 중 1.5%가 브로드캐스트였다. 그중 나를 찾는 것은 극히 일부이고 나머지는 운영체제까지 올라와서야 버려진다. 카드가 걸러 주는 유니캐스트와 달리 브로드캐스트는 CPU가 값을 치른다. 정상이면 이 정도지만, 스위치가 고리로 잘못 연결되어 브로드캐스트가 끝없이 돌면(브로드캐스트 스톰) 모든 기기의 CPU가 그것을 처리하느라 망이 멈춘다. [05](../05-office-lan-configuration)장에서 VLAN으로 도메인을 자른 이유이고, 도메인의 경계는 [15. 데이터가 케이블에서 충돌하지 않는 구조](../15-collision-free-structure)에서 본다.
{{< /callout >}}

## 5. 랜덤화와 스푸핑: 새겨진 주소를 믿을 수 없는 이유

### 로컬 관리 주소

4절의 U/L 비트가 1이면 그 주소는 공장이 새긴 것이 아니라 **소프트웨어가 정한 것**이다. 첫 바이트의 둘째로 낮은 비트가 1이니, 유니캐스트라면 16진수 둘째 자리가 `2`, `6`, `A`, `E` 중 하나다. `02:xx:...`처럼 시작하는 주소를 보면 누군가 정한 주소라고 읽으면 된다. IEEE가 이 비트를 남겨 둔 것은 처음부터 "제조사의 표에 없는 주소"를 쓸 자리가 필요하다고 봤기 때문이고, 그 자리를 가장 크게 쓰는 것이 스마트폰이다.

### MAC 랜덤화

| OS | 도입 | 동작 |
|:---|:-----|:-----|
| iOS, iPadOS | 14부터 | Wi-Fi 이름마다 다른 무작위 주소 |
| Android | 10부터 | 네트워크마다 다른 무작위 주소 |
| Windows | 10부터 | 설정에서 켜면 무작위 주소 |

스마트폰은 Wi-Fi를 찾으려고 끊임없이 "여기 누구 있나"를 전파로 외치고, 그 프레임에는 출발지 MAC이 실린다. 주소가 공장에서 새긴 그대로라면 카페와 지하철과 백화점의 AP가 같은 주소를 기록해 한 사람의 동선을 이을 수 있다. 그래서 요즘 운영체제는 네트워크마다 U/L 비트를 1로 세운 무작위 주소를 만들어 쓴다. 같은 Wi-Fi 안에서는 주소가 유지되니 통신에 문제가 없고, 다른 곳에서는 다른 사람으로 보인다. 프라이버시를 위해 "카드의 이름"이라는 첫째 원리를 일부러 깬 것이다.

{{< callout type="warning" >}}
무작위 주소는 OUI가 없으므로 제조사를 알 수 없고, 네트워크마다 바뀐다. 회사에서 MAC 주소로 접속을 허용하거나(MAC 인증), [04](../04-home-lan-configuration)장처럼 DHCP로 특정 주소를 예약해 두었다면 랜덤화된 기기는 차단되거나 다른 주소를 받는다. 그런 망에서는 기기 쪽에서 그 네트워크에 한해 랜덤화를 끄게 안내해야 한다.
{{< /callout >}}

### MAC 스푸핑

```bash
# Linux에서 주소를 임시로 바꾸기
sudo ip link set dev eth0 down
sudo ip link set dev eth0 address 02:11:22:33:44:55
sudo ip link set dev eth0 up
```

주소는 카드의 ROM에 있지만 운영체제가 프레임을 만들 때 다른 값을 적으면 그만이다. 대부분의 드라이버가 이것을 허용하고, 명령 한 줄이면 된다. 고장 난 장비를 바꾸면서 주소에 묶인 라이선스를 유지하는 정상적인 용도도 있지만, 남의 주소를 흉내 내어 MAC 인증을 넘거나 프레임을 가로채는 데도 쓰인다. 그래서 MAC 주소는 **식별이지 인증이 아니다.** 누구인지 구별하는 데는 쓸 수 있지만 그 사람이 맞는지 보증하지는 못한다. 스위치의 포트 보안은 포트마다 허용할 주소를 정해 두고 다른 주소가 나타나면 포트를 막는 대응이고, 그 동작은 [14. 스위치의 구조](../14-switch-structure)에서 본다.

## 6. 프레임 안의 자리

```
┌─────┬─────┬──┬──────┬───┐
│ DST │ SRC │T │ DATA │FCS│
└─────┴─────┴──┴──────┴───┘
 6B    6B   2B 46-1500 4B
```

MAC 주소는 프레임의 맨 앞 12바이트를 차지한다. 목적지가 먼저인 이유, 타입 필드와 FCS의 뜻은 [12](../12-datalink-layer-ethernet)장에서 봤다. 여기서 하나만 더 보면, 출발지 주소는 답장 말고도 한 곳에서 더 읽힌다. 스위치가 프레임을 받을 때마다 출발지 주소와 들어온 포트를 표에 적어 두는 것인데, 그 표가 스위치가 목적지 포트를 아는 유일한 근거이고 다음 장의 주제다.

## 8. ARP: 위치로 이름을 찾는다

```
1) ARP 요청 (브로드캐스트)
   "192.168.1.3의 MAC 주소는?"

2) ARP 응답 (유니캐스트)
   "192.168.1.3 = 00:23:AE:D9:7A:9C"

3) 캐시에 적어 두고 한동안 재사용
```

1절의 두 주소가 만나는 곳이다. 위층이 넘겨준 패킷에는 목적지 IP 주소(위치)만 있는데, 2층이 프레임을 만들려면 목적지 MAC 주소(이름)가 있어야 한다. 그 번역이 ARP다. 이름을 모르니 브로드캐스트로 "이 IP 주소를 가진 사람 누구?"라고 링크의 모두에게 묻고, 해당하는 기계만 자기 MAC 주소를 유니캐스트로 답한다. 매번 물으면 브로드캐스트가 넘치므로 답을 **캐시**에 적어 두고 한동안 쓴다.

| 상태 | 뜻 | 이 PC의 유선 카드 |
|:-----|:---|:------------------|
| Reachable | 최근에 확인된 항목 | 1개. 기본 게이트웨이 |
| Stale | 시간이 지나 다음에 쓸 때 다시 확인할 항목 | 7개. 같은 망의 이웃들 |
| Unreachable | 물었는데 답이 없던 항목 | 1개 |
| Permanent | 멀티캐스트와 브로드캐스트처럼 계산으로 정해지는 항목 | 5개 |

캐시의 수명은 운영체제마다 다르다. 이 PC의 Windows는 항목을 30초 안팎(무작위로 15~45초) 동안 확인된 상태로 두고, 그 뒤에는 Stale로 바꿔 다음에 쓸 때 다시 묻는다. 인터넷에 흔히 도는 "Windows는 2분, 사용 중이면 10분"은 XP 시절의 값이다. 확인된 항목이 게이트웨이 하나뿐인 것은 이 PC의 통신이 거의 전부 망 밖으로 나가기 때문이다. 물어도 답이 없으면 1초 간격으로 몇 번 더 묻고 Unreachable로 남기는데, 꺼진 기기나 빈 주소에 보낸 흔적이다. 캐시가 있어서 생기는 문제도 있다. 어떤 기기의 카드를 바꾸면 IP는 같은데 MAC이 달라지고, 다른 기기의 캐시가 옛 MAC을 기억하는 동안은 통신이 끊긴다. 그래서 IP 주소를 받거나 바꾼 기기는 묻지 않아도 "내 주소는 이것"이라고 먼저 외치기도 한다(무상 ARP).

목적지가 다른 망에 있으면 ARP는 상대의 MAC이 아니라 **기본 게이트웨이의 MAC**을 찾는다. 이름은 링크 안에서만 통하므로 링크 밖의 이름은 알 필요도, 알 방법도 없다. 라우터가 다음 망에서 다시 ARP를 한다. ARP의 자세한 동작과 도메인의 경계는 [15](../15-collision-free-structure)장에서, IP 주소 쪽의 사정은 [18. IP 주소의 구조](../18-ip-address-structure)에서 본다.

```bash
arp -a               # Windows, macOS
ip neigh show        # Linux
```

## 핵심 정리

| 개념 | 핵심 | 왜 |
|:-----|:-----|:---|
| 이름과 위치 | MAC은 이름, IP는 위치 | 2층은 옆 기계에게, 3층은 세계에게 |
| 48비트 | OUI 24 + 일련번호 24 | 두 단계 위임으로 유일성을 보장한다 |
| 가상 카드의 OUI | Hyper-V는 00:15:5D | 같은 링크에서 이름이 겹치면 안 된다 |
| 표기 | 콜론, 하이픈, 점 | 표준은 비트만 정했다 |
| I/G 비트 | 첫 바이트의 가장 낮은 비트 | 프레임의 첫 비트. 카드가 한 비트로 그룹 여부를 안다 |
| U/L 비트 | 둘째로 낮은 비트 | 소프트웨어가 정한 주소를 표시한다. 둘째 자리가 2, 6, A, E |
| 멀티캐스트 MAC | 01:00:5E + IP의 아래 23비트 | 카드가 대부분을 거르고 나머지는 IP 층이 거른다 |
| 브로드캐스트 | FF:FF:FF:FF:FF:FF | 상대의 이름을 모를 때. 받은 프레임의 1.5% |
| 랜덤화 | 네트워크마다 무작위 로컬 주소 | 새겨진 이름은 동선이 된다 |
| 스푸핑 | 명령 한 줄로 바뀐다 | MAC은 식별이지 인증이 아니다 |
| 프레임 안의 자리 | 맨 앞 12바이트, FCS는 맨 뒤 | 목적지를 가장 먼저 읽는다. 12장 |
| ARP | 위치로 이름을 묻는다 | 프레임에는 이름이 필요한데 패킷에는 위치뿐이다 |
| ARP 캐시 | Windows는 30초 안팎 | 매번 브로드캐스트하면 망이 시끄럽다 |
| 다른 망이면 | 게이트웨이의 MAC | 이름은 링크 안에서만 통한다 |

{{< callout type="info" >}}
**용어 정리**
- **MAC 주소**: 카드에 새겨진 48비트 이름. 같은 링크 안에서 기계를 가리킨다
- **OUI**: 앞 24비트. IEEE가 제조사에게 파는 번호
- **I/G 비트 / U/L 비트**: 한 대인가 그룹인가 / 공장이 새겼나 소프트웨어가 정했나를 나타내는 첫 바이트의 낮은 두 비트
- **유니캐스트 / 멀티캐스트 / 브로드캐스트**: 한 대에게 / 가입한 그룹에게 / 링크의 모두에게
- **로컬 관리 주소 (LAA)**: U/L 비트가 1인, 소프트웨어가 정한 주소
- **MAC 랜덤화 / 스푸핑**: 추적을 막으려고 주소를 바꾸는 것 / 다른 주소를 흉내 내는 것
- **FCS**: 프레임 끝의 CRC-32 오류 검출 값. 12장 참고
- **ARP**: IP 주소로 MAC 주소를 브로드캐스트로 묻는 규칙. 답은 캐시에 둔다
- **무상 ARP**: 묻지 않았는데 자기 주소를 먼저 알리는 ARP
{{< /callout >}}
