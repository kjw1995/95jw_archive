[01. 네트워크의 구조](../01-network-basics)에서 회선 속도를 바이트가 아니라 비트로 적는다고 했다. 이 장은 그 비트가 무엇이고, 비트가 어떻게 글자와 주소와 신호가 되는지를 본다. 원리는 셋이다. 첫째, **모든 데이터는 결국 비트이고, 비트는 전선 위의 신호다.** 네트워크가 비트 단위로 말하는 이유가 여기 있다. 둘째, **같은 비트열도 규칙이 있어야 뜻이 된다.** `01000001`은 규칙에 따라 65이기도, `A`이기도, IP 주소의 한 조각이기도 하다. 진법과 문자 인코딩은 그 규칙이고, 한글이 깨지는 모든 경우가 이 규칙의 불일치다. 셋째, **비트 연산은 네트워크의 기본 도구다.** 서브넷 마스크는 AND이고 브로드캐스트 주소는 OR이며, TCP의 플래그는 비트 하나씩이다. 이 장의 값들은 JDK 25로 실제 바이트를 찍어 확인했다.

## 1. 디지털: 왜 0과 1인가

| 구분 | 특징 | 예 |
|:-----|:-----|:---|
| 아날로그 | 연속적인 파형. 값이 무한히 많다 | 목소리, 온도, 옛 전화선의 신호 |
| 디지털 | 불연속. 정해진 몇 가지 상태만 | 컴퓨터의 모든 데이터 |

자연의 정보는 연속적이다. 목소리는 파형이고 온도는 실수다. 컴퓨터는 그것을 **정해진 몇 가지 상태**로 바꿔 다루는데, 그 상태를 둘로 잡은 것이 2진 디지털이다. 왜 둘인가. 전선 위의 신호는 지나오는 동안 잡음이 섞여 흐트러진다. 상태가 열 가지면 흐트러진 신호가 어느 상태였는지 헷갈리지만, 둘뿐이면 "높은가 낮은가"만 가리면 되므로 웬만한 잡음에도 원래 값을 되살릴 수 있다. 복사를 거듭해도 열화되지 않는 것이 디지털의 힘이고, 그 힘은 상태가 둘이라는 단순함에서 온다. 아날로그 신호를 디지털로 바꾸고 되돌리는 과정은 [09. 물리 계층의 역할과 랜 카드의 구조](../09-physical-layer-nic)에서 본다.

## 2. 비트와 바이트

### 비트: 정보의 최소 단위

```
┌───────────────┐
│    1 bit      │
│  ┌─┐    ┌─┐   │
│  │0│ or │1│   │
│  └─┘    └─┘   │
│  OFF    ON    │
└───────────────┘
```

비트(bit)는 binary digit의 줄임말로, 0 아니면 1인 자리 하나다. 비트 하나로는 두 가지를 구별할 수 있고, 비트를 하나 더하면 경우의 수가 두 배가 된다.

| 비트 수 | 경우의 수 | 무엇을 셀 수 있나 |
|:--------|----------:|:------------------|
| 1 | 2 | 켜짐과 꺼짐 |
| 4 | 16 | 16진수 한 자리 |
| 8 | 256 | 바이트 하나. 영문자와 기호 전부 |
| 16 | 65,536 | 포트 번호, 유니코드 기본 평면 |
| 32 | 약 43억 | IPv4 주소 |
| 48 | 약 281조 | MAC 주소 |

n비트로 2ⁿ가지를 표현한다. 뒤의 장들에 나오는 숫자가 전부 이 표에서 나온다. 포트 번호가 0부터 65,535까지인 것은 16비트이기 때문이고, IPv4 주소가 약 43억 개뿐이라 모자라게 된 것은 32비트이기 때문이며([18. IP 주소의 구조](../18-ip-address-structure)), MAC 주소가 48비트인 것은 세상의 모든 랜 카드에 다른 번호를 주고도 남게 하려는 것이다([13. MAC 주소의 구조](../13-mac-address-structure)).

### 바이트: 왜 8비트인가

```
┌───┬───┬───┬───┬───┬───┬───┬───┐
│ 0 │ 1 │ 0 │ 0 │ 0 │ 0 │ 0 │ 1 │
└───┴───┴───┴───┴───┴───┴───┴───┘
 MSB                         LSB
  = 65 (10진)  = 'A' (ASCII)
```

비트 8개를 묶은 것이 바이트다. 처음부터 8이었던 것은 아니다. 초기 컴퓨터는 6비트나 7비트를 한 묶음으로 쓰기도 했고, 1960년대 IBM의 System/360이 8비트를 택하면서 굳어졌다. 8은 영문자 하나를 담는 7비트에 여유 한 비트를 더한 크기이고, 16진수 두 자리로 딱 떨어지며, 2의 거듭제곱이라 주소 계산이 편하다. 크기가 제각각이던 시절의 흔적이 네트워크 문서에 남아 있다. 표준 문서(RFC)는 byte 대신 **옥텟**(octet, 8개짜리)이라고 적어 크기를 못박는다. [18. IP 주소의 구조](../18-ip-address-structure)에서 IPv4 주소를 옥텟 넷이라 부르는 것이 그 말이다.

바이트 안의 여덟 자리에는 순서가 있다. 가장 큰 자리(맨 왼쪽)가 MSB, 가장 작은 자리가 LSB이고, 위의 `01000001`은 64 + 1 = 65다. 이 65가 `A`인 것은 4절의 약속이다.

### 단위: 1,024인가 1,000인가

| 단위 | 크기 | 쓰는 곳 |
|:-----|:-----|:--------|
| 1 B | 8 bit | |
| 1 KiB, MiB, GiB | 1,024배씩 | 메모리, 운영체제의 파일 크기 |
| 1 KB, MB, GB | 1,000배씩 | 저장 장치 제조사, 네트워크 |
| 1 Kbps, Mbps, Gbps | 초당 1,000배씩의 **비트** | 회선 속도 |

같은 K가 두 뜻으로 쓰인다. 메모리와 운영체제는 2진 세계라 1,024를 K로 부르고, 저장 장치 제조사와 네트워크는 10진 1,000을 쓴다. 500GB로 파는 디스크를 Windows가 465GB로 보여 주는 이유가 이것이고, 정확히 적으면 465GiB다. 네트워크는 여기에 하나를 더 얹는다. 회선 속도는 바이트가 아니라 **비트**다. 1장에서 본 1Gbps는 초당 10억 비트, 즉 125MB다. 선 위를 흐르는 것은 바이트 덩어리가 아니라 비트 하나하나의 신호(5절)이기 때문에 물리 계층의 속도는 비트로 세는 것이 자연스럽다.

## 3. 진법: 사람을 위한 표기

| 10진 | 2진 | 16진 |
|-----:|----:|-----:|
| 0 | 0000 | 0x0 |
| 10 | 1010 | 0xA |
| 15 | 1111 | 0xF |
| 16 | 10000 | 0x10 |
| 45 | 101101 | 0x2D |
| 255 | 11111111 | 0xFF |

```
비트:   1  0  1  1  0  1
가중치: 32 16  8  4  2  1
값:    32 + 0 + 8 + 4 + 0 + 1 = 45
```

컴퓨터 안은 2진수뿐이다. 10진과 16진은 사람이 읽기 위한 표기이고, 값은 같다. 2진에서 10진으로 가려면 자리마다 가중치(1, 2, 4, 8, ...)를 곱해 더하면 된다. 16진이 네트워크에서 특히 자주 쓰이는 이유는 **16진 한 자리가 정확히 4비트**이기 때문이다. 바이트 하나는 16진 두 자리이고, 2진과 16진 사이의 변환은 계산이 아니라 4비트씩 끊어 읽는 것이다.

| 16진 | 2진 | 비고 |
|:-----|:----|:-----|
| 0xA | 1010 | |
| 0xF | 1111 | 한 자리의 최대 |
| 0x2A | 0010 1010 | 두 자리 = 한 바이트 |
| 0xFF | 1111 1111 | 한 바이트의 최대, 255 |

그래서 MAC 주소는 `B4-2E-99-F4-7E-E3`처럼 바이트마다 16진 두 자리로 적고, 패킷을 뜯어 보는 도구도 바이트를 16진으로 보여 준다. 반면 IP 주소 `192.168.10.100`은 옥텟마다 10진이다. 16진으로 적으면 `C0.A8.0A.64`이고 2진으로는 `11000000.10101000.00001010.01100100`인데, 6절에서 이 2진 표기가 필요해진다.

## 4. 문자 인코딩: 숫자에 글자를 붙이는 약속

### ASCII: 7비트의 출발점

| 문자 | 10진 | 2진 |
|:-----|-----:|:----|
| `A` | 65 | 01000001 |
| `a` | 97 | 01100001 |
| `0` | 48 | 00110000 |
| 공백 | 32 | 00100000 |

컴퓨터는 숫자만 다루므로 글자는 **숫자에 이름을 붙인 약속**이다. 1963년의 ASCII는 7비트로 128개의 영문자, 숫자, 기호, 제어 문자를 정했다. 표를 보면 설계의 흔적이 보인다. `A`와 `a`는 정확히 32, 즉 **비트 하나**만 다르다. 비트 하나를 켜고 끄는 것으로 대소문자를 바꿀 수 있게 배치한 것이다. 숫자 `0`이 48인 것도 아래 4비트가 `0000`이라 값과 글자를 오가기 쉽게 한 배치다.

### 각국의 확장과 한글

ASCII는 7비트라 바이트의 여덟째 비트가 남았고, 각 나라가 그 나머지 128칸을 자기 글자로 채웠다. 한글은 128칸에 들어가지 않는다. 그래서 바이트 두 개를 묶어 한 글자로 쓰는 EUC-KR이 나왔는데, 흔히 쓰는 완성된 글자 2,350개만 담았다. `가`는 `B0 A1`, `한글`은 `C7 D1 B1 DB`다. 문제는 2,350개에 없는 글자였다. `뷁`을 EUC-KR로 바꾸면 못 바꿔서 `?`(`3F`)가 되고, Microsoft가 나머지 8,822자를 덧붙인 CP949(MS949)로 바꾸면 `94 EE`가 된다. 같은 "한글 인코딩"인데 같은 글자가 한쪽에서는 물음표가 되는 것이다. 나라마다, 회사마다 표가 다르니 한 문서에 여러 언어를 섞을 수도 없었다.

### 유니코드와 UTF-8

유니코드는 이 혼란을 **번호는 하나, 적는 법은 여럿**으로 정리했다. 세상의 모든 글자에 번호 하나씩을 매기고(`가`는 U+AC00, `😀`는 U+1F600), 그 번호를 바이트로 적는 방법을 따로 정했다. 적는 방법이 UTF-8, UTF-16, UTF-32다.

| 인코딩 | 길이 | 특징 | 어디서 |
|:-------|:-----|:-----|:-------|
| ASCII | 7비트 | 영문 128자 | 모든 인코딩의 바닥 |
| EUC-KR | 2바이트 | 완성형 한글 2,350자 | 옛 한국 시스템 |
| CP949 | 2바이트 | EUC-KR + 8,822자 | Windows 한국어 |
| UTF-8 | 1~4바이트 가변 | 유니코드. ASCII와 호환 | 웹, 리눅스, 파일 |
| UTF-16 | 2 또는 4바이트 | 유니코드. 기본 평면은 2바이트 | JVM과 Windows 내부 |

| 번호 범위 | 바이트 | 예 | 바이트 값 |
|:----------|-------:|:---|:----------|
| U+0000 ~ U+007F | 1 | `A` | `41` |
| U+0080 ~ U+07FF | 2 | `ñ` | `C3 B1` |
| U+0800 ~ U+FFFF | 3 | `가` | `EA B0 80` |
| U+10000 ~ U+10FFFF | 4 | `😀` | `F0 9F 98 80` |

```
1바이트  0xxxxxxx
2바이트  110xxxxx 10xxxxxx
3바이트  1110xxxx 10xxxxxx 10xxxxxx
4바이트  11110xxx 10xxxxxx ×3
```

UTF-8이 웹의 표준이 된 이유는 설계에 있다. 첫째, **ASCII 문서는 그대로 UTF-8 문서다.** 영문은 1바이트에 옛 값 그대로 적히므로 기존 파일과 프로그램을 바꾸지 않아도 됐다. 둘째, **바이트만 보고 글자의 경계를 안다.** 첫 바이트는 `110`, `1110`, `11110`으로 시작해 몇 바이트짜리인지 말하고, 이어지는 바이트는 항상 `10`으로 시작한다. 스트림 중간부터 읽어도 다음 글자의 시작을 찾을 수 있고, 한 바이트가 깨져도 그 글자 하나만 잃는다. 1장에서 오류를 국소화하려고 패킷을 나눴다고 했는데 같은 발상이다. 셋째, **바이트 순서 문제가 없다.** UTF-16은 `가`를 `AC 00`으로 적을지 `00 AC`로 적을지가 기계마다 달라 순서 표시(BOM)가 필요하지만 UTF-8은 한 바이트씩이라 그런 것이 없다. 대가는 한글이 3바이트라는 것인데, 웹에서는 영문 태그와 코드가 대부분이라 손해보다 이득이 크다.

UTF-16은 JVM과 Windows가 안에서 쓴다. 자주 쓰는 글자는 2바이트로 고정이라 다루기 편하지만, U+FFFF를 넘는 `😀` 같은 글자는 2바이트 둘을 이어 4바이트로 적는다. 자바의 `"😀".length()`가 2인 이유이고, 자바가 문자를 안에서 어떻게 담는지는 자바 기초 시리즈의 [Chapter 02](../../java/basics/02-java-variable)에, 파일과 소켓에서 인코딩이 어긋나면 어떻게 깨지는지는 [Chapter 15](../../java/basics/15-io)에 있다. 한글이 깨지는 모든 경우의 원인은 하나다. **적은 규칙과 읽는 규칙이 다르다.**

## 5. 비트에서 신호로

```
     송신                    수신
  ┌────────┐             ┌────────┐
  │  'Hi'  │             │  'Hi'  │
  └───┬────┘             └───▲────┘
      ▼                      │
  01001000                01001000
  01101001                01101001
      ▼                      │
   ▁█▁▁█▁▁▁  ═══ 전송 ═══  ▁█▁▁█▁▁▁
```

`Hi`를 보내면 4절의 약속대로 `48 69`, 2진으로 `01001000 01101001`이 되고, 그 비트가 전선 위에서 높은 전압과 낮은 전압의 열이 된다. 비트를 신호로 바꾸고 되돌리는 장치가 랜 카드이고([09](../09-physical-layer-nic)장), 신호가 무엇을 타고 가느냐가 전송 매체다.

| 매체 | 신호 | 특징 |
|:-----|:-----|:-----|
| UTP 케이블 | 전압의 높낮이 | 값싸고 흔하다. 100m를 넘으면 신호가 약해진다 |
| 광케이블 | 빛의 켜짐과 꺼짐 | 빠르고 멀리 간다. 전기 간섭이 없다 |
| Wi-Fi | 전파 | 선이 없다. 벽과 다른 전파에 간섭받는다 |

케이블의 종류는 [10. 케이블의 종류와 구조](../10-cable-types-structure)에서, 전파로 보내는 무선 랜은 [35. 무선 랜의 구조](../35-wireless-lan-structure)에서 본다. 신호는 가는 동안 잡음을 만나고, 1절에서 본 대로 대개는 되살아나지만 가끔 비트가 뒤집힌다. 그것을 받는 쪽이 알아채는 장치가 1장에서 본 트레일러의 오류 검출 코드이고, 이더넷 프레임 끝의 FCS가 그것이다([13](../13-mac-address-structure)장).

## 6. 비트 연산: 네트워크의 기본 도구

| 연산 | 기호 | 뜻 | 예 (4비트) |
|:-----|:-----|:---|:-----------|
| AND | `&` | 둘 다 1이면 1 | 1010 & 1100 = 1000 |
| OR | `\|` | 하나라도 1이면 1 | 1010 \| 1100 = 1110 |
| XOR | `^` | 서로 다르면 1 | 1010 ^ 1100 = 0110 |
| NOT | `~` | 뒤집는다 | ~1010 = 0101 |
| 왼쪽 시프트 | `<<` | 2ⁿ배 | 1010 << 2 = 101000 (10 → 40) |
| 오른쪽 시프트 | `>>` | 2ⁿ으로 나눔 | 101000 >> 2 = 1010 (40 → 10) |

비트 연산은 자리마다 따로 계산한다. 자바에서의 문법과 부호 처리는 자바 기초 시리즈 [Chapter 03](../../java/basics/03-java-operator)의 비트 연산자 절에 있고, 여기서 볼 것은 네트워크가 이것을 어디에 쓰는가다.

```
IP   11000000.10101000.00001010.01100100
MASK 11111111.11111111.11111111.00000000
AND  11000000.10101000.00001010.00000000
     = 192.168.10.0  (네트워크 주소)
```

IP 주소 `192.168.10.100`에 서브넷 마스크 `255.255.255.0`을 AND하면 `192.168.10.0`이 나온다. 마스크의 1인 자리는 IP 주소의 비트를 그대로 남기고 0인 자리는 지우므로, 결과는 "어느 네트워크인가"만 남긴 네트워크 주소다. 두 주소를 같은 마스크로 AND해서 값이 같으면 같은 네트워크이고, 그것이 라우터가 패킷을 안으로 보낼지 밖으로 보낼지 정하는 방법이다. 반대로 마스크를 NOT한 뒤 OR하면 호스트 자리가 전부 1인 `192.168.10.255`, 즉 브로드캐스트 주소가 된다. [20. 네트워크 주소와 브로드캐스트 주소의 구조](../20-network-broadcast-address)와 [21. 서브넷의 구조와 서브넷팅](../21-subnet-structure)이 이 계산의 장이다.

플래그도 비트다. [24. TCP의 구조](../24-tcp-structure)에서 볼 TCP 헤더에는 SYN, ACK, FIN 같은 제어 비트가 한 자리씩 있고, "SYN과 ACK가 함께 켜진 패킷"은 그 두 비트가 1인 바이트다. 헤더의 필드를 읽고 쓰는 일이 전부 시프트와 마스크이고, 2장에서 2진 표기를 굳이 익히는 이유가 여기 있다.

## 핵심 정리

| 개념 | 핵심 | 왜 |
|:-----|:-----|:---|
| 디지털 | 상태가 둘뿐이다 | 잡음 속에서도 높은가 낮은가는 가릴 수 있다 |
| 비트 | 0 아니면 1. n비트는 2ⁿ가지 | 포트 65,536개, IPv4 43억 개가 여기서 나온다 |
| 바이트 | 8비트. 문서는 옥텟이라 부른다 | 크기가 제각각이던 시절이 있어 못박는다 |
| 1,024와 1,000 | KiB는 1,024, KB와 Kbps는 1,000 | 2진 세계와 10진 세계의 K가 다르다 |
| bps | 회선 속도는 비트 | 선 위를 흐르는 것이 비트의 신호다. 1Gbps는 125MB/s |
| 16진 | 한 자리가 4비트, 두 자리가 한 바이트 | MAC 주소와 패킷 덤프의 표기 |
| ASCII | 7비트 128자 | `A`와 `a`는 비트 하나 차이 |
| EUC-KR과 CP949 | 2바이트 한글, 2,350자와 11,172자 | 완성형에 없는 글자는 `?`가 된다 |
| 유니코드 | 번호는 하나, 적는 법은 여럿 | UTF-8, UTF-16은 같은 번호를 다르게 적는다 |
| UTF-8 | 1~4바이트 가변 | ASCII 호환, 글자 경계 자기 표시, 바이트 순서 무관 |
| 한글 깨짐 | 적은 규칙과 읽는 규칙이 다르다 | 원인은 언제나 이 하나 |
| 신호 | 비트를 전압, 빛, 전파로 | 랜 카드가 바꾸고 매체가 나른다 |
| AND, OR | 서브넷 마스크, 브로드캐스트 | 네트워크 부분만 남기거나 호스트 부분을 채운다 |
| 플래그 | 헤더의 비트 하나 | SYN, ACK, FIN은 각각 한 자리 |

{{< callout type="info" >}}
**용어 정리**
- **bit**: binary digit. 0 또는 1인 자리 하나. 정보의 최소 단위
- **Byte / 옥텟**: 8비트. 네트워크 표준 문서는 크기를 못박으려고 옥텟이라 쓴다
- **MSB / LSB**: 가장 큰 자리 비트(맨 왼쪽) / 가장 작은 자리 비트(맨 오른쪽)
- **KiB / KB**: 1,024바이트 / 1,000바이트. 메모리는 앞을, 디스크와 네트워크는 뒤를 쓴다
- **인코딩**: 글자에 매긴 번호를 바이트로 적는 규칙. 유니코드는 번호, UTF-8은 적는 법
- **ASCII**: 1963년의 7비트 문자 코드 128자. 모든 인코딩의 바닥
- **UTF-8**: 1~4바이트 가변 길이의 유니코드 인코딩. 웹과 파일의 표준
- **서브넷 마스크**: IP 주소와 AND해서 네트워크 주소를 얻는 비트열
