네트워크 시리즈의 첫 장이다. 패킷, 대역폭, 프로토콜처럼 뒤에서 계속 쓰일 말들을 여기서 처음 만나는데, 용어를 외우기보다 **왜 그렇게 만들어졌는지**를 붙잡으면 뒤의 서른다섯 장이 전부 이 장의 결과가 된다. 원리는 셋이다. 첫째, **네트워크는 회선을 나눠 쓰는 기술이다.** 데이터를 패킷으로 잘게 나누는 이유, 패킷에 헤더가 붙는 이유, 순서가 뒤바뀌는 이유가 전부 "나눠 쓴다"에서 나온다. 둘째, **속도는 하나가 아니다.** 대역폭, 처리량, 지연은 서로 다른 것이고, 회선이 1Gbps인데 파일이 느린 이유와 핑이 250ms인 이유는 다른 곳에 있다. 셋째, **규칙이 있어야 대화가 된다.** 프로토콜이 그 규칙이고, 규칙을 층으로 나눈 것이 이 시리즈의 뼈대인 OSI 모델이다. 이 장의 수치는 필자의 PC(1Gbps 유선, Windows)에서 `ping`과 `tracert`로 잰 것이다.

---

## 1. 네트워크: 회선을 나눠 쓰는 기술

### 두 대 이상이 연결되면

컴퓨터 두 대를 선으로 이으면 네트워크다. 파일을 나누고 프린터를 함께 쓰는 사무실의 망부터 전 세계를 잇는 인터넷까지 규모만 다를 뿐 같은 원리로 동작한다. 연결의 목적은 언제나 **공유**다. 데이터, 장비, 회선을 여럿이 나눠 쓰는 것이고, 이 장의 개념 대부분은 "어떻게 하면 공평하고 효율적으로 나눠 쓸 수 있는가"에 대한 답이다.

```text
┌────────────────────────────┐
│      인터넷 (Internet)     │
│  ┌──────────────────────┐  │
│  │   WAN (광역 통신망)  │  │
│  │  ┌────────────────┐  │  │
│  │  │ LAN (근거리)   │  │  │
│  │  │ ┌────────────┐ │  │  │
│  │  │ │ PAN (개인) │ │  │  │
│  │  │ └────────────┘ │  │  │
│  │  └────────────────┘  │  │
│  └──────────────────────┘  │
└────────────────────────────┘
```

| 네트워크 | 범위 | 예 | 누가 관리하나 |
|:---------|:-----|:---|:--------------|
| PAN | 개인 주변 수 m | 블루투스 이어폰, 스마트워치 | 본인 |
| LAN | 건물, 사무실 | 회사 내부망, 집의 공유기 아래 | 그 조직 |
| MAN | 도시 | 도시 통신망, 캠퍼스 간 연결 | 지역 사업자 |
| WAN | 국가, 대륙 | 통신사의 망 | 통신사 |
| 인터넷 | 전 세계 | WWW | 아무도, 그리고 모두 |

범위로 나누는 기준은 거리보다 **누가 회선을 갖고 관리하느냐**다. LAN은 내 조직이 깔고 관리하는 망이라 빠르고 마음대로 바꿀 수 있지만, 건물을 벗어나면 남의 회선을 빌려야 한다. 그것이 통신사의 WAN이고, WAN들이 서로 이어진 것이 인터넷이다. 인터넷에는 주인이 없다. 수많은 망이 각자 규칙(5절)만 지키며 이어져 있을 뿐이고, 그래서 어느 한 곳이 멈춰도 전체는 살아 있다. LAN과 WAN의 차이는 [03. LAN과 WAN](../03-lan-and-wan)에서, 집과 회사의 LAN이 실제로 어떻게 구성되는지는 [04](../04-home-lan-configuration)장과 [05](../05-office-lan-configuration)장에서 본다.

### 인터넷, 인트라넷, 엑스트라넷

| 구분 | 무엇인가 | 누가 들어오나 |
|:-----|:---------|:-------------|
| 인터넷 | 전 세계의 망을 이은 개방망 | 누구나 |
| 인트라넷 | 조직 내부 전용의 폐쇄망 | 내부 사용자 |
| 엑스트라넷 | 인트라넷을 협력사까지 연 것 | 허가된 파트너 |

셋은 기술이 다른 것이 아니다. 인트라넷은 인터넷과 **같은 TCP/IP 기술**을 쓰면서 방화벽과 VPN으로 바깥과 잘라 낸 망이다. 사내 포털이나 그룹웨어가 회사 밖에서는 열리지 않는 이유가 이것이고, 재택근무 때 VPN을 켜야 열리는 것은 VPN이 바깥의 PC를 잠시 인트라넷 안으로 들여보내기 때문이다. 기술이 같으니 구분의 기준은 하나, **누구에게 문을 여는가**다.

## 2. 패킷: 왜 잘게 나누어 보내는가

### 회선 교환에서 패킷 교환으로

```
회선 교환      A ══════════ B  (독점)
               C ─ ─ 대기 ─ ─ D

패킷 교환      A ─[1]─[3]─── B
               C ─[2]─[4]─── D
  한 회선을 여럿이 번갈아 쓴다
```

전화망은 통화가 시작될 때 두 사람 사이에 전용 회선을 잡고 끊을 때까지 독점한다. 이것이 **회선 교환**이다. 통화 중에는 품질이 일정하지만, 말을 하지 않는 순간에도 회선은 잡혀 있고 다른 사람은 그 회선을 쓸 수 없다. 컴퓨터 통신은 이 방식과 맞지 않는다. 컴퓨터는 한꺼번에 왕창 보내고 한참 쉬는 식으로 통신해서, 회선을 독점시키면 대부분의 시간이 낭비된다.

1960년대에 폴 배런과 도널드 데이비스가 따로 같은 답에 이르렀다. 데이터를 작은 조각으로 나누고, 각 조각에 주소를 붙여 회선에 섞어 보내며, 받는 쪽이 다시 맞추는 **패킷 교환**이다. 조각을 뜻하는 packet이라는 이름도 이때 붙었고, 1969년의 ARPANET이 이 방식으로 만들어진 첫 망이자 인터넷의 조상이다.

| 구분 | 회선 교환 | 패킷 교환 |
|:-----|:----------|:----------|
| 연결 | 통신 전에 전용 회선을 잡는다 | 잡지 않는다. 패킷마다 경로를 고른다 |
| 회선 | 통화 동안 독점 | 여러 통신이 섞여 쓴다 |
| 품질 | 일정하다 | 붐비면 지연되고 잃을 수 있다 |
| 효율 | 쉬는 동안도 낭비 | 쉬는 틈을 남이 쓴다 |
| 예 | 전통 전화망(PSTN) | 인터넷 |

패킷으로 나누면 얻는 것이 셋이다. **공평하게 나눠 쓴다.** 큰 파일 하나가 회선을 독점하지 않고, 다른 사람의 작은 패킷이 그 사이에 끼어든다. **오류가 국소화된다.** 전송 중에 일부가 깨져도 깨진 조각만 다시 보내면 되고, 파일 전체를 다시 보낼 필요가 없다. **길이 막히면 돌아간다.** 패킷마다 경로를 고르므로 중간의 회선이나 장비가 죽어도 다른 길로 간다. 배런이 핵 공격에도 살아남는 통신망을 연구하다 이 방식에 이른 것은 우연이 아니다. 음성 통화조차 지금은 대부분 VoIP, 즉 패킷 교환 위에서 돈다.

### 패킷의 구조: 주소가 붙어야 섞을 수 있다

```
┌──────┬──────────┬────────┐
│ 헤더 │  데이터  │ 트레일러│
└──────┴──────────┴────────┘
  주소     본문     오류검출
  순번
```

| 영역 | 담는 것 | 왜 필요한가 |
|:-----|:--------|:-----------|
| 헤더 | 출발지와 목적지 주소, 순서 번호, 어떤 프로토콜인지 | 회선에 섞어 보내려면 조각마다 누구 것인지 적혀 있어야 한다 |
| 페이로드 | 실제 데이터 | |
| 트레일러 | 오류 검출 코드(CRC) | 전선을 지나며 비트가 깨졌는지 받는 쪽이 확인한다 |

회선 교환에서는 회선 자체가 "이 신호는 A와 B의 것"임을 말해 주지만, 패킷 교환에서는 한 회선에 여러 사람의 조각이 섞여 흐르므로 **조각마다 봉투**가 필요하다. 그것이 헤더다. 봉투에는 받는 주소만이 아니라 보내는 주소(답장하려면), 순서 번호(다시 맞추려면), 안의 내용이 어떤 규칙을 따르는지(열어 보려면)가 적힌다. 봉투가 클수록 정작 실어 나르는 데이터의 비율은 줄어드는데, 3절에서 처리량이 대역폭에 못 미치는 이유 중 하나가 이것이다. 뒤에서 보듯 실제 패킷에는 봉투가 한 겹이 아니라 계층마다 한 겹씩 붙는다([08. 캡슐화와 역캡슐화](../08-encapsulation-decapsulation)). 트레일러는 데이터 링크 계층의 프레임에 붙는 것으로, [12. 데이터 링크 계층의 역할과 이더넷](../12-datalink-layer-ethernet)에서 실제 모습을 본다.

패킷 하나의 크기에는 한도가 있다. 이더넷에서는 1,500바이트이고, 이 PC의 네트워크 어댑터 설정에도 MTU 1500이라고 적혀 있다. 왜 무한히 크게 만들지 않을까. 패킷이 크면 한 사람의 패킷이 회선을 오래 붙잡아 공평함이 깨지고, 깨졌을 때 다시 보낼 양도 커지며, 중간 장비가 잠시 담아 둘 메모리도 커진다. 1,500이라는 숫자는 1980년대 이더넷의 절충이고, 지금까지 남아 있다.

### 순서가 뒤바뀌는 이유

```
송신측            수신측
 ┌─┐┌─┐┌─┐       ┌─┐┌─┐┌─┐
 │1││2││3│  ──▶  │2││3││1│
 └─┘└─┘└─┘       └─┘└─┘└─┘
                    │
                    ▼
               순서 번호로
                 재조립
```

패킷마다 경로를 고른다는 것은 같은 파일의 조각들이 **다른 길**로 갈 수 있다는 뜻이다. 1번이 막힌 길로 가고 2번이 빈 길로 가면 2번이 먼저 도착한다. 잃어버리는 것도 있다. 붐비는 장비는 담아 둘 자리가 없으면 패킷을 버린다. 그래서 받는 쪽은 헤더의 순서 번호로 다시 줄을 세우고, 빠진 번호가 있으면 다시 보내 달라고 한다. 이 일을 누가 하는가가 [23. 전송 계층의 역할](../23-transport-layer-role)의 주제이고, TCP가 순서 번호로 그것을 해내는 방법이 [25. 일련번호와 확인 응답 번호의 구조](../25-sequence-ack-number)다. 패킷 교환의 대가인 지연, 손실, 순서 뒤바뀜을 응용 프로그램이 못 느끼게 덮어 주는 것이 TCP의 일이다.

## 3. 대역폭, 처리량, 지연: 속도는 하나가 아니다

### 세 가지 속도

| 용어 | 뜻 | 비유 | 단위 |
|:-----|:---|:-----|:-----|
| 대역폭 (bandwidth) | 회선이 낼 수 있는 이론상 최대 전송량 | 도로의 차선 수 | bps |
| 처리량 (throughput) | 실제로 오간 데이터의 양 | 실제 지나간 차의 수 | bps |
| 지연 (latency) | 패킷이 갔다 오는 데 걸리는 시간 | 출발에서 도착까지의 시간 | ms |

"인터넷이 느리다"는 말은 셋 중 무엇이 느린지에 따라 원인도 해법도 다르다. 대역폭은 회선의 폭이다. 이 PC의 유선 어댑터는 1Gbps로 잡혀 있고, 그것이 이 선이 낼 수 있는 상한이다. 처리량은 그 폭 안에서 실제로 흐른 양이다. 상한에 못 미치는 이유는 여럿이다. 2절의 헤더가 자리를 차지하고, 같은 회선을 남과 나눠 쓰고, 잃은 패킷을 다시 보내느라 되돌아가며, 상대 서버가 그만큼 빨리 내주지 못한다. 대역폭은 회선을 바꿔야 늘지만 처리량은 이 중 무엇이 병목인지를 찾아야 는다.

단위는 **초당 비트**(bps)이고 바이트가 아니다. 1Gbps는 초당 10억 비트, 즉 125MB다. 파일 크기는 바이트로 적고 회선 속도는 비트로 적기 때문에 "1Gbps인데 100MB/s밖에 안 나온다"는 말은 사실 회선을 거의 다 쓰고 있다는 뜻이다. 네트워크의 K, M, G는 컴퓨터 메모리와 달리 1,024가 아니라 1,000 단위다. 비트와 바이트, 그리고 이 단위들은 [02. 비트와 바이트](../02-bit-and-byte)에서 이어진다.

| 단위 | 크기 | 예 |
|:-----|:-----|:---|
| bps | 초당 비트 1개 | |
| Kbps | 1,000 bps | 옛 전화 모뎀 56Kbps |
| Mbps | 1,000,000 bps | 가정 인터넷 100Mbps ~ 1Gbps |
| Gbps | 1,000,000,000 bps | 데이터센터 내부 10 ~ 400Gbps |

### 지연: 거리와 경유지의 값

```
서울 ─▶ 핀란드 약 7,000 km
빛(광섬유) 한쪽 방향 ≥ 35 ms
왕복 최소 70 ms, 실측 251 ms
```

| `ping` 대상 | 왕복 시간 | 거리 |
|:------------|----------:|:-----|
| 127.0.0.1 (내 PC) | 0 ms | 회선을 타지 않는다 |
| 8.8.8.8 (구글 DNS) | 38 ms | 가까운 데이터센터, 12개 장비 경유 |
| ftp.funet.fi (핀란드) | 251 ms | 약 7,000 km |

지연은 대역폭과 무관하다. 회선이 아무리 넓어도 패킷이 핀란드까지 갔다 오는 데는 시간이 든다. 광섬유 속의 빛은 초당 약 20만 km를 가므로 7,000km를 한쪽으로 가는 데만 35ms, 왕복은 아무리 잘해도 70ms다. 실측이 251ms인 것은 케이블이 직선으로 깔려 있지 않고, 중간의 라우터마다 패킷을 받아 살펴보고 다음으로 넘기는 시간이 쌓이기 때문이다. `tracert`로 보면 구글 DNS까지 가는 데도 이 PC를 나선 뒤 12개의 장비를 거친다. 그 장비들이 [22. 라우터의 구조와 라우팅](../22-router-structure)의 라우터다.

그래서 큰 파일 하나를 받을 때는 대역폭이 중요하고, 작은 요청을 수백 번 주고받는 웹 페이지에서는 지연이 중요하다. 지연 100ms인 회선에서 요청을 순서대로 100번 하면 대역폭과 상관없이 10초다. 뒤에서 볼 TCP의 연결 수립이 왕복 한 번을 먼저 쓰고, HTTP가 연결을 재사용하려 애쓰는 이유가 여기 있다.

## 4. 네트워크를 이루는 것들

### 장비: 어디까지 읽는가로 나뉜다

| 장비 | 하는 일 | 보는 것 | 계층 |
|:-----|:--------|:--------|:-----|
| NIC (랜 카드) | 컴퓨터를 회선에 잇고 신호를 비트로 | 전기 신호와 비트 | L1 ~ L2 |
| 허브 | 들어온 신호를 모든 포트로 복사 | 신호만 | L1 |
| 스위치 | MAC 주소를 보고 해당 포트로만 전달 | 프레임의 헤더 | L2 |
| 라우터 | IP 주소를 보고 다른 네트워크로 넘긴다 | 패킷의 헤더 | L3 |

장비의 계층은 그 장비가 **패킷의 어디까지 읽는가**다. 허브는 아무것도 읽지 않고 들어온 신호를 모든 구멍으로 되쏜다. 그래서 싸지만 모두가 모두의 데이터를 받고, 둘이 동시에 보내면 신호가 부딪힌다. 스위치는 2절의 봉투에서 받는 MAC 주소를 읽어 그 구멍으로만 보낸다. 라우터는 한 겹 더 안쪽의 IP 주소를 읽어 **다른 네트워크**로 가는 길을 고른다. 1절에서 LAN을 벗어나면 남의 회선이라고 했는데, 그 경계에 서 있는 장비가 라우터다. 각 장비는 [09. 랜 카드](../09-physical-layer-nic), [11. 리피터와 허브](../11-repeater-hub), [14. 스위치](../14-switch-structure), [22. 라우터](../22-router-structure)에서 하나씩 뜯어본다.

### 토폴로지: 왜 스타형이 이겼나

| 토폴로지 | 모양 | 장점 | 단점 |
|:---------|:-----|:-----|:-----|
| 버스형 | 한 케이블에 모두 매달림 | 케이블이 적다 | 케이블 한 곳이 끊기면 전체가 멈춘다. 동시 전송이 부딪힌다 |
| 스타형 | 중앙 장비에 각자 연결 | 한 선이 끊겨도 그 장비만 | 중앙 장비가 죽으면 전체 |
| 링형 | 고리로 연결 | 순서대로 공평하게 | 한 곳이 끊기면 전체 |
| 메시형 | 서로 여러 갈래로 연결 | 길이 여럿이라 튼튼하다 | 비용과 복잡도 |

초기 이더넷은 버스형이었다. 동축 케이블 하나를 사무실에 죽 깔고 컴퓨터를 매다는 방식인데, 케이블 한 곳이 끊기면 전부 멈추고 두 대가 동시에 보내면 신호가 충돌해 둘 다 다시 보내야 했다. 스위치가 값싸지면서 지금의 LAN은 거의 전부 스타형이다. 컴퓨터마다 스위치까지 선 하나씩이라 남의 선이 끊겨도 나는 멀쩡하고, 스위치가 구멍마다 따로 보내 주니 충돌도 사라졌다. 이 이야기는 [15. 데이터가 케이블에서 충돌하지 않는 구조](../15-collision-free-structure)로 이어진다. 메시형은 LAN에서는 비싸서 안 쓰지만 인터넷의 뼈대는 메시형이다. 2절에서 "길이 막히면 돌아간다"가 가능하려면 길이 여럿이어야 하기 때문이다.

## 5. 프로토콜: 규칙이 있어야 대화가 된다

프로토콜은 데이터를 주고받기 위해 **미리 합의한 규칙**이다. 어떤 신호를 1로 볼지, 봉투의 몇 번째 바이트가 주소인지, 받았다는 답은 어떻게 하는지가 전부 규칙이고, 규칙이 같으면 제조사와 운영체제가 달라도 통신할 수 있다. 윈도우 PC가 리눅스 서버와, 아이폰이 안드로이드와 대화하는 것은 같은 규칙을 따르기 때문이지 같은 물건이기 때문이 아니다.

| 프로토콜 | 계층 | 정하는 것 |
|:---------|:-----|:----------|
| HTTP, HTTPS | 응용 | 웹 페이지를 요청하고 받는 형식 |
| DNS | 응용 | 이름을 IP 주소로 바꾸는 문답 |
| TCP | 전송 | 순서와 재전송으로 신뢰를 만드는 법 |
| UDP | 전송 | 봉투만 붙여 빨리 보내는 법 |
| IP | 네트워크 | 주소 체계와 다른 망으로 넘기는 법 |
| 이더넷 | 데이터 링크 | 한 LAN 안에서 프레임을 주고받는 법 |

규칙이 하나가 아니라 여섯 줄이나 되는 이유가 이 시리즈의 뼈대다. 통신에는 여러 종류의 문제가 있다. 전선에 어떤 신호를 실을지, 옆 컴퓨터를 어떻게 부를지, 다른 망으로 어떻게 넘길지, 잃어버린 조각을 어떻게 다시 받을지, 웹 페이지를 어떤 형식으로 요청할지. 이것을 규칙 하나로 정하면 웹 페이지 형식을 바꿀 때 전선의 신호 규칙까지 다시 정해야 한다. 그래서 문제를 **층으로 나누고 층마다 규칙을 따로** 두었다. 한 층은 바로 아래 층이 해 주는 일만 믿고 자기 문제만 푼다. HTTP는 TCP가 순서를 맞춰 준다고 믿고 형식만 신경 쓰며, TCP는 IP가 어디로든 보내 준다고 믿고 순서만 신경 쓴다. 이 층의 이름과 역할이 [07. OSI 모델과 TCP/IP 모델](../07-osi-tcpip-model)이고, 프로토콜이 어떻게 만들어지고 표준이 되는지는 [06. 네트워크의 규칙 - 프로토콜](../06-network-protocol)에서 본다. 자바에서 이 규칙들이 `Socket`과 `HttpClient`로 어떻게 보이는지는 자바 기초 시리즈의 [Chapter 16. 네트워킹](../../java/basics/16-networking)에 있다.

## 핵심 정리

| 개념 | 핵심 | 왜 |
|:-----|:-----|:---|
| 네트워크 | 회선을 나눠 쓰는 기술 | 목적은 공유. 개념 대부분이 공평한 공유의 답이다 |
| 범위 분류 | PAN, LAN, WAN, 인터넷 | 기준은 거리보다 누가 회선을 관리하느냐 |
| 인트라넷 | 같은 기술, 닫힌 문 | 인터넷과 같은 TCP/IP를 방화벽으로 잘라 낸 것 |
| 회선 교환 | 전용 회선을 독점 | 품질은 일정하지만 쉬는 동안도 낭비 |
| 패킷 교환 | 조각에 주소를 붙여 섞어 보낸다 | 공평한 공유, 오류 국소화, 우회 |
| 헤더 | 조각마다 붙는 봉투 | 한 회선에 여럿의 조각이 섞이므로 |
| MTU 1,500 | 패킷 크기의 한도 | 크면 회선 독점, 재전송 비용, 버퍼 부담 |
| 순서 뒤바뀜 | 조각마다 다른 길 | 순서 번호로 재조립. TCP의 일 |
| 대역폭 | 회선의 폭, bps | 비트 단위, 1,000 단위. 1Gbps는 125MB/s |
| 처리량 | 실제 흐른 양 | 헤더, 공유, 재전송, 상대 서버가 깎는다 |
| 지연 | 갔다 오는 시간 | 빛의 속도와 경유 장비. 대역폭과 무관 |
| 장비의 계층 | 어디까지 읽는가 | 허브는 신호만, 스위치는 MAC, 라우터는 IP |
| 스타형 | 지금의 LAN | 한 선의 장애가 격리되고 충돌이 없다 |
| 프로토콜 | 합의한 규칙 | 규칙이 같으면 다른 기계도 대화한다 |
| 계층 | 문제마다 규칙을 따로 | 한 층은 아래 층을 믿고 자기 문제만 푼다 |

{{< callout type="info" >}}
**용어 정리**
- **패킷 (Packet)**: 주소가 적힌 헤더를 붙여 보내는 데이터 조각. 네트워크 계층의 전송 단위
- **회선 교환 / 패킷 교환**: 전용 회선을 독점하는 방식 / 조각을 섞어 보내고 받는 쪽이 맞추는 방식
- **MTU**: 한 번에 보낼 수 있는 패킷의 최대 크기. 이더넷은 1,500바이트
- **대역폭 (Bandwidth)**: 단위 시간당 보낼 수 있는 최대 비트 수
- **처리량 (Throughput)**: 실제로 오간 데이터의 양
- **지연 (Latency)**: 패킷이 상대까지 갔다 오는 시간. `ping`이 재는 것
- **인트라넷 (Intranet)**: 인터넷과 같은 기술로 만든 조직 내부 전용 망
- **프로토콜 (Protocol)**: 통신을 위해 미리 합의한 규칙
