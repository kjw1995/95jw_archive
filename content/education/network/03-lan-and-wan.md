[01. 네트워크의 구조](../01-network-basics)에서 네트워크를 범위로 나누는 기준은 거리보다 **누가 회선을 갖고 관리하느냐**라고 했다. 이 장은 그 두 세계, 내가 깔고 관리하는 LAN과 남의 회선을 빌리는 WAN을 나란히 놓고 본다. 원리는 셋이다. 첫째, **LAN과 WAN을 가르는 것은 소유와 규칙이다.** LAN은 내 것이라 빠르고 마음대로 바꾸며 기술도 이더넷 하나로 통일되어 있지만, WAN은 통신사의 것이라 계약한 만큼만 쓰고 기술도 여럿이다. 둘의 경계에 서 있는 장비가 라우터다. 둘째, **거리가 속도와 오류를 결정한다.** 1장에서 본 지연이 LAN에서는 1ms가 안 되고 WAN에서는 수십에서 수백 ms가 되는 것은 빛의 속도와 경유 장비 때문이지 회선의 품질 때문이 아니다. 셋째, **인터넷은 WAN들의 연합이다.** 주인 없는 인터넷이 어떻게 이어져 있는지가 ISP의 계층이고, 그것이 어디서 시작됐는지가 ARPANET이다. 이 장의 지연 수치는 필자의 PC에서 잰 것이다.

## 1. 범위: 거리가 아니라 소유

```
┌──────────────────────┐
│      인터넷          │
│  ┌────────────────┐  │
│  │      WAN       │  │
│  │  ┌──────────┐  │  │
│  │  │   MAN    │  │  │
│  │  │ ┌──────┐ │  │  │
│  │  │ │ LAN  │ │  │  │
│  │  │ │ ┌──┐ │ │  │  │
│  │  │ │ │P │ │ │  │  │
│  │  │ │ │AN│ │ │  │  │
│  │  │ │ └──┘ │ │  │  │
│  │  │ └──────┘ │  │  │
│  │  └──────────┘  │  │
│  └────────────────┘  │
└──────────────────────┘
```

| 망 | 범위 | 회선의 주인 | 기술 |
|:---|:-----|:-----------|:-----|
| PAN | 내 주변 수 m | 나 | 블루투스, USB |
| LAN | 건물, 캠퍼스 | 그 조직 | 이더넷, Wi-Fi |
| MAN | 도시 | 지역 사업자나 지자체 | 광케이블 |
| WAN | 국가, 대륙 | 통신사(ISP) | 전용선, MPLS, 인터넷 |
| 인터넷 | 전 세계 | 아무도 | 위의 전부 |

교과서는 범위를 거리로 나누지만, 실제로 성질을 가르는 것은 셋째 열이다. 같은 건물 안이라도 통신사 회선으로 이어졌으면 WAN처럼 동작하고, 도시 하나를 덮어도 한 대학이 광케이블을 직접 깔았으면 LAN처럼 동작한다. 회선의 주인이 누구냐에 따라 속도를 누가 정하는지, 장애가 나면 누가 고치는지, 규칙을 누가 바꾸는지가 정해진다.

## 2. LAN: 내가 깔고 관리하는 망

### 구성

```
  PC     PC     PC
  └──────┼──────┘
      ┌──┴───┐
      │스위치│
      └──┬───┘
  ┌──────┼──────┐
 서버   프린터   NAS
```

사무실의 PC, 서버, 프린터, NAS를 스위치 하나에 모으면 LAN이다. 케이블은 조직이 깔고, 스위치도 조직이 사며, 누구를 붙이고 뗄지도 조직이 정한다. 1장에서 본 대로 요즘의 LAN은 거의 전부 스타형이고, 그 중심의 스위치가 프레임을 목적지 포트로만 보내 주기 때문에 여러 대가 동시에 통신해도 부딪히지 않는다.

| 항목 | 값 | 왜 |
|:-----|:---|:---|
| 범위 | 건물, 캠퍼스 | 구리선 한 가닥은 100m가 한계라 그 안에서 스위치로 잇는다 |
| 속도 | 1Gbps가 흔하고 10Gbps까지 | 내 회선이라 장비만 바꾸면 빨라진다 |
| 지연 | 1ms 미만 | 거리가 짧고 거치는 장비가 스위치 한두 대뿐이다 |
| 오류율 | 매우 낮다 | 선이 짧고 환경을 통제한다 |
| 비용 | 초기 투자뿐 | 회선 사용료가 없다 |

### 왜 전부 이더넷인가

LAN의 기술은 사실상 하나, **이더넷**이다. 1973년 제록스 PARC에서 나와 1983년에 IEEE 802.3 표준이 됐고, 한때 IBM의 토큰링과 경쟁했지만 값싼 장비와 단순한 규칙으로 이겼다. 이더넷은 케이블 한 가닥에 여럿이 매달리던 버스형 시절의 규칙(신호가 부딪히면 잠시 쉬었다 다시 보낸다)에서 출발해, 스위치가 나오면서 충돌 자체를 없앴고, 속도는 10Mbps에서 400Gbps까지 올랐다. 규칙은 그대로 두고 매체와 속도만 바꿔 온 것이 이더넷이 살아남은 비결이며, 그 규칙은 [12. 데이터 링크 계층의 역할과 이더넷](../12-datalink-layer-ethernet)에서, 규격의 역사는 [16. 이더넷의 종류와 특징](../16-ethernet-types-features)에서 본다. 이 PC의 유선 어댑터가 1Gbps로 붙어 있는 것도 1999년의 1000BASE-T 규격이다.

### 경계: 라우터

```
192.168.0.10 ─┐
192.168.0.11 ─┼─ 스위치 ─ 라우터 ─ ISP
192.168.0.12 ─┘   (LAN)   (경계)  (WAN)
```

LAN은 어디서 끝나는가. 스위치에 붙은 장비들은 서로 직접 대화하지만, 밖으로 나가는 패킷은 전부 **라우터** 한 대를 거친다. PC의 네트워크 설정에서 "기본 게이트웨이"로 적혀 있는 주소가 그 라우터이고, PC는 목적지가 같은 LAN 안이면 직접 보내고 아니면 게이트웨이에 맡긴다. 그 판단을 2장에서 본 서브넷 마스크의 AND로 한다. 라우터 안쪽이 내 망, 바깥쪽이 남의 망이며, 그래서 라우터는 LAN과 WAN을 잇는 경계 장비다([22. 라우터의 구조와 라우팅](../22-router-structure)).

## 3. WAN: 남의 회선을 빌리는 망

### 구성

```
서울 지사              부산 본사
┌───────┐             ┌───────┐
│  LAN  │             │  LAN  │
└───┬───┘             └───┬───┘
    │     ┌─────────┐     │
    └─────┤ ISP 회선├─────┘
          └─────────┘
```

서울과 부산의 사무실을 잇고 싶다고 직접 케이블을 깔 수는 없다. 통신사가 이미 깔아 둔 회선을 **빌린다.** 그것이 WAN이고, WAN의 모든 성질이 "남의 것"에서 나온다. 속도는 계약한 만큼이고, 더 필요하면 더 낸다. 장애가 나면 통신사가 고치며, 어떤 기술로 이어져 있는지는 대개 알 필요도 없다.

| 항목 | 값 | 왜 |
|:-----|:---|:---|
| 범위 | 도시, 국가, 전 세계 | 통신사의 망은 그 규모로 깔려 있다 |
| 속도 | 계약한 대역폭. 수 Mbps에서 수 Gbps | 회선을 빌리는 값이 대역폭에 비례한다 |
| 지연 | 수십에서 수백 ms | 거리를 빛이 가는 시간과 경유 라우터의 처리 시간 |
| 오류율 | LAN보다 높다 | 선이 길고 거치는 장비가 많다 |
| 비용 | 월 사용료 | 남의 자산을 쓴다 |

### 빌리는 방법

| 방식 | 무엇인가 | 언제 |
|:-----|:---------|:-----|
| 전용선 | 두 지점 사이를 통신사 회선으로 독점 | 은행처럼 품질과 보안이 우선일 때 |
| MPLS VPN | 통신사 망 안에서 고객별로 분리한 가상 회선 | 지점이 많은 기업의 표준이었다 |
| 인터넷 VPN | 공용 인터넷 위에 암호화한 터널 | 값싸다. 재택근무, 소규모 지점 |
| SD-WAN | 여러 회선을 소프트웨어로 묶어 관리 | 인터넷 회선을 주로 쓰며 전용선을 줄인다 |

1장에서 회선 교환은 독점, 패킷 교환은 공유라고 했는데, 전용선은 WAN에서 남은 회선 교환의 후예다. 비싸지만 남과 섞이지 않는다. 반대편 끝의 인터넷 VPN은 공용 인터넷이라는 가장 싼 회선 위에 암호화로 사적인 통로를 만든 것이고, 그 터널이 패킷을 한 겹 더 감싸는 방식은 [08. 캡슐화와 역캡슐화](../08-encapsulation-decapsulation)에서 본다. 회사 망의 구성은 [05. 회사에서의 LAN 구성](../05-office-lan-configuration)에서 이어진다.

### ISP의 계층: 인터넷은 어떻게 하나로 이어지나

```
Tier 1  국제 백본. 서로 무상 피어링
   │ 트랜짓(유료)
Tier 2  국가 사업자 (KT, SKB, LG U+)
   │ 트랜짓
Tier 3  지역 사업자 ─▶ 가정, 회사
```

| 계층 | 누구 | 어떻게 연결되나 |
|:-----|:-----|:----------------|
| Tier 1 | 국제 백본 사업자(AT&T, NTT, Lumen 등) | 서로 돈을 주고받지 않고 맞교환(피어링)한다. 남에게 회선을 사지 않는다 |
| Tier 2 | 국가·지역 사업자(KT, SKB, LG U+) | 같은 급끼리는 피어링하고, 위로는 회선을 산다(트랜짓) |
| Tier 3 | 지역 케이블, 소규모 사업자 | 위에서 사기만 한다 |

인터넷에는 주인이 없다고 했는데, 그렇다면 KT 가입자의 패킷이 미국 서버에 어떻게 닿는가. 답은 **ISP끼리의 계약**이다. 작은 사업자는 큰 사업자에게 돈을 내고 통로를 사고(트랜짓), 비슷한 크기의 사업자끼리는 서로의 트래픽을 무상으로 넘겨 준다(피어링). 맨 위의 Tier 1 사업자들은 서로 전부 피어링해서 아무에게도 사지 않으며, 그래서 세상 어디로든 갈 수 있다. 한 나라 안의 사업자들이 한 장소에 모여 피어링하는 곳이 인터넷 교환점(IX)이고 한국에는 KINX가 있다. 인터넷은 하나의 망이 아니라 이 계약들로 이어진 수만 개의 망이며, 그래서 한 사업자가 망가져도 나머지는 돈다. 가정에서 ISP를 고르고 회선을 받는 과정은 [04. 가정에서의 LAN 구성](../04-home-lan-configuration)에 있다.

## 4. MAN과 PAN

MAN은 도시 하나를 덮는 망이다. 대학의 캠퍼스들을 잇는 광케이블, 지자체가 깐 CCTV 망, 지하철 Wi-Fi가 여기 든다. 기술은 광케이블이 주류이고, 회선을 직접 깔았으면 LAN처럼, 사업자에게 빌렸으면 WAN처럼 동작한다. 1절의 기준이 여기서도 통한다.

PAN은 내 몸 주변 수 m다. 블루투스 이어폰과 스마트워치, USB로 이은 장치가 여기 들고, 주인이 나 하나라 규칙도 내가 정한다. 거리가 짧아 전력이 적게 들도록 만들어진 것이 블루투스 같은 PAN 기술의 특징이다.

## 5. LAN과 WAN 나란히 보기

| 비교 | LAN | WAN |
|:-----|:----|:----|
| 회선의 주인 | 조직 | ISP |
| 기술 | 이더넷 하나 | 전용선, MPLS, 인터넷 등 여럿 |
| 속도 | 1~10Gbps. 장비를 바꾸면 는다 | 계약한 만큼. 돈을 내면 는다 |
| 지연 | 1ms 미만 | 10~300ms |
| 오류율 | 낮다 | 상대적으로 높다 |
| 비용 | 초기 투자 | 월 사용료 |
| 보안 | 내 통제 아래 | 남의 망을 지나므로 암호화가 필요하다 |

| `ping` 대상 | 왕복 | 어디 |
|:------------|-----:|:-----|
| 기본 게이트웨이 | 0~1ms | LAN의 끝, 라우터 |
| 8.8.8.8 | 38ms | WAN 건너 가까운 데이터센터 |
| 핀란드의 서버 | 251ms | WAN 건너 7,000km |

지연의 차이가 백 배를 넘는 것은 회선이 나빠서가 아니다. 1장에서 본 대로 빛이 거리를 가는 시간과 경유 라우터의 처리 시간이 쌓인 것이고, LAN에서는 둘 다 거의 0이다. 그래서 같은 프로그램이 LAN에서는 빠르고 WAN에서는 느리며, WAN을 건너는 요청의 횟수를 줄이는 것이 네트워크 프로그램의 성능을 좌우한다.

{{< callout type="info" >}}
가정의 공유기 한 대가 두 세계를 다 맡는다. **WAN 포트** 하나는 ISP의 회선에 꽂히고, **LAN 포트**와 Wi-Fi에는 집 안의 기기가 붙는다. 그 사이에서 공유기는 2절의 라우터이자 3절의 경계이고, 집 안의 사설 주소를 바깥의 공인 주소 하나로 바꿔 내보내는 NAT까지 한다. 자세한 것은 [04. 가정에서의 LAN 구성](../04-home-lan-configuration)에서 본다.
{{< /callout >}}

## 6. 인터넷의 기원

| 시기 | 사건 | 의미 |
|:-----|:-----|:-----|
| 1969 | ARPANET, UCLA·SRI·UCSB·유타대 4개 노드 연결 | 1장의 패킷 교환을 실제 망으로 실증 |
| 1974 | 빈트 서프와 로버트 칸의 TCP 논문 | 서로 다른 망을 하나로 잇는 규칙의 출발 |
| 1982 | 한국의 SDN, 미국 밖 첫 TCP/IP 망 | 서울대와 구미 사이의 연결 |
| 1983 | ARPANET이 TCP/IP로 전환 | 지금 인터넷의 규칙이 이날 시작됐다 |
| 1991 | 팀 버너스리의 WWW | 인터넷 위에 웹이라는 응용이 얹혔다 |
| 1995 | 미국 NSFNET 백본 퇴역 | 상용 ISP들의 망으로 넘어갔다 |

ARPANET은 미국 국방부 ARPA가 만든 망으로, 1장의 패킷 교환이 실제로 동작함을 처음 보인 곳이다. 처음에는 망마다 규칙이 달라 서로 대화할 수 없었고, 그 망들을 잇는 공통 규칙으로 나온 것이 TCP/IP다. 이름 그대로 "망과 망 사이"(inter-network)를 잇는 규칙이라 인터넷이라 부른다. 1983년 ARPANET이 TCP/IP로 갈아탄 뒤 대학과 연구소의 망이 차례로 붙었고, 1991년 웹이 얹히면서 일반인이 쓰는 인터넷이 됐으며, 1995년 미국 정부의 백본이 물러나면서 3절의 ISP들이 그 자리를 이어받았다. 인터넷에 주인이 없는 것은 그렇게 만들어졌기 때문이다. TCP/IP가 무엇을 어떻게 정했는지는 [07. OSI 모델과 TCP/IP 모델](../07-osi-tcpip-model)에서 본다.

## 핵심 정리

| 개념 | 핵심 | 왜 |
|:-----|:-----|:---|
| LAN | 내가 깔고 관리하는 망 | 빠르고 싸고 마음대로 바꾼다 |
| WAN | 남의 회선을 빌리는 망 | 속도는 계약, 장애는 통신사, 기술은 여럿 |
| 가르는 기준 | 거리가 아니라 소유 | 성질을 정하는 것은 회선의 주인이다 |
| 이더넷 | LAN의 유일한 기술 | 규칙은 두고 매체와 속도만 바꿔 살아남았다 |
| 라우터 | LAN과 WAN의 경계 | 기본 게이트웨이. 밖으로 가는 패킷은 전부 여기로 |
| 100m | 구리선 한 가닥의 한계 | LAN을 스위치로 잇는 이유 |
| 지연 | LAN 1ms 미만, WAN 수십에서 수백 ms | 거리를 가는 빛과 경유 라우터 |
| 전용선과 VPN | 독점 회선과 공용 인터넷 위의 터널 | 회선 교환의 후예와 가장 싼 회선의 활용 |
| ISP 계층 | 트랜짓과 피어링 | 주인 없는 인터넷은 계약으로 이어진다 |
| Tier 1 | 서로 피어링, 아무에게도 안 산다 | 그래서 어디로든 간다 |
| IX | 사업자들이 모여 피어링하는 곳 | 한국은 KINX |
| 공유기 | WAN 포트 하나, LAN 포트 여럿 | 집 안의 라우터이자 경계 |
| ARPANET | 1969년, 패킷 교환의 실증 | 1983년 TCP/IP 전환이 인터넷의 시작 |

**용어 정리**
- **LAN (Local Area Network)**: 건물이나 캠퍼스 안에서 조직이 직접 구축하고 관리하는 망
- **WAN (Wide Area Network)**: 통신사의 회선을 빌려 먼 지점을 잇는 망
- **MAN (Metropolitan Area Network)**: 도시 규모의 망
- **PAN (Personal Area Network)**: 개인 주변 수 m의 망
- **ISP (Internet Service Provider)**: 인터넷 회선을 제공하는 사업자
- **트랜짓 / 피어링**: 상위 사업자에게 통로를 사는 것 / 대등한 사업자끼리 트래픽을 무상 교환하는 것
- **기본 게이트웨이**: LAN 밖으로 나가는 패킷을 맡기는 라우터의 주소
- **ARPANET**: 1969년의 첫 패킷 교환 망. 인터넷의 시초
