[15. 데이터가 케이블에서 충돌하지 않는 구조](../15-collision-free-structure)의 마지막 문장이 "케이블을 꽂으면 회의가 끝나고, 전파를 쓰면 회의가 다시 시작된다"였다. [12](../12-datalink-layer-ethernet)장은 전파에서는 보내면서 들을 수 없어 충돌을 감지하는 대신 피하는 규칙을 쓴다고 했고, [04](../04-home-lan-configuration)장은 규격의 최대 속도가 방에 기기 하나만 있을 때의 값이라고 했으며, [09](../09-physical-layer-nic)장과 [10](../10-cable-types-structure)장은 전파용 카드와 매체를 여기로 미뤘다. 원리는 셋이다. 첫째, **전파는 나눌 수 없는 하나의 매체라 회의가 다시 시작된다.** 케이블은 기기마다 한 가닥이었지만 전파는 방 안의 모두가 하나를 나눠 쓰고, 보내면서 들을 수 없으므로 충돌을 피하는 절차(CSMA/CA)가 필요하며, 그 절차의 값이 규격 속도와 실제 속도의 차이다. 둘째, **주파수가 곧 성격이다.** 2.4GHz인 이유는 면허 없이 쓸 수 있는 대역이 그것뿐이었기 때문이고, 높은 주파수가 빠르지만 짧게 가는 것은 계산으로 나오며, 세대가 바뀌며 빨라진 것은 같은 전파에 더 많은 비트를 싣는 방법의 진화다. 셋째, **전파는 벽을 넘으므로 무선의 보안은 암호화가 전부다.** 케이블은 꽂아야 듣지만 전파는 옆집도 듣는다. 이 PC에는 무선 랜 카드가 없어 실측 대신 계산으로 채웠고, 대신 같은 2.4GHz를 쓰는 블루투스 어댑터가 있어 간섭의 이야기에 쓴다.

## 1. 무선 랜이란

```
유선:
 PC ── 케이블 ── 스위치 ── 라우터

무선:
 PC ))) 전파 ))) AP ── 스위치 ── 라우터
```

| 장점 | 단점 | 왜 |
|:-----|:-----|:---|
| 케이블이 없다, 움직인다 | 유선보다 느리다 | 하나의 전파를 모두가 나눠 쓴다 |
| 설치와 재배치가 쉽다 | 벽과 간섭에 흔들린다 | 전파는 거리와 장애물에 약해진다 |
| 기기 여럿을 한 번에 | 범위가 한정되고 보안이 필수 | 전파는 벽을 넘는다 |

무선 랜은 케이블 자리에 전파를 넣은 LAN이고 Wi-Fi가 그 이름이다. 그림에서 달라진 것은 PC와 스위치 사이의 한 구간뿐이며, AP부터 뒤는 [14](../14-switch-structure)장의 유선 LAN 그대로다. 그런데 그 한 구간이 [10](../10-cable-types-structure)장의 케이블과 성질이 정반대다. 케이블은 기기마다 한 가닥이라 [15](../15-collision-free-structure)장에서 본 대로 충돌이라는 개념이 사라졌지만, 전파는 방 안의 기기 전부가 하나를 나눠 쓴다. 이 PC에는 무선 랜 카드가 없어 Windows의 무선 서비스조차 돌지 않지만, 블루투스 5.0 어댑터는 있다. 블루투스도 2.4GHz 전파이고, 그래서 이 PC 옆에서 Wi-Fi를 쓰는 기기와 같은 대역을 나눠 쓴다.

## 2. 구성 요소

| 부품 | 하는 일 | 왜 있나 |
|:-----|:--------|:--------|
| AP (액세스 포인트) | 전파와 케이블 사이의 다리. 이름을 알리고, 손님을 받고, 프레임을 중계한다 | 무선 프레임과 이더넷 프레임은 모양이 달라 바꿔 줄 것이 필요하다 |
| 무선 어댑터 | 09장의 전파용 PHY를 가진 카드 | 비트를 전압 대신 전파로 바꾼다 |
| 무선 공유기 | AP와 라우터와 스위치와 DHCP를 한 상자에 | 04장. 가정의 규모 |

AP는 본질적으로 [14](../14-switch-structure)장에서 본 브리지다. 전파 쪽의 프레임(802.11)을 받아 케이블 쪽의 프레임(802.3)으로 바꿔 스위치에 넘기고, 반대도 한다. 두 프레임의 모양이 다른 것은 전파 쪽에 주소가 더 필요하기 때문이다. 유선 프레임은 보낸 이와 받을 이 둘이지만, 무선 프레임은 그 둘에 더해 "어느 AP를 거쳐"가 있어야 하므로 MAC 주소 칸이 셋이고 AP끼리 중계할 때는 넷이다. AP는 100ms마다 비콘이라는 프레임으로 자기 이름과 능력을 알리고, 손님이 오면 인증과 연결을 처리한 뒤 그 손님의 프레임을 유선으로 넘긴다. 이름과 채널의 이야기는 [36. SSID의 구조](../36-ssid-structure)에서 본다.

```
┌─────────────────────────┐
│      무선 공유기        │
│  ┌───────────────────┐  │
│  │ AP (SSID, 인증)   │  │
│  ├───────────────────┤  │
│  │ 라우터 (NAT, FW)  │  │
│  ├───────────────────┤  │
│  │ 스위치 (LAN 4포트)│  │
│  └───────────────────┘  │
└─────────────────────────┘
```

## 3. 연결 방식

```
[기기 A] ))) [AP] ))) [기기 B]
               │
            유선 네트워크
               │
             인터넷
```

```
1) AP가 비콘으로 SSID를 알린다
2) 클라이언트가 스캔한다 (Probe)
3) 인증 (Authentication)
4) 연결 (Association)
5) DHCP로 주소를 받는다
6) 데이터를 주고받는다
```

보통의 방식은 모든 통신이 AP를 거치는 인프라스트럭처 모드다. 같은 방의 A가 B에게 보내도 전파는 A에서 AP로, 다시 AP에서 B로 두 번 난다. 왜 직접 보내지 않는가. 나눠 쓰는 매체에 누군가 순서를 정하고 모두가 닿는 자리에 있어야 하기 때문이고, 그 역할이 AP다. 절차의 3단계와 4단계가 둘로 나뉜 것은 옛 규격의 흔적이다. 처음의 "인증"은 WEP 시절의 형식적인 것이라 지금은 거의 비어 있고, 진짜 인증은 4단계 뒤 6절의 핸드셰이크에서 한다. 5단계부터는 [18](../18-ip-address-structure)장의 DHCP 그대로다. 무선이라고 3층이 달라지는 것은 없다.

AP 없이 기기끼리 직접 맺는 애드혹 모드도 있지만 범위와 성능과 보안이 제한적이라, 지금은 한 기기가 잠시 AP 노릇을 하는 Wi-Fi Direct가 그 자리를 대신한다.

{{< callout type="info" >}}
같은 네트워크라도 유선과 무선은 성질이 다르다. 유선은 15장에서 본 대로 스위치와 전이중으로 충돌 자체가 없고, 무선은 반이중에 5절의 CSMA/CA로 차례를 다투며, 신호 세기와 간섭에 따라 속도가 수시로 변한다. 붐비는 환경이라면 회의와 스트리밍은 유선으로, 움직이는 기기만 무선으로 나누는 것이 안정적이다.
{{< /callout >}}

## 4. IEEE 802.11 표준

| 표준 | 별칭 | 주파수 | 최대 속도 | 무엇이 빨라졌나 |
|:-----|:-----|:-------|:----------|:---------------|
| 802.11b | | 2.4GHz | 11Mbps | 1999년의 출발 |
| 802.11a, g | | 5GHz, 2.4GHz | 54Mbps | OFDM. 전파를 잘게 나눠 싣는다 |
| 802.11n | Wi-Fi 4 | 2.4, 5GHz | 600Mbps | 안테나 넷(MIMO), 채널 40MHz |
| 802.11ac | Wi-Fi 5 | 5GHz | 6.9Gbps | 안테나 여덟, 채널 160MHz, 256-QAM |
| 802.11ax | Wi-Fi 6, 6E | 2.4, 5, 6GHz | 9.6Gbps | 1024-QAM, 기기 여럿을 한 번에(OFDMA), 6GHz |
| 802.11be | Wi-Fi 7 | 2.4, 5, 6GHz | 46Gbps | 채널 320MHz, 4096-QAM, 대역 동시 사용 |

속도가 오른 방법은 [09](../09-physical-layer-nic)장의 PAM-5와 같은 발상이다. 전파 한 번에 실을 비트 수를 늘리고(QAM의 단계. 256이면 8비트, 1024면 10비트), 안테나를 여럿 두어 같은 주파수에 흐름 여럿을 겹치고(MIMO), 채널을 넓힌다. Wi-Fi 6의 9.6Gbps는 흐름 하나가 160MHz 채널에서 1.2Gbps인 것을 안테나 여덟으로 곱한 값이다. 폰의 안테나는 둘이고 채널은 보통 80MHz라 규격상으로도 1.2Gbps이며, 5절의 절차를 거치면 그 절반 아래가 실제 값이다. 04장에서 규격의 최대 속도는 방에 기기 하나만 있을 때의 값이라고 한 것이 이 계산이다.

| 항목 | 2.4GHz | 5GHz | 6GHz | 왜 |
|:-----|:-------|:-----|:-----|:---|
| 속도 | 낮다 | 높다 | 매우 높다 | 채널을 넓게 잡을 자리가 있다 |
| 거리 | 멀다 | 중간 | 짧다 | 주파수가 높을수록 같은 거리에서 약해진다 |
| 벽 | 잘 지난다 | 약하다 | 매우 약하다 | 파장이 짧을수록 장애물에 막힌다 |
| 간섭 | 많다 | 적다 | 거의 없다 | 전자레인지, 블루투스, 이웃이 다 2.4GHz다 |
| 겹치지 않는 채널 | 3개 (1, 6, 11) | 20개 남짓 | 60개 | 대역의 폭. 83MHz 대 1,200MHz |

왜 하필 2.4GHz인가. 1985년에 미국이 면허 없이 쓸 수 있게 열어 둔 대역(ISM)이 2.4GHz였고, 그 대역이 비어 있던 이유는 전자레인지가 2.45GHz로 물 분자를 데우는 대역이라 통신에 쓰기 나빴기 때문이다. Wi-Fi는 그 나쁜 대역에서 출발했고, 그래서 전자레인지를 돌리면 끊기고, 이 PC의 블루투스와도 이웃집 공유기와도 같은 83MHz를 나눠 쓴다. 5GHz와 6GHz는 그 뒤에 열린 넓은 대역이다.

| 거리 | 2.4GHz | 5GHz | 6GHz |
|:-----|:-------|:-----|:-----|
| 1m | −20dBm | −26dBm | −28dBm |
| 10m | −40dBm | −46dBm | −48dBm |
| 30m | −50dBm | −56dBm | −58dBm |

주파수가 높을수록 짧게 가는 것은 계산으로 나온다. AP가 20dBm(100mW)으로 보낼 때 아무것도 없는 공간에서 받는 세기를 거리와 주파수의 공식으로 계산한 표다. 같은 10m에서 5GHz는 2.4GHz보다 6dB, 곧 전력으로 4분의 1이 약하고, 6GHz는 8dB 약하다. 벽 하나가 다시 3~10dB를 빼앗으므로 실제 집에서는 이보다 훨씬 낮다. 공유기가 두 대역을 같은 이름으로 함께 내는 이유가 이 표다. 가까우면 빠른 5GHz, 멀면 벽을 지나는 2.4GHz를 기기가 고른다.

## 5. 매체 접근 제어: CSMA/CA

```
1) 채널이 비었나 듣는다
2) 비었으면 DIFS만큼 기다린다
3) 무작위 시간을 더 기다린다 (백오프)
4) 보낸다
5) 받는 쪽이 ACK를 돌려준다
   └ ACK가 없으면 다시 보낸다
```

[11](../11-repeater-hub)장의 CSMA/CD는 보내면서 듣다가 부딪히면 멈추는 규칙이었다. 전파에서는 그 "보내면서 듣기"가 안 된다. 내 안테나에서 나가는 신호는 몇 m 밖에서 오는 남의 신호보다 10억 배쯤 세서, 보내는 동안 내 수신기에는 내 신호밖에 안 들린다. 충돌이 나도 모르므로 감지 대신 **피하고**, 피했는데도 부딪혔는지는 상대의 확인으로 안다.

| 단계 | 왜 |
|:-----|:---|
| 듣는다 | 남이 말하는 중이면 기다린다. 유선과 같다 |
| DIFS | 조용해진 직후 잠깐 더 기다린다. 방금 끝난 대화의 ACK가 먼저 나갈 자리를 준다 |
| 무작위 백오프 | 기다리던 모두가 같은 순간에 시작하면 부딪힌다. 11장의 백오프와 같다 |
| ACK | 부딪혔는지 내가 모르니 상대가 받았다고 말해 줘야 한다. 프레임마다 |

```
[A] ))) [AP] ((( [B]
 A와 B는 서로를 인식 못함
 → 동시에 전송 시 AP에서 충돌
```

유선에 없던 문제도 생긴다. AP의 양쪽 끝에 있는 A와 B는 서로의 전파가 닿지 않아 상대가 말하는 중인지 들을 수 없고(숨은 노드), 둘이 동시에 보내면 AP에서 부딪힌다. 그래서 큰 프레임을 보내기 전에 A가 짧게 "보내도 되나"(RTS)를 묻고 AP가 "보내라"(CTS)를 모두에게 알리면, B는 A가 안 들려도 AP의 CTS를 듣고 그 시간만큼 조용히 한다.

이 절차의 값이 규격 속도와 실제 속도의 차이다. 1,500바이트 프레임을 1.2Gbps로 실어 보내는 데는 10μs가 드는데, 그 앞뒤의 기다림과 백오프와 상대의 ACK를 합치면 100μs가 넘는다. 데이터보다 절차가 열 배 길고, 방에 기기가 늘수록 백오프에서 지는 횟수가 늘며, 이웃집 공유기가 같은 채널이면 그 집 기기들과도 차례를 다툰다. 그리고 이 모든 것이 반이중이다. AP가 말하는 동안 아무도 말할 수 없고, 15장에서 본 대로 이것이 Wi-Fi가 지금도 반이중인 이유다. Wi-Fi 6의 OFDMA는 이 절차를 한 번 밟고 채널을 잘게 나눠 여러 기기의 작은 프레임을 한꺼번에 싣는 방법이고, 기기가 많은 방에서 6가 5보다 나은 이유가 절차의 횟수를 줄이는 데 있다.

## 6. 무선 랜 보안

| 방식 | 암호 | 상태 | 왜 |
|:-----|:-----|:-----|:---|
| Open | 없다 | 공개 Wi-Fi. 쓰면 안 된다 | 같은 AP의 남이 전부 듣는다 |
| WEP | RC4 | 1997년. 금지 | 키를 재사용해 몇 분이면 풀린다 |
| WPA | TKIP (RC4) | 2003년. 금지 | WEP 장비에서 돌게 만든 임시방편 |
| WPA2 | AES-CCMP | 2004년. 최소선 | 제대로 된 암호. 비밀번호가 약하면 사전 공격 |
| WPA3 | AES-GCMP, SAE | 2018년. 권장 | 비밀번호를 사전 공격에서 지킨다 |

케이블은 꽂은 사람만 듣지만 전파는 벽 너머 옆집도, 주차장의 차 안에서도 듣는다. 그래서 무선에는 유선에 없던 층이 하나 더 있다. 프레임 자체를 암호화하는 층이고, 표는 그 층이 세 번 깨지고 고쳐진 역사다. 첫 규격 WEP는 같은 키를 반복해 쓰는 설계 결함으로 2001년에 몇 분 만에 풀리게 됐고, 급히 만든 WPA를 거쳐 2004년의 WPA2가 제대로 된 암호(AES)를 넣었다. WPA2의 남은 약점은 비밀번호 자체다. 아래 인사말을 녹음해 두면 사전의 단어를 하나씩 대입해 볼 수 있어, 짧은 비밀번호는 오프라인에서 풀린다. 2018년의 WPA3는 그 인사말을 바꿔 녹음해도 소용없게 했다.

```
클라이언트           AP
    │  ANonce         │
    │◀────────────────┤
    │  SNonce+MIC     │
    ├────────────────▶│
    │  GTK+MIC        │
    │◀────────────────┤
    │  ACK            │
    ├────────────────▶│
    │  암호화 통신 시작│
```

WPA2의 4단계 인사말이 하는 일은 **비밀번호를 보내지 않고 알고 있음을 증명하고, 이번 연결에서만 쓸 키를 만드는 것**이다. 양쪽은 비밀번호에서 같은 마스터 키를 이미 갖고 있다. AP가 난수 하나(ANonce)를 보내고 클라이언트가 자기 난수(SNonce)를 보내면, 둘은 마스터 키와 난수 둘로 같은 세션 키를 계산한다. 그 키로 만든 서명(MIC)이 맞으면 상대도 비밀번호를 안다는 증명이 되고, 3번째에 AP가 방송용 키(GTK)를 그 세션 키로 감싸 보내며, 4번째가 확인이다. 난수가 연결마다 바뀌므로 키도 연결마다 다르고, 비밀번호는 한 번도 전파에 실리지 않는다. 그런데도 녹음한 인사말로 사전 공격이 되는 것은 난수 둘이 평문으로 오가기 때문이다. 비밀번호 후보마다 키를 계산해 MIC가 맞는지 보면 된다. WPA3의 SAE는 그 앞에 양쪽이 서로 검증하는 교환을 하나 더 두어 후보를 한 번에 하나씩, 그것도 AP를 상대로만 시험하게 만들었고, 그래서 사전 공격이 안 통하며 나중에 비밀번호가 새도 옛 통신은 못 푼다.

{{< callout type="warning" >}}
공개 Wi-Fi에서는 HTTPS나 VPN 없이 민감한 일을 하지 않는다. Open 네트워크는 프레임이 암호화되지 않아 같은 AP에 붙은 누구나 남의 트래픽을 그대로 본다. [28](../28-application-layer-role)장에서 본 TLS가 그 위에서 내용을 지키지만, 어느 사이트에 가는지는 보인다. WPA3에는 비밀번호 없는 공개망도 암호화하는 방식(OWE)이 있어 카페의 AP가 그것을 켜면 옆자리에서는 못 듣는다.
{{< /callout >}}

## 7. 실무 도구

```bash
# Linux
iwconfig
iw dev wlan0 link                 # 지금 붙은 AP, 신호, 속도
iw dev wlan0 info
sudo iw dev wlan0 scan | grep SSID
nmcli dev wifi list               # 주변 AP, 채널, 신호
nmcli dev wifi connect "MyWiFi" password "secret"
wavemon                           # 신호를 실시간으로
```

```powershell
netsh wlan show interfaces        # 붙은 AP, 신호(%), 속도
netsh wlan show networks mode=bssid
netsh wlan show profiles
netsh wlan show profile name="MyWiFi" key=clear
```

이 PC에서 첫 명령을 치면 "무선 서비스가 돌고 있지 않다"가 나온다. 무선 카드가 없으면 Windows는 그 서비스를 띄우지 않는다. 카드가 있는 노트북에서는 붙어 있는 AP의 이름, 채널, 신호 세기, 협상된 속도가 나오고, 신호는 dBm 대신 퍼센트로 보인다.

| RSSI (dBm) | 상태 | 왜 |
|:-----------|:-----|:---|
| −30 ~ −50 | 매우 좋다 | 4절의 표에서 AP와 같은 방 |
| −50 ~ −67 | 좋다. 영상 통화가 된다 | 벽 하나 너머 |
| −67 ~ −70 | 보통 | 높은 QAM을 못 쓰고 속도가 내려간다 |
| −70 ~ −80 | 약하다. 끊길 수 있다 | 재전송이 늘고 백오프에서 진다 |
| −80 이하 | 쓰기 어렵다 | 잡음과 구별이 안 된다 |

dBm은 1mW를 0으로 둔 로그 눈금이라 −40이 −50보다 10배 세다. 4절의 계산표와 나란히 보면 −67dBm이라는 경계는 5GHz로 벽 하나쯤 너머의 값이다. 이 경계 아래로 가면 [02](../02-bit-and-byte)장에서 본 잡음이 신호와 비슷해져 비트가 뒤집히고, 카드는 QAM의 단계를 낮춰 느리지만 튼튼한 방식으로 바꾸며, 그래도 깨진 프레임은 [12](../12-datalink-layer-ethernet)장의 FCS에서 걸려 5절의 ACK가 안 오고 재전송이 는다. 신호가 약할 때 속도가 계단처럼 떨어지는 것이 그 QAM 단계다.

## 핵심 정리

| 개념 | 핵심 | 왜 |
|:-----|:-----|:---|
| 무선 랜 | 케이블 한 구간을 전파로 | AP 뒤는 유선 그대로 |
| 하나의 매체 | 방 안의 모두가 나눠 쓴다 | 15장의 회의가 다시 시작된다 |
| AP | 전파와 케이블 사이의 브리지 | 무선 프레임은 주소가 셋이다 |
| 2.4GHz인 이유 | 면허 없는 대역이 그것뿐이었다 | 전자레인지의 대역. 블루투스도 같다 |
| 주파수와 거리 | 5GHz는 10m에서 6dB 약하다 | 계산으로 나온다. 전력 4분의 1 |
| 채널 수 | 3개 대 60개 | 83MHz 대 1,200MHz |
| 세대의 진화 | QAM 단계, 안테나 수, 채널 폭 | 같은 전파에 더 많은 비트를 |
| 9.6Gbps | 1.2Gbps × 안테나 여덟 | 폰은 둘. 실제는 그 절반 아래 |
| CSMA/CA | 듣고, 기다리고, 무작위로 더 기다리고, ACK | 보내면서 들을 수 없다 |
| 절차의 값 | 데이터 10μs에 절차 100μs | 규격과 실제의 차이 |
| 숨은 노드 | 서로 안 들리는 둘이 AP에서 부딪힌다 | RTS와 CTS |
| 반이중 | AP가 말하면 모두 듣는다 | 유선에는 없어진 성질 |
| 보안의 역사 | WEP, WPA, WPA2, WPA3 | 전파는 벽을 넘는다 |
| 4단계 인사 | 비밀번호를 안 보내고 증명 | 난수 둘로 연결마다 다른 키 |
| WPA3 | 녹음해도 소용없다 | 후보를 하나씩, AP를 상대로만 |
| −67dBm | 좋음과 보통의 경계 | 잡음과의 거리. QAM 단계가 내려간다 |

{{< callout type="info" >}}
**용어 정리**
- **AP**: 전파와 케이블을 잇는 다리. 비콘으로 이름을 알리고 손님의 프레임을 중계한다
- **SSID**: 무선 네트워크의 이름. 36장
- **ISM 대역**: 면허 없이 쓰는 주파수. 2.4GHz가 그 시작
- **QAM, MIMO, 채널 폭**: 전파 한 번에 싣는 비트, 겹치는 흐름의 수, 쓰는 주파수의 폭
- **CSMA/CA**: 듣고, 기다리고, 무작위로 더 기다린 뒤 보내고 ACK를 받는 규칙
- **DIFS, 백오프**: 조용해진 뒤의 기다림, 그 뒤의 무작위 기다림
- **숨은 노드 / RTS, CTS**: 서로 안 들리는 기기들 / 보내기 전에 AP에게 허락을 받는 절차
- **WPA2, WPA3**: AES 암호와 4단계 인사 / 사전 공격을 막는 SAE
- **RSSI, dBm**: 받는 신호의 세기. 1mW를 0으로 둔 로그 눈금
{{< /callout >}}
