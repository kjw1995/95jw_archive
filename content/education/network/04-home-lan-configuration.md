[03. LAN과 WAN](../03-lan-and-wan)의 끝에서 가정의 공유기 한 대가 LAN과 WAN을 다 맡는다고 했다. 이 장은 그 상자를 열어 본다. 원리는 셋이다. 첫째, **집의 인터넷은 WAN 회선 하나를 기기 여럿이 나눠 쓰는 구조다.** 통신사는 회선 하나와 공인 주소 하나를 주는데 집에는 PC, 폰, TV, 냉장고까지 수십 대가 있다. 이 불일치가 공유기의 존재 이유이고, NAT와 DHCP는 그 불일치를 메우는 장치다. 둘째, **공인 주소는 부족하고, 사설 주소는 밖에서 보이지 않는다.** IPv4 주소가 43억 개뿐이라는 [02. 비트와 바이트](../02-bit-and-byte)의 사실이 집 안의 주소 체계를 결정했고, 집에서 띄운 서버가 밖에서 안 보이는 이유도 여기 있다. 셋째, **자동으로 되는 것에는 전부 프로토콜이 있다.** 케이블을 꽂기만 하면 주소가 잡히고 이름이 풀리고 Wi-Fi가 붙는데, 그 뒤에서 DHCP, DNS, 802.11이 정해진 순서로 대화한다.

## 1. 전체 구조: WAN 하나를 여럿이 나눠 쓴다

```
   인터넷 (WAN)
       │  ISP 회선 (광, 전화선, 동축)
   ┌───┴───┐
   │ 모뎀  │  신호를 이더넷으로
   └───┬───┘
   ┌───┴───┐
   │공유기 │  주소, 경로, 무선
   └───┬───┘
  ┌────┼────┐
 PC   폰    TV   (사설 IP)
```

통신사(ISP)의 회선이 집에 들어오면 장비 둘을 거친다. **모뎀**은 회선의 신호를 이더넷 신호로 바꾼다. 광케이블이면 빛을, 전화선이면 전압의 변조를, 동축이면 케이블 방송용 주파수를 이더넷의 신호로 바꾸는 매체 변환 장치이고, 통신사가 대개 함께 설치해 준다. **공유기**는 그 이더넷 한 가닥을 집 안의 기기 여럿에 나눠 준다. 주소를 나눠 주고(DHCP), 밖으로 나가는 패킷의 주소를 바꾸고(NAT), 유선 포트 사이를 잇고(스위치), 전파로도 잇는다(무선 AP). 요즘은 통신사가 모뎀과 공유기를 한 상자에 넣어 주기도 하는데, 안에서 하는 일은 둘로 나뉘어 있다는 것만 알아 두면 된다.

## 2. ISP와 회선

ISP가 주는 것은 넷이다. 물리 회선, 공인 IP 주소 **하나**, 이름을 풀어 줄 DNS 서버, 그리고 3장에서 본 상위 사업자와의 연결이다. KT, SK브로드밴드, LG U+ 같은 국내 사업자가 3장의 Tier 2이고, 지역 케이블 사업자는 그 아래에서 회선을 빌려 판다.

| 회선 | 매체 | 속도 | 왜 그런 성질인가 |
|:-----|:-----|:-----|:-----------------|
| FTTH | 광케이블 | 100Mbps ~ 10Gbps | 빛이라 멀리 가고 간섭이 없다. 집까지 새로 깔아야 해서 설치비가 든다 |
| VDSL | 전화선 | 최대 100~300Mbps | 이미 깔린 전화선을 쓴다. 전화국에서 멀수록 느려진다 |
| ADSL | 전화선 | 최대 24Mbps | 구형. 내려받기에 대역폭을 몰아준 비대칭(A) 방식 |
| 케이블 | 동축 | 10Mbps ~ 1Gbps | 케이블 방송선을 쓴다. 한 동네가 한 회선을 나눠 써서 저녁에 느려진다 |

회선의 성질은 매체에서 나온다. 전화선과 동축은 이미 집집마다 들어와 있어서 새로 깔 것 없이 인터넷을 얹을 수 있었고, 그래서 초기 인터넷은 ADSL과 케이블이었다. 둘 다 원래 다른 용도로 깐 선이라 한계가 있었다. 전화선은 거리에 따라 신호가 약해지고, 케이블은 동네가 한 회선을 나눠 쓴다. 광케이블은 인터넷을 위해 새로 깐 선이라 그런 한계가 없고, 한국은 FTTH 비율이 세계에서 가장 높은 축이다. 매체별 신호의 차이는 [10. 케이블의 종류와 구조](../10-cable-types-structure)에서 본다.

## 3. 공유기: 한 상자에 든 여섯 가지

| 기능 | 하는 일 | 왜 필요한가 | 계층 |
|:-----|:--------|:-----------|:-----|
| 라우팅 | WAN과 LAN 사이에서 패킷을 넘긴다 | 집 안과 밖은 다른 네트워크다. 3장의 경계 | L3 |
| NAT | 사설 주소를 공인 주소 하나로 바꿔 내보낸다 | 공인 주소는 하나뿐이다(4절) | L3 ~ L4 |
| DHCP | 기기에 주소를 자동으로 준다 | 손으로 주면 겹치고 틀린다(5절) | 응용 |
| 스위치 | 유선 포트 사이에 프레임을 전달한다 | 집 안 기기끼리는 밖을 거칠 필요가 없다 | L2 |
| 무선 AP | Wi-Fi 전파를 낸다 | 선을 꽂을 수 없는 기기가 대부분이다(6절) | L1 ~ L2 |
| 방화벽 | 밖에서 들어오는 연결을 막는다 | NAT의 부산물이자 기본 방어(8절) | L3 ~ L4 |

여섯 가지가 한 상자에 든 것은 가정의 규모 때문이다. 회사라면 라우터, 스위치, 무선 컨트롤러, 방화벽이 따로 있고 그 구성이 [05. 회사에서의 LAN 구성](../05-office-lan-configuration)의 주제인데, 집은 기기 수십 대에 회선 하나라 그것을 전부 갖출 이유가 없다. 표의 계층은 [07. OSI 모델](../07-osi-tcpip-model)의 것으로, 스위치는 프레임의 MAC 주소만 보고 라우터는 패킷의 IP 주소를 본다는 1장의 구분 그대로다.

## 4. 공인 IP와 사설 IP, 그리고 NAT

### 왜 두 종류인가

| 구분 | 공인 IP | 사설 IP |
|:-----|:--------|:--------|
| 누가 주나 | ISP | 공유기(DHCP) |
| 어디서 유일한가 | 인터넷 전체 | 그 집 안에서만 |
| 밖에서 닿나 | 닿는다 | 못 닿는다. NAT를 거쳐야 한다 |

| 사설 대역 (RFC 1918) | 범위 | 개수 |
|:---------------------|:-----|:-----|
| 10.0.0.0/8 | 10.0.0.0 ~ 10.255.255.255 | 약 1,678만 |
| 172.16.0.0/12 | 172.16.0.0 ~ 172.31.255.255 | 약 105만 |
| 192.168.0.0/16 | 192.168.0.0 ~ 192.168.255.255 | 65,536 |

IPv4 주소는 32비트, 약 43억 개다. 세상의 기기가 그보다 훨씬 많으니 기기마다 공인 주소를 줄 수 없다. 그래서 1996년의 RFC 1918이 세 대역을 **인터넷에서 쓰지 않는 주소**로 떼어 두었다. 누구나 자기 집 안에서 마음대로 쓰되 밖으로는 내보내지 않는 주소이고, 그래서 옆집도 우리 집도 똑같이 192.168.0.2를 써도 부딪히지 않는다. 대부분의 공유기가 192.168.0.1이나 192.168.1.1을 자기 주소로 삼고 그 대역을 기기에 나눠 준다. 주소 체계 자체는 [18. IP 주소의 구조](../18-ip-address-structure)와 [19. IP 주소의 클래스 구조](../19-ip-address-class)에서 본다.

### NAT: 주소 하나를 여럿이 쓰는 방법

```
 안(사설)      공유기      밖(공인)
 .2:50000 ─┐
 .3:50000 ─┼─ NAT 표 ─▶ 211.x.x.x:40001
 .4:50000 ─┘             :40002, :40003
```

| 안 (사설 IP:포트) | 밖 (공인 IP:포트) |
|:------------------|:------------------|
| 192.168.0.2:50000 | 211.x.x.x:40001 |
| 192.168.0.3:50000 | 211.x.x.x:40002 |
| 192.168.0.4:50000 | 211.x.x.x:40003 |

사설 주소는 인터넷에서 통하지 않으니 밖으로 나가는 패킷의 출발지 주소를 공유기가 **자기 공인 주소로 바꿔** 내보낸다. 이것이 NAT(주소 변환)다. 문제는 답장이다. 서버가 211.x.x.x로 답을 보내면 공유기는 그것이 PC의 것인지 폰의 것인지 알아야 한다. 그래서 주소만이 아니라 **포트 번호까지 바꾸고** 그 대응을 표에 적어 둔다. PC와 폰이 우연히 같은 50000번 포트를 써도 밖에서는 40001과 40002로 나뉘고, 답장이 40001로 오면 표를 보고 PC에게 돌려준다. 포트 번호가 무엇인지는 [26. 포트 번호의 구조](../26-port-number-structure)에 있다.

이 방식의 대가가 "밖에서 안으로는 못 들어온다"다. 표는 안에서 밖으로 나간 연결만 기록하므로, 밖에서 먼저 들어오는 패킷은 누구에게 줄지 알 수 없어 버려진다. 집에서 게임 서버나 NAS를 띄웠는데 밖에서 붙지 않는 이유, 자바 기초 시리즈 [Chapter 16](../../java/basics/16-networking)의 `ServerSocket`을 집 PC에서 열어도 친구가 접속하지 못하는 이유가 이것이다. 해법은 표에 미리 한 줄을 적어 두는 **포트 포워딩**이다. "밖의 8080번으로 오면 192.168.0.10의 80번에게"라고 공유기에 적으면 그 포트만 열린다. 기기 하나에 모든 포트를 넘기는 설정을 공유기 메뉴에서 DMZ라고 부르는데, 5장에서 볼 회사의 DMZ와는 이름만 같다. 프로그램이 이 표를 스스로 적게 하는 UPnP도 있지만 아무 프로그램이나 문을 열 수 있어 8절에서 끄라고 할 것이다.

### 통신사도 NAT를 한다

공인 주소가 모자라는 것은 통신사도 마찬가지라, 가입자에게 공인 주소 대신 100.64.0.0/10 대역의 주소를 주고 통신사 안에서 한 번 더 NAT를 하는 곳이 늘고 있다. 이것이 CGNAT이고, 1장에서 `tracert`를 했을 때 두 번째 홉이 100.80.x.x였던 것이 그 흔적이다. CGNAT 아래에서는 포트 포워딩을 해도 밖에서 들어올 수 없다. 표가 통신사 쪽에도 있기 때문이다. 집에 공유기가 둘(통신사 것과 내 것)이면 NAT가 두 겹이 되어 같은 문제가 생기고, 통신사 장비를 브리지 모드로 바꿔 NAT를 한 겹으로 줄이는 것이 해법이다.

## 5. DHCP: 주소를 자동으로 받는 이유

```
기기                   공유기
 │  Discover (브로드캐스트) │
 ├──────────────────────▶
 │  Offer  "192.168.0.10 어때" │
 ◀──────────────────────┤
 │  Request "그걸로 할게"  │
 ├──────────────────────▶
 │  Ack  + 마스크, GW, DNS │
 ◀──────────────────────┤
```

기기마다 주소를 손으로 적어도 된다. 그러나 두 기기에 같은 주소를 적으면 둘 다 통신이 끊기고, 마스크나 게이트웨이를 하나만 틀려도 밖으로 못 나가며, 손님의 폰이 올 때마다 적어 줄 수도 없다. DHCP는 이 일을 공유기가 대신하는 규칙이다. 기기가 켜지면 아직 주소가 없으므로 "주소 좀 주세요"를 **브로드캐스트**로 외치고(Discover), 공유기가 빈 주소 하나를 제안하며(Offer), 기기가 그것으로 하겠다고 답하고(Request), 공유기가 확정하면서 서브넷 마스크, 기본 게이트웨이, DNS 서버 주소까지 함께 준다(Ack). 네 단계라 DORA라고 외운다.

주소는 주는 것이 아니라 **빌려주는** 것이다. 임대 기간(보통 몇 시간에서 며칠)이 있고, 기기는 절반쯤 지나면 연장을 요청하며, 떠난 기기의 주소는 기간이 끝나면 회수되어 다른 기기에게 간다. 프린터나 NAS처럼 주소가 바뀌면 곤란한 기기는 공유기에서 그 기기의 MAC 주소에 특정 주소를 **예약**해 두면 DHCP를 쓰면서도 늘 같은 주소를 받는다. DHCP의 자세한 동작은 [18. IP 주소의 구조](../18-ip-address-structure)의 DHCP 절에서, 브로드캐스트가 무엇인지는 [20. 네트워크 주소와 브로드캐스트 주소의 구조](../20-network-broadcast-address)에서 이어진다. Ack에 딸려 오는 DNS 서버 주소는 보통 ISP의 것인데, 8.8.8.8(구글)이나 1.1.1.1(클라우드플레어)로 바꿔 쓸 수도 있다. 이름을 주소로 바꾸는 일은 [30. DNS 서버의 구조](../30-dns-server-structure)에서 본다.

## 6. 유선과 무선

| 항목 | 유선 LAN | 무선 LAN | 왜 |
|:-----|:---------|:---------|:---|
| 매체 | UTP 케이블 | 전파 (2.4, 5, 6GHz) | |
| 속도 | 1~10Gbps | 규격상 최대 9.6Gbps (Wi-Fi 6) | 실제 무선은 규격의 절반 아래 |
| 안정성 | 높다 | 거리와 간섭에 흔들린다 | 전파는 벽과 이웃의 전파에 막힌다 |
| 동시성 | 기기마다 전용 선 | 모두가 한 전파를 나눠 쓴다 | 한 번에 하나만 말할 수 있다 |
| 이동성 | 없다 | 자유 | |

무선이 유선보다 느리고 흔들리는 이유는 매체의 성질이다. 케이블은 기기마다 한 가닥씩이라 동시에 보낼 수 있지만, 전파는 방 안의 모든 기기가 **하나를 나눠 쓴다.** 둘이 동시에 말하면 섞이므로 차례를 기다려야 하고(반이중), 이웃집 공유기도 같은 주파수를 쓰면 그것과도 차례를 다툰다. 규격의 최대 속도는 그 방에 기기 하나만 있고 간섭이 없을 때의 값이다. 이 규칙이 [35. 무선 랜의 구조](../35-wireless-lan-structure)의 CSMA/CA이고, 공유기가 내는 이름과 채널은 [36. SSID의 구조](../36-ssid-structure)에서 본다.

| 세대 | 규격 | 최대 속도 | 주파수 | 바뀐 것 |
|:-----|:-----|:----------|:-------|:--------|
| Wi-Fi 4 | 802.11n | 600Mbps | 2.4/5GHz | 안테나 여러 개(MIMO) |
| Wi-Fi 5 | 802.11ac | 3.5Gbps | 5GHz | 넓은 채널 |
| Wi-Fi 6 | 802.11ax | 9.6Gbps | 2.4/5GHz | 기기가 많을 때의 효율 |
| Wi-Fi 6E | 802.11ax | 9.6Gbps | 2.4/5/6GHz | 비어 있는 6GHz 대역 |
| Wi-Fi 7 | 802.11be | 46Gbps | 2.4/5/6GHz | 여러 대역 동시 사용 |

주파수는 높을수록 빠르고 낮을수록 멀리 간다. 2.4GHz는 벽을 잘 지나지만 채널이 좁고 전자레인지, 블루투스와 겹쳐 붐비며, 5GHz와 6GHz는 빠르지만 벽에 약하다. 공유기가 같은 이름으로 두 대역을 함께 내는 이유이고, 기기는 신호가 좋은 쪽을 고른다.

## 7. 확인 명령어

```
> ipconfig
이더넷 어댑터 이더넷:
  IPv4 주소 . . . . . . : 192.168.0.10
  서브넷 마스크 . . . . : 255.255.255.0
  기본 게이트웨이 . . . : 192.168.0.1
```

```bash
ipconfig /all    # Windows. DHCP 사용 여부, 임대 시간, DNS 서버까지
tracert 8.8.8.8  # 첫 홉이 공유기, 그다음이 통신사
ip addr          # Linux
ifconfig         # macOS, 구형 Linux
```

`ipconfig`의 세 줄이 5절의 Ack로 받은 것이다. 첫 줄이 DHCP가 준 사설 주소, 셋째 줄이 공유기다. 주소가 192.168.x.x나 10.x.x.x면 지금 NAT 뒤에 있다는 뜻이고, 기본 게이트웨이가 공유기의 주소다. 내 공인 주소는 이 명령으로는 알 수 없다. 공유기 관리 화면의 WAN 상태에서 보거나 "내 IP"를 알려 주는 웹 사이트로 확인하는데, 그 값이 100.64.x.x 대역이면 4절의 CGNAT 아래에 있는 것이다.

## 8. 보안 기본

| 조치 | 왜 |
|:-----|:---|
| 관리자 비밀번호 바꾸기 | 기본값은 모델별로 공개되어 있다. 이것을 아는 사람은 4절의 표를 마음대로 적을 수 있다 |
| WPA2 이상, 가능하면 WPA3 | WEP는 몇 분이면 열리고 WPA도 약점이 알려졌다 |
| SSID 기본값 바꾸기 | 기본 이름은 공유기 모델을 드러내 알려진 취약점의 표적이 된다 |
| 펌웨어 업데이트 | 공유기는 인터넷에 직접 노출된 컴퓨터다. 구멍이 발견되면 메워야 한다 |
| WPS, UPnP, 원격 관리 끄기 | WPS의 PIN은 몇 시간이면 뚫리고, UPnP는 아무 프로그램이나 포트를 열며, 원격 관리는 밖에서 설정 화면을 연다 |

| 프로토콜 | 나온 해 | 상태 | 왜 |
|:---------|:--------|:-----|:---|
| WEP | 1997 | 사용 금지 | 암호 설계가 깨져 도청한 패킷 몇 개로 키가 나온다 |
| WPA | 2003 | 비권장 | WEP 장비를 살리려는 임시 방편이라 약점을 물려받았다 |
| WPA2 | 2004 | 권장 | AES 암호. 2017년의 KRACK은 업데이트로 막았다 |
| WPA3 | 2018 | 강력 권장 | 비밀번호를 추측해 맞춰 보는 공격을 막고 공개망도 암호화한다 |

유선은 선에 꽂아야 도청할 수 있지만 전파는 담 너머까지 간다. 무선을 암호화하는 이유이고, 무엇을 얼마나 지키는지는 [36. SSID의 구조](../36-ssid-structure)의 보안 절에서 본다. 공유기는 켜 두고 잊는 물건이지만 집에서 인터넷에 직접 노출된 유일한 컴퓨터라는 것을 기억할 만하다.

## 핵심 정리

| 구성 요소 | 역할 | 왜 |
|:----------|:-----|:---|
| ISP | 회선, 공인 IP 하나, DNS | 3장의 Tier 2. 집은 그 아래의 끝이다 |
| 모뎀 | 회선 신호를 이더넷으로 | 광, 전화선, 동축은 신호가 다르다 |
| 공유기 | 라우팅, NAT, DHCP, 스위치, AP, 방화벽 | 회선 하나를 기기 여럿이 나눠 쓴다 |
| 사설 IP | 집 안에서만 유효한 주소 | 공인 주소 43억 개로는 모자라다 |
| NAT | 주소와 포트를 바꿔 내보내고 표로 되돌린다 | 답장이 누구 것인지 알아야 한다 |
| 포트 포워딩 | 표에 미리 적는 한 줄 | 밖에서 안으로는 표가 없어 못 들어온다 |
| CGNAT | 통신사 쪽의 NAT 한 겹 더 | 100.64.0.0/10. 포트 포워딩이 안 통한다 |
| DHCP | Discover, Offer, Request, Ack | 손으로 주면 겹친다. 주소는 빌리는 것이다 |
| 무선 | 하나의 전파를 나눠 쓴다 | 반이중과 간섭. 규격 속도는 상한일 뿐 |
| 보안 | WPA2 이상, 기본값 변경, 불필요한 기능 끄기 | 전파는 담을 넘고 공유기는 인터넷에 노출돼 있다 |

{{< callout type="info" >}}
**용어 정리**
- **인터넷 공유기 (Broadband Router)**: 라우터, 스위치, 무선 AP, DHCP, NAT, 방화벽을 한 장비에 결합한 가정용 통합 장비
- **ISP**: 인터넷 접속 서비스를 제공하는 사업자
- **모뎀 (Modem)**: ISP 회선의 신호와 이더넷 신호를 서로 바꾸는 장비
- **NAT (Network Address Translation)**: 사설 주소를 공인 주소로, 포트까지 바꿔 내보내고 표로 되돌리는 기술
- **포트 포워딩**: 밖의 특정 포트로 온 연결을 안의 특정 기기와 포트로 넘기도록 NAT 표에 미리 적는 것
- **CGNAT**: 통신사가 가입자에게 100.64.0.0/10 주소를 주고 자기 쪽에서 하는 NAT
- **DHCP**: 기기에 IP, 서브넷 마스크, 게이트웨이, DNS를 자동으로 빌려주는 프로토콜
- **사설 IP / 공인 IP**: 내부망에서만 유효한 주소(RFC 1918) / 인터넷 전체에서 유일한 주소
- **WPA2 / WPA3**: 무선 구간을 암호화하는 보안 프로토콜
{{< /callout >}}
