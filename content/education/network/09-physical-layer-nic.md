[07. OSI 모델과 TCP/IP 모델](../07-osi-tcpip-model)의 맨 아래 층, "비트를 어떤 신호로"를 답하는 층이다. 원리는 셋이다. 첫째, **물리 계층은 비트를 신호로 바꾸는 층이고, 그 변환에도 규칙이 필요하다.** 1을 높은 전압, 0을 낮은 전압으로 보내면 될 것 같지만 0이 백 개 이어지면 받는 쪽은 몇 개인지 셀 수 없다. 코딩과 변조는 그 문제의 답이다. 둘째, **랜 카드는 1층과 2층을 한 몸에 담은 작은 컴퓨터다.** 신호를 만드는 PHY와 프레임을 다루는 MAC 컨트롤러가 한 칩에 있고, 요즘 카드는 검사와 자르기까지 CPU 대신 한다. 이 PC의 카드를 열어 그것을 확인한다. 셋째, **주소는 카드에 새겨진다.** MAC 주소의 앞 절반이 제조사인 이유와 브로드캐스트 주소가 있는 이유가 여기서 나온다. 이 장의 수치는 필자의 PC의 유선 랜 카드에서 읽은 것이다.

## 1. 물리 계층의 역할

```
송신
  10110100 ──▶ 신호 변환 ──▶ 매체로 전송

수신
  신호 수신 ──▶ 비트 복원 ──▶ 10110100
```

| 정하는 것 | 예 | 왜 필요한가 |
|:----------|:---|:-----------|
| 비트를 어떤 신호로 | 전압, 빛, 전파 | 매체마다 실을 수 있는 것이 다르다 |
| 신호를 어떤 규칙으로 | 코딩, 변조 | 받는 쪽이 비트의 경계를 세어야 한다(3절) |
| 어떤 선과 어떤 꽂이로 | UTP, 광케이블, RJ-45 | 규격이 같아야 아무 장비나 꽂는다 |
| 얼마나 빨리, 어느 방향으로 | 1Gbps, 전이중 | 양쪽이 같은 속도로 합의해야 한다 |
| 어디까지 | 100m | 신호가 약해지고 뭉개지는 거리 |

[02. 비트와 바이트](../02-bit-and-byte)에서 비트가 전선 위의 신호가 된다고 했다. 물리 계층은 그 변환의 모든 것, 즉 어떤 신호로, 어떤 규칙으로, 어떤 선과 커넥터로, 얼마나 빨리 보낼지를 정한다. 위층은 이것을 전혀 모른다. 이더넷 케이블을 뽑고 Wi-Fi로 바꿔도 IP부터 위는 한 줄도 바뀌지 않는 것이 7장에서 본 계층의 독립성이다.

## 2. 아날로그와 디지털 신호

| 항목 | 아날로그 | 디지털 |
|:-----|:---------|:-------|
| 파형 | 연속. 값이 무한히 많다 | 몇 가지 값만 |
| 잡음 | 섞이면 그대로 왜곡된다 | 값 사이의 경계만 지키면 되살린다 |
| 중계 | 증폭하면 잡음도 커진다 | 다시 만들어 보내면 새것이 된다 |
| 예 | 옛 전화, 라디오 | 이더넷, USB |

```
전압
 ▲
 │ ┌──┐  ┌──┐   ┌──┐
H├─┘  │  │  │   │  │
 │    │  │  │   │  │
L┼────┴──┴──┴───┴──┴──▶ 시간
비트: 1  0  1  0  0  0  1  0
```

컴퓨터 안은 디지털이지만 전선 위의 신호는 결국 전압이라는 아날로그 양이다. 2장에서 본 대로 디지털이 강한 이유는 값을 둘로 잡았기 때문이다. 잡음이 섞여 흐트러져도 "높은 쪽인가 낮은 쪽인가"만 가리면 원래 비트가 나오고, 중간 장비가 그 비트로 신호를 새로 만들어 보내면 잡음은 사라진다. 아날로그 신호를 증폭하면 잡음까지 커지지만 디지털은 **재생**한다. 그래서 디지털은 멀리 갈 수 있고, 7절의 리피터가 하는 일이 정확히 이 재생이다.

## 3. 비트를 신호로: 코딩과 변조

### 디지털 매체: 라인 코딩

| 방식 | 규칙 | 문제와 해법 | 쓰인 곳 |
|:-----|:-----|:-----------|:--------|
| NRZ | 1은 높게, 0은 낮게 | 같은 비트가 이어지면 신호가 변하지 않아 시계가 어긋난다 | 단순한 직렬 통신 |
| 맨체스터 | 비트마다 가운데서 전환. 1은 오르고 0은 내린다 | 비트마다 전환이 있어 시계를 맞춘다. 대신 대역폭이 두 배 | 10BASE-T |
| 4B/5B | 4비트를 전환이 보장된 5비트로 바꿔 보낸다 | 맨체스터보다 싸게 전환을 보장한다. 25% 오버헤드 | 100BASE-TX |
| PAM-5 | 전압을 5단계로 나눠 한 번에 더 많은 비트를 | 네 쌍의 선을 동시에 써 1Gbps를 100MHz 안에 넣는다 | 1000BASE-T |

1을 높은 전압, 0을 낮은 전압으로 보내는 가장 단순한 방법(NRZ)에는 함정이 있다. 0이 백 개 이어지면 전선은 그동안 낮은 전압을 유지할 뿐이고, 받는 쪽은 자기 시계로 시간을 재어 "낮은 상태가 비트 몇 개 분량이었나"를 세어야 한다. 시계가 조금만 어긋나도 99개인지 101개인지 틀린다. 그래서 라인 코딩의 첫째 목적은 **신호 자체에 시계를 실어 보내는 것**이다. 맨체스터 부호는 비트마다 반드시 한 번 전환해서 받는 쪽이 전환을 보고 시계를 맞추게 하고, 그 대가로 같은 속도에 두 배의 대역폭을 쓴다. 100Mbps로 올라가면서 그 대가가 커지자 4B/5B처럼 데이터에 여분의 비트를 섞어 긴 0이 나오지 않게 하는 방식이 나왔고, 1Gbps에서는 전압을 5단계로 나누고 선 네 쌍을 동시에 써서 신호의 주파수를 100Mbps 때와 같게 유지했다. 규격의 역사는 [16. 이더넷의 종류와 특징](../16-ethernet-types-features)에서 본다.

### 아날로그 매체: 변조

| 방식 | 바꾸는 것 | 쓰인 곳 |
|:-----|:----------|:--------|
| ASK | 진폭 | 광통신(빛의 세기) |
| FSK | 주파수 | 옛 전화 모뎀 |
| PSK | 위상 | Wi-Fi, 위성 |
| QAM | 진폭과 위상을 함께 | ADSL, 케이블, Wi-Fi 6(1024-QAM) |

전파나 전화선처럼 원래 아날로그인 매체에는 전압을 바로 실을 수 없다. 대신 일정한 파형(반송파)을 하나 두고 그것의 진폭, 주파수, 위상 중 무엇을 비트에 따라 바꾸는 것이 변조다. 둘을 함께 바꾸는 QAM은 한 번의 변화로 여러 비트를 실어, Wi-Fi 6의 1024-QAM은 한 심볼에 10비트를 담는다. 4장의 Wi-Fi가 세대마다 빨라진 것은 상당 부분 이 변조가 촘촘해진 덕이고, 촘촘할수록 잡음에 약해져 거리가 멀면 낮은 단계로 떨어지는 것도 여기서 나온다.

### 반대 방향: 샘플링

목소리처럼 원래 아날로그인 정보를 디지털로 바꿀 때는 일정한 간격으로 값을 재고(샘플링), 그 값을 정해진 단계로 반올림하고(양자화), 비트로 적는다(부호화). 얼마나 자주 재야 하는가에 답이 있다. 원래 신호의 가장 높은 주파수의 두 배 이상이면 원래 파형을 잃지 않는다(나이키스트 정리). 사람의 목소리는 3.4kHz까지만 있으면 알아들으니 전화는 8kHz로 재고, 음악은 20kHz까지 들리니 CD는 44.1kHz로 잰다.

## 4. 랜 카드: 1층과 2층을 한 몸에

```text
┌──────────────────────────┐
│           NIC            │
│ ┌────┐ ┌────┐ ┌────┐     │
│ │PHY │ │버퍼│ │ROM │     │
│ │    │ │RAM │ │MAC │     │
│ └─┬──┘ └────┘ └────┘     │
│   │                      │
│ ┌─┴──┐                   │
│ │MAU │ 신호 변환         │
│ └─┬──┘                   │
│   │                      │
│ ┌─┴──┐                   │
│ │RJ45│ 케이블 포트       │
│ └────┘                   │
│ ══════════════════       │
│   PCI/PCIe 버스          │
└──────────────────────────┘
```

| 부품 | 하는 일 | 층 |
|:-----|:--------|:---|
| PHY | 3절의 코딩과 변조. 비트를 신호로, 신호를 비트로 | 1 |
| MAU(트랜시버) | 전선에 실제로 전압을 싣고 읽는 회로. 옛날에는 별도 장치였다 | 1 |
| MAC 컨트롤러 | 프레임을 만들고 뜯고, FCS를 계산하고, 내 것인지 판단한다 | 2 |
| 버퍼(RAM) | 보내고 받을 프레임을 잠시 둔다 | |
| ROM | 5절의 MAC 주소 | |
| RJ-45 포트와 LED | 케이블 연결과 링크 표시 | 1 |
| PCIe 버스 | 컴퓨터의 메모리와 오간다 | |

랜 카드(NIC)는 컴퓨터를 케이블에 잇는 부품이지만 하는 일은 신호 변환만이 아니다. 아래쪽 PHY가 1층(신호)을, 위쪽 MAC 컨트롤러가 2층(프레임)을 맡아 한 카드가 두 층을 담당한다. 그래서 7장의 장비 표에서 랜 카드가 L1~L2에 걸쳐 있었다.

| 이 PC의 유선 랜 카드 | 값 | 뜻 |
|:---------------------|:---|:---|
| 칩 | Realtek 기가비트 컨트롤러(온보드) | 메인보드에 붙은 카드 |
| 링크 | 1Gbps, 전이중 | 상대 스위치와 자동 협상한 결과 |
| 버스 | PCIe 1레인, 1세대 | 약 2Gbps. 1Gbps 카드에는 충분하다 |
| 체크섬 오프로드 | IP, TCP, UDP 모두 켜짐 | 검사 계산을 CPU 대신 카드가 |
| 대량 전송 오프로드(LSO) | 켜짐 | 큰 덩어리를 카드가 MSS 단위로 자른다 |
| 수신 큐(RSS) | 4개 | 받은 패킷을 CPU 코어 넷에 나눈다 |
| 누적 통계 | 받은 126GB, 보낸 36GB, 오류 0 | 유니캐스트 1억 2천만 개, 브로드캐스트 930만 개 |

표의 아래 세 줄이 요즘 랜 카드가 "작은 컴퓨터"인 이유다. 1Gbps로 1,500바이트 프레임이 들어오면 초당 8만 개, 10Gbps면 80만 개다. 프레임마다 CPU가 체크섬을 계산하고 인터럽트로 깨어나면 CPU가 네트워크만 하다 끝난다. 그래서 검사(체크섬 오프로드), 자르기(LSO), 여러 코어에 나누기(RSS)를 카드가 떠맡고, CPU는 프레임 여러 개를 한 번에 받아 처리한다. 링크가 1Gbps 전이중으로 잡힌 것은 케이블을 꽂는 순간 카드와 스위치가 서로 지원하는 속도와 방향을 주고받아 가장 좋은 조합을 고른 결과(자동 협상)이고, 이것이 어긋나면 어떻게 되는지는 [15. 데이터가 케이블에서 충돌하지 않는 구조](../15-collision-free-structure)에서 본다.

| 형태 | 설명 |
|:-----|:-----|
| 온보드 | 메인보드에 내장. 이 PC가 이것이다 |
| PCIe 카드 | 확장 슬롯에 꽂는다. 10Gbps 이상이나 포트 여러 개 |
| USB | 랜 포트가 없는 노트북용 |
| 무선 | 전파용 PHY를 가진 카드. 규칙은 [35](../35-wireless-lan-structure)장 |

| 규격 | 속도 | 케이블 |
|:-----|:-----|:-------|
| 10BASE-T | 10Mbps | Cat3 |
| 100BASE-TX | 100Mbps | Cat5 |
| 1000BASE-T | 1Gbps | Cat5e, Cat6 |
| 2.5GBASE-T, 5GBASE-T | 2.5, 5Gbps | Cat5e, Cat6 |
| 10GBASE-T | 10Gbps | Cat6a |

## 5. MAC 주소: 카드에 새겨진 이름

```
AA : BB : CC : DD : EE : FF
└─ OUI (24b) ─┘└ 일련번호 (24b) ┘
   제조사 식별    제조사가 부여
```

| 부분 | 크기 | 누가 정하나 |
|:-----|:-----|:-----------|
| OUI | 24비트 | IEEE가 제조사에게 판다 |
| 일련번호 | 24비트 | 제조사가 카드마다 다르게 |

랜 카드에는 48비트 주소가 새겨져 있다. 2장에서 48비트면 약 281조 가지라 세상의 모든 카드에 다른 번호를 줄 수 있다고 했는데, 그 배분 방식이 두 토막 구조다. IEEE가 제조사에게 앞 24비트(OUI)를 팔고, 제조사가 뒤 24비트를 자기 카드마다 다르게 붙인다. 두 제조사가 같은 번호를 만들 일이 없고, 한 제조사 안에서는 자기가 관리한다. 이 PC의 카드에서 읽은 OUI는 `B4-2E-99`인데, 칩은 Realtek이지만 IEEE 표에서 이 번호는 메인보드 제조사의 것이다. 주소를 새기는 쪽은 칩을 만든 회사가 아니라 **카드를 만든 회사**이기 때문이다.

| 주소 | 뜻 | 왜 있나 |
|:-----|:---|:--------|
| FF:FF:FF:FF:FF:FF | 브로드캐스트. 이 망의 모두에게 | 상대의 주소를 모를 때 묻는다. ARP, DHCP |
| 01:00:5E:xx:xx:xx | IPv4 멀티캐스트. 신청한 카드들에게 | 여럿에게 한 번에 보내되 모두는 아닐 때 |
| 33:33:xx:xx:xx:xx | IPv6 멀티캐스트 | 같다 |

브로드캐스트 주소가 있는 이유는 "상대의 주소를 모를 때"가 있기 때문이다. [04. 가정에서의 LAN 구성](../04-home-lan-configuration)의 DHCP Discover는 아직 주소가 없는 기기가 외치는 것이고, ARP는 IP 주소만 알고 MAC 주소를 모를 때 묻는 것이다. 이 PC의 카드 통계에서 받은 프레임의 7%가 브로드캐스트였다. 조용해 보이는 망도 늘 이 정도는 떠들고 있고, [05](../05-office-lan-configuration)장에서 VLAN으로 그 범위를 자른 이유가 이것이다. 주소의 비트 구조와 스마트폰이 주소를 무작위로 바꾸는 이유는 [13. MAC 주소의 구조](../13-mac-address-structure)에서 본다.

```bash
ipconfig /all      # Windows. "물리적 주소"
ip link show       # Linux
ifconfig           # macOS
```

## 6. 송수신 과정

```
응용 프로그램
    │ 데이터
    ▼
OS 네트워크 스택 (캡슐화)
    │ 프레임
    ▼
NIC
  1. 프레임 버퍼링
  2. CSMA/CD 등 매체 접근 확인
  3. 비트 → 전기 신호 변환
  4. 케이블로 송출
    │
    ▼
   매체 (케이블·전파)
```

```
   매체
    │
    ▼
NIC
  1. 신호 수신 → 비트 복원
  2. 목적지 MAC 확인
     - 자신의 MAC → 수신
     - 브로드캐스트 → 수신
     - 타인의 MAC → 폐기
  3. FCS로 오류 검사
  4. 버퍼에 저장 후 인터럽트
    │
    ▼
OS 네트워크 스택 (역캡슐화)
    │
    ▼
응용 프로그램
```

보낼 때 운영체제는 [08. 캡슐화와 역캡슐화](../08-encapsulation-decapsulation)의 봉투를 다 붙인 프레임을 메모리에 두고 카드에 알린다. 카드는 그것을 자기 버퍼로 가져와(DMA) 보낼 차례를 기다린 뒤, 3절의 규칙으로 신호를 만들어 케이블에 싣는다. 받을 때는 순서가 거꾸로다. 카드가 신호를 비트로 되돌리고 프레임을 조립한 뒤, 목적지 MAC이 나이거나 브로드캐스트인지 보고 아니면 그 자리에서 버린다. 남의 프레임이 컴퓨터의 메모리까지 올라오지 않는 것은 카드가 이 판단을 먼저 하기 때문이고, 그래서 허브 시절에도 남의 데이터가 내 화면에 나타나지는 않았다. 내 것이면 FCS로 깨졌는지 확인하고 메모리에 옮긴 뒤 운영체제를 깨운다(인터럽트). 4절에서 본 대로 요즘 카드는 여러 프레임을 모아 한 번에 깨우고, 체크섬 검사까지 끝내 놓는다.

## 7. 물리 계층의 장비

| 장비 | 하는 일 | 왜 |
|:-----|:--------|:---|
| 리피터 | 약해진 신호를 비트로 되돌려 새 신호로 다시 보낸다 | 2절의 재생. 거리를 늘린다 |
| 허브 | 포트가 여럿인 리피터 | 한 포트의 신호를 모든 포트로 되쏜다. 읽지 않는다 |
| 스위치 | 프레임의 MAC 주소를 읽어 그 포트로만 | 2층 장비. 허브를 대체했다 |

리피터와 허브는 신호만 다룬다. 프레임이 무엇인지 모르고, 누구에게 가는지도 모른다. 허브는 들어온 신호를 나머지 모든 포트로 되쏘므로 모두가 모두의 프레임을 받고, 두 대가 동시에 보내면 신호가 부딪힌다. 6절에서 카드가 남의 프레임을 버리는 이유가 여기 있었다. 그 한계와 스위치가 그것을 어떻게 해결했는지는 [11. 리피터와 허브의 구조](../11-repeater-hub)와 [14. 스위치의 구조](../14-switch-structure)에서 본다.

{{< callout type="warning" >}}
허브는 한 포트로 들어온 신호를 모든 포트로 보내므로 대역폭을 나눠 쓰고, 누구나 남의 프레임을 볼 수 있어 보안에도 약하다. 지금은 스위치로 거의 대체되었고, 남아 있다면 바꾸는 것이 답이다.
{{< /callout >}}

## 8. 전송 매체

| 매체 | 신호 | 거리 | 왜 그 거리인가 |
|:-----|:-----|:-----|:--------------|
| UTP | 구리선 네 쌍의 전압 | 100m | 멀수록 약해지고 옆 쌍의 신호가 섞인다 |
| STP | UTP에 차폐를 더한 것 | 100m | 간섭이 심한 공장 등에서 |
| 광케이블 (SMF) | 가는 심(9μm)에 빛 한 줄기 | 수십 km | 빛이 한 길로만 가서 퍼지지 않는다 |
| 광케이블 (MMF) | 굵은 심(50μm)에 여러 줄기 | 수백 m | 줄기마다 길이가 달라 멀리 가면 퍼진다 |

| 무선 | 주파수 | 범위 | 속도 |
|:-----|:-------|:-----|:-----|
| Wi-Fi 6 | 2.4, 5GHz | 수십 m | 규격상 9.6Gbps |
| 블루투스 | 2.4GHz | 10m 안팎 | 수 Mbps |
| 5G | 수백 MHz에서 수십 GHz | 수백 m에서 수 km | 규격상 20Gbps |

구리선의 100m라는 한계는 1절의 "어디까지"다. 전압은 선을 지나며 약해지고, 네 쌍이 나란히 달리다 보니 옆 쌍의 신호가 섞여 들며, 그 둘이 커지면 받는 쪽이 높낮이를 가리지 못한다. 3장에서 LAN을 100m마다 스위치로 잇는 이유였다. 빛은 그보다 훨씬 덜 약해지고 옆 선의 영향도 없어 km 단위로 가는데, 심이 굵으면 빛이 여러 경로로 나뉘어 도착 시각이 벌어지므로 먼 거리에는 가는 심의 싱글모드를 쓴다. 케이블과 커넥터의 종류는 [10. 케이블의 종류와 구조](../10-cable-types-structure)에서, 전파는 [35. 무선 랜의 구조](../35-wireless-lan-structure)에서 본다.

## 핵심 정리

| 개념 | 핵심 | 왜 |
|:-----|:-----|:---|
| 물리 계층 | 비트를 신호로, 신호를 비트로 | 매체마다 실을 수 있는 것이 다르다 |
| 디지털의 힘 | 값이 둘뿐이라 되살린다 | 증폭은 잡음도 키우지만 재생은 새것을 만든다 |
| 라인 코딩 | 신호에 시계를 싣는다 | 같은 비트가 이어지면 개수를 셀 수 없다 |
| 맨체스터, 4B/5B, PAM-5 | 전환 보장, 여분 비트, 다단계 전압 | 속도가 오를수록 대역폭을 아끼는 쪽으로 |
| 변조 | 반송파의 진폭, 주파수, 위상 | 전파와 전화선에는 전압을 바로 못 싣는다 |
| 나이키스트 | 최고 주파수의 두 배로 샘플링 | 전화 8kHz, CD 44.1kHz |
| 랜 카드 | PHY(1층)와 MAC 컨트롤러(2층) | 신호와 프레임을 한 카드가 |
| 오프로드 | 체크섬, 자르기, 큐 나누기를 카드가 | 초당 수십만 프레임을 CPU가 못 따라간다 |
| 자동 협상 | 속도와 방향을 케이블 꽂을 때 합의 | 어긋나면 15장의 문제 |
| MAC 주소 | OUI 24비트 + 일련번호 24비트 | 제조사끼리 겹치지 않게 IEEE가 나눠 준다 |
| 브로드캐스트 | FF:FF:FF:FF:FF:FF | 상대 주소를 모를 때 묻는다. 망의 7%가 이것 |
| 수신 판단 | 내 것과 브로드캐스트만 올린다 | 남의 프레임은 카드가 버린다 |
| 허브 | 읽지 않고 되쏜다 | 대역폭을 나누고 충돌한다. 스위치로 대체 |
| 100m | 구리선의 한계 | 약해지고 옆 쌍이 섞인다 |

{{< callout type="info" >}}
**용어 정리**
- **NIC (Network Interface Card)**: 랜 카드. 신호 변환(1층)과 프레임 처리(2층)를 함께 맡는 부품
- **PHY / MAC 컨트롤러**: 비트와 신호를 오가는 회로 / 프레임을 만들고 뜯고 주소를 판단하는 회로
- **MAU (Medium Attachment Unit)**: 트랜시버. 전선에 신호를 싣고 읽는 부분
- **라인 코딩 / 변조**: 디지털 매체에 비트를 싣는 규칙 / 아날로그 매체의 반송파를 비트에 따라 바꾸는 규칙
- **오프로드**: 체크섬 계산, 세그먼트 자르기처럼 CPU가 하던 일을 카드가 대신하는 것
- **MAC 주소 / OUI**: 카드에 새겨진 48비트 주소 / 그 앞 24비트인 제조사 코드
- **FCS (Frame Check Sequence)**: 프레임 끝의 오류 검출 코드. 카드가 계산하고 검사한다
{{< /callout >}}
